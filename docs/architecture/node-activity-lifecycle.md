# Node 新活动生命周期与重新配对评审包

- 日期：2026-10-28
- 状态：**D17 已由所有者接受并授权实施，正式决策见 [ADR 0008](../adr/0008-node-activity-lifecycle.md)**
- 面向：Node 状态、存储与安全接入协作者
- 范围：此前按“提交工作区更改，继续推进下一步”形成评审包；随后所有者明确“接受，实施”。入站准入批次已提交为 `bf99955`，本生命周期批次的结果见[实施记录](../testing/node-activity-lifecycle.md)

## 基线与接受范围

[ADR 0005 D9](../adr/0005-node-security-integration.md)要求新 boot 隔离旧会话/责任，重新通信须新活动、新会话及可信重配；[ADR 0006 D11](../adr/0006-node-identity-and-control-profile.md)要求每活动新活动/参与者标识和三组独立键，旧联系人不能恢复信任。[ADR 0007 D16](../adr/0007-node-envelope-and-control-budget.md)要求最多一个可通信活动、最长 12 小时、五人四代和固定 1 MiB/576 记录预留。这些方向无需重复接受。

D17 已接受多个结束活动的持久归档、旧控制记录占用现有业务控制余额、满额拒绝新活动及首次仅同 boot 切换的取舍。接受不包含提高限额、自动删除旧数据或解除跨 boot 隔离。下述 v7 核对是实施前基线，v8 实现结果单独记录。

## 实施前 v7 代码核对

| 当前 schema v7 边界 | 新活动不能直接复用的原因 |
| --- | --- |
| `control_activity(id=1)` 只存一个活动；start 拒绝重复创建，stop 保留 marker | 覆盖 id=1 会丢失旧活动拒绝依据及本机身份上下文 |
| `control_bindings`、对象/邻居责任以单活动为隐含上下文 | 清表破坏业务政策不变量；保留但不增加活动过滤则可能把旧 Active 行当成新活动可信邻居 |
| `messages/message_data` 保存活动、原字节、boot、政策及本机凭据 | 历史校验目前会连接唯一活动和其绑定；旧关联必须仍能校验，但不能因此获得发送权 |
| `security_states(session)` 只有全局字符串键，消息未保存 session→activity 的映射 | 不能从同名、唯一当前活动或最大 revision 推断旧密码状态属于新活动 |
| `action_scopes/actions` 的 UI scope/generation 未绑定活动 | 新活动不能复用旧动作权限；现有 retire 方法还会删除该 scope 的动作记录，不能直接当作活动切换 |
| 入站任务持有拥有者身份/活动/凭据/政策；输出游标、尝试、ACK 已持久 | 新活动不得接纳旧任务结果或重放旧发送决定；重置速率不能返还旧责任次数 |
| 所有写入共用 `writable()` 的 boot/时间隔离 | 将 `time_uncertain` 清零或覆盖 meta.boot 不是 D9 新活动恢复机制 |

核对来源：`node/src/store/schema.sql`、`migration_v4.sql`—`migration_v7.sql`、`control_state.rs`、`business_policy.rs`、`transactions.rs`、`data.rs`、`control_ingress.rs`。没有操作用户数据或运行真实密码提供者。

## 已接受 D17：单库活动作用域，旧事实有界保留

保留单 Store、单连接与唯一提交权。schema v8 将活动上下文改为按 activity_id 保存，meta 指向唯一当前上下文；当前上下文可以运行或已停用，历史上下文只读归档。绑定、控制对象和邻居责任在同一组表中增加活动关联，不另建第二套身份库或外部归档文件。

- 所有准入、签署、验证完成、数据/receipt/ACK/退出输出都要求匹配唯一当前活动且权限有效；归档记录只用于事实校验和查询。`policy_stopped` 不反转，旧活动不能重新变成当前活动。
- 新 activity_id 必须与保留的所有活动不同；新 participant_id 与凭据重新准备并核验，不复制旧 Active/Pending、三组键或安全会话。标识相同或输入不明确时拒绝，不靠字符串改名迁移旧权限。
- 业务记录保留现有内部 message key 与 D15 复合身份、原始 core/密文、deadline、retain_until、历史及去重。新活动不得抢占旧 key；旧唯一 payload 不因切换提前删除。已交付事实不改成未交付。
- 新安全状态必须显式以 `(activity_id, session)` 定位。旧 v7 的 session 缺乏可靠活动映射，迁移后隔离保留，不能猜测归属、继续更新或作为新会话起点。未来真实 MLS state/KeyPackage 的作用域仍须按 D6 联合事务验证。
- UI scope 的活动代数在切换时退休，旧动作记录保留为不可重放事实；新的 scope/generation 显式绑定新活动。不得调用现有删除动作记录的 helper 来代替该迁移。手机连接关闭、迟到响应丢弃和授权验证仍须实际 UI 接入实现。
- 新活动的政策修订可从自身零点开始，但每个准备结果必须同时绑定活动 ID；本机修订不跨活动或跨节点比较。入站任务/发送结果不能仅凭整数相同复用。

### 归档容量

当前活动继续获得完整 **1 MiB/576 记录**预留。旧活动控制事实转入原 8 MiB 控制总额扣除此预留后的余额，按实际逻辑责任计费；不抬高 config 上限，也不挤掉已承诺的业务责任。旧业务数据/历史/安全状态继续按原各自额度计费，不重复计入下表。

| 归档内容 | 每条计费 | 单活动保守上限 |
| --- | ---: | ---: |
| 关闭上下文、活动 ID 拒绝 marker、最终政策/时间/切换引用 | 4096 bytes / 1 记录 | 1 |
| 已核验/Pending 绑定及原字节/状态 | 1024 bytes / 1 记录 | 25 |
| 原始退出/报告对象 | 4096 bytes / 1 记录 | 100 |
| 邻居尝试、ACK、终态及原起算点 | 512 bytes / 1 记录 | 400 |
| 合计 | **644096 bytes / 526 记录** | 保守组合，不宣称全部同时可达 |

旧速率/游标的最终摘要可纳入有界关闭上下文，但不得生成可恢复许可；新活动速率从空桶开始。当前活动的逻辑辅助预留仍完整保留，归档计费不是再复制一份 1 MiB 的空余空间。

计算：业务控制余额原为 `8 MiB - 1 MiB = 7340032 bytes`。没有其他占用时，一份上述保守满额归档使 4096-byte 业务证明责任上限从 1792 降为 **1634**；只有一个空活动归档上下文也会使其变成 **1791**。记录限额、历史、payload、已有证明/预留可能更早命中。归档记录还计入全局 record_count；这不是 SQLite journal/页/磁盘硬预算。

**容量不足时拒绝建立下一活动，保留旧活动已停用状态和全部原数据。** 本机停用/封禁不要求先支付归档费用。首次实现不做自动归档清理，不删除旧活动 ID、绑定、去重或尚被引用的数据来腾空间；长期自动回收需另审引用闭包、保留时钟和拒绝旧活动依据。因此本方案允许有限次数的活动切换，不承诺无限期滚动使用。

替代方案比较：让归档挤占当前 1 MiB 会削弱新活动退出保障；每活动再预留 1 MiB 会更快消耗总额；提高总额改变已接受预算；直接删除旧事实改变数据保留与安全保证。已选择上述实际计费/满额拒绝，后续另评生命周期回收。

## 切换顺序与事务边界

1. **预检只读**：返回旧活动、政策修订、在途任务数量、待归档计费与剩余额度。新随机 ID/三组键由未来合格库准备；本批内部实现只接受有界的合成/已准备输入，不生成密码材料。
2. **明确停用旧活动**：复用持久停用和不可反转业务停止；不因新活动准备失败恢复旧权限。该步骤无需空闲远程队列或归档余额，也不等待验证器。
3. **收束旧运行任务**：关闭/撤销旧通道和 UI 输出，停止并 Join 旧验证工作；等待项显式丢弃，在途任务必须返回或取消，仍有任务则拒绝切换。当前离线代码只能验证内部任务计数和结果拒绝，不能伪造实际 worker 已停止的证据。
4. **一次切换事务**：复核旧活动已停用、预期活动/政策、可信同 boot 坐标、新 ID 不重复及容量；原上下文成为只读归档，绑定/对象/次数原样保留；旧安全状态和 UI 动作权限隔离；创建新上下文并更新唯一当前指针。新绑定从空集合/Pending 开始，空桶起算；没有旧队列、ACK、receipt 或会话自动进入新活动。
5. **提交后才发布新上下文**：新配对依 D11 逐对核验；未 Active 前普通业务拒绝。只有内部状态切换完成不代表真实配对或安全通信成立。

COMMIT 前失败保留“旧活动已停用、新活动未建立”，不将停用回滚成 Active；COMMIT 后响应丢失隔离拥有者，重开查询稳定的切换引用/新 activity_id 确认结果，不重复切换或重新发放额度。切换引用纳入关闭上下文的有界记录，不能为无限请求单独增长日志。

## 首次实现与迁移范围

首次实施**同 boot、旧活动明确停用之后的新活动切换**。跨 boot 继续沿用现有只读隔离，不提供 ignore/reset/unlock 开关。D9 的跨 boot 新活动方向保留；其显式新写域、历史时间坐标、旧安全状态隔离和可信平台输入须另行设计验证，不能把同 boot 用例当作完成 D9。

v7→v8 为显式维护迁移：有当前活动时必须已停用，且无未收束验证任务；不能为方便迁移自动结束正在使用的活动。旧 D15/业务事实及次数原样保留，旧 session 隔离。更早来源沿已有显式迁移链到 v7 边界，复核旧活动已停用后再进入 v8；实现将这些阶段保持在同一事务。若旧活动仍运行，整笔拒绝，须由兼容旧版本的可信入口先明确停用；不存在活动的更早库不伪造活动。历史 SQL 与缺失映射不改写。新库直接初始化新格式；未知版本、重复迁移、容量不足和损坏均拒绝。精确 SQL、键/索引和兼容结果见实施记录，不以设计文字替代测试证据。

## 必须通过的验收与后续拆分

| 范围 | 通过条件 |
| --- | --- |
| 活动/权限 | 运行中切换拒绝；旧 ID 重用拒绝；旧数据、proof、ACK、原退出及 Pending 均不能在新活动获得权限；新活动无可信绑定时拒绝业务 |
| 历史与关联 | 原 core、payload、历史事实、去重、重试/ACK 次数不变；当前准入只查当前活动，历史不变量查正确旧上下文 |
| 安全/界面 | 旧 session 不可更新，新 session 从新作用域开始；旧 action reference 不能在新代数变成新请求；真实 MLS/UI 接线单独验收 |
| 资源 | 归档实际计费、644096/526 保守上限、可用余额前后 1 byte/1 record、多个空活动及满额拒绝；停用/封禁不被容量或远程队列阻止 |
| 任务/时间 | 未收束 job 拒绝切换；旧 job/已消费输出不能跨新活动；新桶空、旧次数不变；新 boot/回拨仍隔离 |
| 原子/迁移 | 每个写点失败、COMMIT 前后退出、响应未知；恢复只能见完整旧停用状态或完整新上下文；旧 SQL、历史证据与真实入口不改变 |
