## 基线与接受范围

[ADR 0005 D9](../adr/0005-node-security-integration.md)要求新 boot 隔离旧会话/责任，重新通信须新活动、新会话及可信重配；[ADR 0006 D11](../adr/0006-node-identity-and-control-profile.md)要求每活动新活动/参与者标识和三组独立键，旧联系人不能恢复信任。[ADR 0007 D16](../adr/0007-node-envelope-and-control-budget.md)要求最多一个可通信活动、最长 12 小时、五人四代和固定 1 MiB/576 记录预留。这些方向无需重复接受。

D17 已接受多个结束活动的持久归档、旧控制记录占用现有业务控制余额、满额拒绝新活动及首次仅同 boot 切换的取舍。接受不包含提高限额、自动删除旧数据或解除跨 boot 隔离。下述 v7 核对是实施前基线，v8 实现结果单独记录。

## 已接受 D17：单库活动作用域，旧事实有界保留

保留单 Store、单连接与唯一提交权。schema v8 将活动上下文改为按 activity_id 保存，meta 指向唯一当前上下文；当前上下文可以运行或已停用，历史上下文只读归档。绑定、控制对象和邻居责任在同一组表中增加活动关联，不另建第二套身份库或外部归档文件。

- 所有准入、签署、验证完成、数据/receipt/ACK/退出输出都要求匹配唯一当前活动且权限有效；归档记录只用于事实校验和查询。`policy_stopped` 不反转，旧活动不能重新变成当前活动。
- 新 activity_id 必须与保留的所有活动不同；新 participant_id 与凭据重新准备并核验，不复制旧 Active/Pending、三组键或安全会话。标识相同或输入不明确时拒绝，不靠字符串改名迁移旧权限。
- 业务记录保留现有内部 message key 与 D15 复合身份、原始 core/密文、deadline、retain_until、历史及去重。新活动不得抢占旧 key；旧唯一 payload 不因切换提前删除。已交付事实不改成未交付。
- 新安全状态必须显式以 `(activity_id, session)` 定位。旧 v7 的 session 缺乏可靠活动映射，迁移后隔离保留，不能猜测归属、继续更新或作为新会话起点。未来真实 MLS state/KeyPackage 的作用域仍须按 D6 联合事务验证。
- UI scope 的活动代数在切换时退休，旧动作记录保留为不可重放事实；新的 scope/generation 显式绑定新活动。不得调用现有删除动作记录的 helper 来代替该迁移。手机连接关闭、迟到响应丢弃和授权验证仍须实际 UI 接入实现。
- 新活动的政策修订可从自身零点开始，但每个准备结果必须同时绑定活动 ID；本机修订不跨活动或跨节点比较。入站任务/发送结果不能仅凭整数相同复用。

### 归档容量

当前活动继续获得完整 **1 MiB/576 记录**预留。旧活动控制事实转入原 8 MiB 控制总额扣除此预留后的余额，按实际逻辑责任计费；不抬高 config 上限，也不挤掉已承诺的业务责任。旧业务数据/历史/安全状态继续按原各自额度计费，不重复计入下表。

| 归档内容 | 每条计费 | 单活动保守上限 |
| --- | ---: | ---: |
| 关闭上下文、活动 ID 拒绝 marker、最终政策/时间/切换引用 | 4096 bytes / 1 记录 | 1 |
| 已核验/Pending 绑定及原字节/状态 | 1024 bytes / 1 记录 | 25 |
| 原始退出/报告对象 | 4096 bytes / 1 记录 | 100 |
| 邻居尝试、ACK、终态及原起算点 | 512 bytes / 1 记录 | 400 |
| 合计 | **644096 bytes / 526 记录** | 保守组合，不宣称全部同时可达 |

旧速率/游标的最终摘要可纳入有界关闭上下文，但不得生成可恢复许可；新活动速率从空桶开始。当前活动的逻辑辅助预留仍完整保留，归档计费不是再复制一份 1 MiB 的空余空间。

计算：业务控制余额原为 `8 MiB - 1 MiB = 7340032 bytes`。没有其他占用时，一份上述保守满额归档使 4096-byte 业务证明责任上限从 1792 降为 **1634**；只有一个空活动归档上下文也会使其变成 **1791**。记录限额、历史、payload、已有证明/预留可能更早命中。归档记录还计入全局 record_count；这不是 SQLite journal/页/磁盘硬预算。

**容量不足时拒绝建立下一活动，保留旧活动已停用状态和全部原数据。** 本机停用/封禁不要求先支付归档费用。首次实现不做自动归档清理，不删除旧活动 ID、绑定、去重或尚被引用的数据来腾空间；长期自动回收需另审引用闭包、保留时钟和拒绝旧活动依据。因此本方案允许有限次数的活动切换，不承诺无限期滚动使用。

替代方案比较：让归档挤占当前 1 MiB 会削弱新活动退出保障；每活动再预留 1 MiB 会更快消耗总额；提高总额改变已接受预算；直接删除旧事实改变数据保留与安全保证。已选择上述实际计费/满额拒绝，后续另评生命周期回收。

## 切换顺序与事务边界

1. **预检只读**：返回旧活动、政策修订、在途任务数量、待归档计费与剩余额度。新随机 ID/三组键由未来合格库准备；本批内部实现只接受有界的合成/已准备输入，不生成密码材料。
2. **明确停用旧活动**：复用持久停用和不可反转业务停止；不因新活动准备失败恢复旧权限。该步骤无需空闲远程队列或归档余额，也不等待验证器。
3. **收束旧运行任务**：关闭/撤销旧通道和 UI 输出，停止并 Join 旧验证工作；等待项显式丢弃，在途任务必须返回或取消，仍有任务则拒绝切换。当前离线代码只能验证内部任务计数和结果拒绝，不能伪造实际 worker 已停止的证据。
4. **一次切换事务**：复核旧活动已停用、预期活动/政策、可信同 boot 坐标、新 ID 不重复及容量；原上下文成为只读归档，绑定/对象/次数原样保留；旧安全状态和 UI 动作权限隔离；创建新上下文并更新唯一当前指针。新绑定从空集合/Pending 开始，空桶起算；没有旧队列、ACK、receipt 或会话自动进入新活动。
5. **提交后才发布新上下文**：新配对依 D11 逐对核验；未 Active 前普通业务拒绝。只有内部状态切换完成不代表真实配对或安全通信成立。

COMMIT 前失败保留“旧活动已停用、新活动未建立”，不将停用回滚成 Active；COMMIT 后响应丢失隔离拥有者，重开查询稳定的切换引用/新 activity_id 确认结果，不重复切换或重新发放额度。切换引用纳入关闭上下文的有界记录，不能为无限请求单独增长日志。

面向 Node 状态、存储、安全与恢复协作者。本节为 D9/D17 的后续设计输入，目标是冷启动后明确建立全新活动，并保留旧事实；非目标为透明续传、防克隆/完整防回滚、真实配对/签验、自动清空数据库或无限次滚动使用。原评审阶段仅完成设计；现按 ADR 0009 实施 schema v9 与 Node 自有内部边界，实际结果见[实施记录](../testing/node-activity-lifecycle.md#d18-跨-boot-时钟域与-schema-v92026-11-02)。生产入口不开放。

| 1. 时钟与写域 | 单库增加显式时钟域；旧域冻结，新业务只写当前 active 域及活动 | 新 boot 不恢复旧会话/责任；需修改全部相关查询和不变量，无可信新 UTC 时不能建立业务写域 |

### 场景、输入与输出

场景：旧活动可能在没有正常停用的情况下结束于断电；解锁后的新 boot 不能继续旧会话，但所有者希望重新配对并开始下一活动。即使新活动失败，历史仍可只读查询，旧发送权不能恢复。

可信生命周期调用方须提供：经过验证的新 boot 标识及当前单调坐标、可信 UTC 区间、预期源 schema/revision/当前活动、新 activity_id/participant_id，以及仅限本次转换的请求引用。身份与三组键仍须未来合格密码库及可信配对准备；合成输入不能成为真实授权。输入有界，UI、邻居和普通业务 API 均不能提供 boot/Clock 或调用维护转换。

第一步隔离不以新身份、可信新 UTC 或归档余额为前置；这些是第二步建立新上下文的要求。无法证明新 UTC 时可保持旧域隔离，但不能建立可业务写入的新域。

输出分成持久转换结果和通信就绪状态。转换结果可查询旧域、隔离原因、新域及 successor；新活动从空绑定、空会话、空速率桶和新 owner 开始。转换成功仅说明内部边界成立，未重新核验为 Active 前业务继续拒绝，不能显示为已安全重连。

### v8 中必须一起改变的假设

| 代码边界 | 当前事实 | 新设计必须满足 |
| --- | --- | --- |
| `store/mod.rs` 的 open / `writable()` / `atomic()` | boot 不同或时间回退使整个 Store 隔离；普通事务拒绝写入 | 只增加精确的维护转换；普通写入继续拒绝隔离状态，不提供清除 `time_uncertain` 的通用入口 |
| `activity.rs` / `control_state.rs` | 全部活动 boot 等于 meta.boot，归档 closed_ms 与后继 started 相等 | 同域继续比较单调时间；跨域只核对明确关联，不将新 boot 的数值当旧活动结束时间 |
| `data.rs` | 所有消息的 admitted_mono/UTC 与唯一 meta 比较；`constrain_data_clock` 扫描全部消息 | 旧消息按自己的冻结域校验；新时钟只能缩短当前域消息，不能改写旧 deadline、原 core 或 admission |
| `maintenance.rs` / `receipts.rs` / 调度 | 全库 deadline 与当前 monotonic 比较；证明责任也依赖这一比较 | 先限定当前域及当前权限，再比较时间；旧消息不能因数值碰巧相近被发送、到期或重新产生证明 |
| 历史 / 动作 / 安全状态 | history.expires 为绝对 UTC；动作和 session 已按活动隔离 | 历史到期仍要求可信 UTC 下界；旧动作、session、联系人或凭据不能赋予新活动权限 |

核对基线为 `c7008eb` 的 schema v8。`meta`、控制域、消息域和维护查询必须作为一个兼容性切片评审，不能只放宽某一条不变量后沿用其余全库查询。

### 已接受选择一：单库显式时钟域

通过版本化迁移增加 `clock_domains`，meta 只引用当前写域，保留单 Store、单连接和唯一提交者。以下为已接受的字段合同；SQL 与接口精确映射见实施记录：

| 记录 | 候选字段与不变量 |
| --- | --- |
| 时钟域 | 有界 domain_id、平台 boot 标识、最后实际持久的 monotonic/UTC 区间、active/frozen 状态及隔离原因；冻结域的时间不再推进。domain_id 只作数据库关联，不证明状态新鲜性 |
| meta | revision、limits、当前 domain_id 与 current_activity；旧 boot/mono/UTC 列迁入域记录，不保留第二套可独立更新的时钟口径 |
| 活动 | domain_id、原 started/deadline；区分同 boot 明确停用与新 boot 隔离。跨域隔离不伪造 closed_ms；冻结域的最后观测不是实际掉电/停用时刻 |
| 关闭关联 | 同 boot 沿用原时间相等规则；跨 boot 保存隔离类型与后继引用，后继位于新域且内部顺序更晚，不比较两个域的单调数值 |
| 消息及旧队列 | message_data 显式关联原域；legacy 消息只保留原域归属，不补造缺失认证字段。队列、意图、预留及历史通过 message_key 追溯该域 |

最多一个 active 域；只有 meta 指向的域可以 active，且当前活动必须属于该域。meta 指向 frozen 域时必须处于隔离状态，普通业务与维护时钟推进均拒绝。实现将 domain_id 限为 32 bytes、boot 标识沿用 Clock 的 64-byte 上限，请求引用限为 256 bytes、隔离摘要限为 512 bytes；整数坐标与固定关联使用受检编码，不存无限 JSON 或外部证明正文。

域另保存正的内部 sequence，迁移初始为 1，后续受检递增；到 i64 上限拒绝，不比较随机 domain_id 的字节大小来判断先后。sequence 仅验证同库后继关系，不作为可信 boot counter 或防回滚证据。已归档域的 sequence/时间/boot 不再变化，同 boot 的多个活动共享一个域，不为活动切换重复创建域。

任何普通业务写入必须同时匹配当前 active 域、当前活动及有效政策。旧域记录仅用于事实查询和原始坐标下的完整性检查；原字节、deadline、retain_until、retry/ACK 次数、交付事实和去重保持。旧 `policy_stopped` 不能反转，旧 `security_states` 不更新。

新域须使用未出现在保留域中的平台 boot 标识；相同 boot 的回拨、UTC 失信或旧域回放不得走“新 boot”路径。平台输入须独立可信；数据库内 ID/计数、正常关机标志及 LUKS 解锁都不能证明未回滚，旧库镜像仍是后续可信平台验收的负例。

首批建议要求可信 UTC 区间满足现有 D15 宽度和有效性规则，且下、上端点均不低于保留域已记录的对应最大端点；不满足时保持隔离，接受可能需要等待可信时间收敛的可用性代价。新 boot 的 monotonic 可从较小值开始，但只能在新域使用。平台如何证明 boot/UTC 输入有效仍是缺口，合成 Clock 不填补该缺口。

### 已接受选择二：先隔离，再原子建立新域与新活动

普通 open 仍不自动迁移、停止或建立活动。可信维护拥有者取得现有独占锁、验证源格式/完整性/关联后，显式执行以下两步；这是已接受的专用维护合同，不能复用普通 `atomic()` 或直接改 meta 来绕过隔离。

1. **持久隔离旧域。** 复核真实 boot 已改变及预期旧域/活动/revision；保存原最后观测并冻结旧域，明确停用旧当前活动，退休其 UI scope，将源域中尚未停止的业务责任单向标记为 policy stopped。无可信签名时不伪造退出对象或远端确认，不改变 payload、历史、原 deadline、次数和旧绑定事实。此步不新增归档/请求日志，不要求先有归档余额；写入失败仍由新 boot 不匹配阻止旧业务输出，不能报告持久隔离已完成。
2. **建立新上下文。** 使用第一步提交后返回或重开查询所得的隔离 revision，再核对原请求关联、隔离状态、新 ID 不复用、可信新坐标、容量及实际 worker/channel 已收束。在一个事务中计费旧域与旧活动归档、保存跨域 successor、建立新域和新活动、切换指针并重建空桶。只有提交成功才发布新上下文，旧域和旧上下文保持冻结。

隔离后的状态可以没有 active 写域，meta 仍可指向等待归档的 frozen 域；此状态只允许维护转换与只读查询。容量不足或新输入失效时保留该状态，不恢复旧活动。归档触发器须区分“待归档的当前冻结上下文”和已经归档的不可变事实，不能通过关闭触发器放开普通业务写入。

每步都必须检查真实关联和版本；维护事务只能写上述白名单，并执行域化后的全部适用不变量。新域建立成功后，普通事务仅对新域使用原来的 fail-closed 提交路径。时钟推进、业务政策协调和维护不得隐式遍历并改写所有旧域。

COMMIT 前失败回滚本步；第一步成功后第二步失败保留完整旧隔离。COMMIT 后响应丢失或回滚失败隔离 owner，重开以有界隔离标记及 successor 查询完整结果；相同引用只能返回既有结果，不另建域或返还额度。首步不另造无限增长的请求表，第二步引用纳入原有有界关闭上下文。再次冷启动发生在两步之间时，只能针对实际最新 boot 重新预检，未提交的候选不得被视为已有活动。

隔离与建立新活动分别保存有界的请求关联，不能仅凭 request_ref 相同返回成功。隔离关联包含源 domain、可空旧 activity、预期源 revision、引用与首次观察的新 boot；完整重复只返回原隔离结果。已经 frozen 后的新请求只能查询该稳定结果，不覆盖首次观察、反复写入新尝试或消费新额度。

新活动请求关联包含隔离来源/revision、request_ref、目标 domain_id、受检 sequence、目标 boot、新 activity_id/participant_id、起始单调坐标及期限。相同引用但任一持久参数不同均 Conflict；完全相同的重复可返回已提交的后继事实，不能重新创建域、续期、重置桶或返回发送许可。重开后的新时钟采样是另一次准入依据，不通过重写原请求起点来“匹配”重复。

两步间若从实际 boot B 再进入 C，而数据库仍停在旧 A 的隔离态，A 的首次隔离观察仍保留为 B；新请求可在 C 重新预检并建立 C 域，不补造未提交的 B 域。若 B 域其实已提交，则先查询确认结果，再以 B 为源明确隔离，不能越过它直接把 A 连接到 C。跨 boot 的重复结果只是历史事实，不能解除当前运行者的时间/权限隔离。

旧库没有当前活动时，第一步只冻结原域，旧 activity 明确为 None，不伪造空活动或签名停用。第二步仍建立全新域与活动；没有旧活动就不写活动 successor，域后继保存在原有域记录。该情况只归档旧域的 4096 bytes / 1 记录；已有一个空活动时才另加活动上下文费用。无旧活动也不允许旧 legacy session、联系人或动作获得新权限。

内存 job/输出准备必须同时绑定 owner、domain、activity 和 policy revision。真正的新系统 boot 不会保留原进程线程，但服务重建、测试和进程子树仍须核验停止/Join；内部计数为零不替代实际 worker/channel 关闭。首次配对还须让相关对端明确拒绝旧活动，不将本机隔离扩展成全队撤销已完成。

### 已接受选择三：域元数据显式计费，不增加上限

每个时钟域按 **4096 bytes / 1 记录**计逻辑责任，字段和隔离摘要必须有界且装入该额度。当前域占原 1 MiB / 576 记录固定预留；冻结的当前域在第二步成功前仍占该预留，转为历史域后按实际占用计入原业务控制余额及全局记录上限。没有活动的旧域也计费，不能靠反复空启动累积免费记录。

当前活动、输出桶及域记录的保守组合为 `652288 bytes / 528 记录`，仍低于原固定预留；其未使用部分不外借。原 D17 的同 boot 单活动归档仍为 `644096 bytes / 526 记录`；若该次还关闭一个 boot 域，合计为 **648192 bytes / 527 记录**。无其他占用时，4096-byte 业务证明理论上限相应为 **1633**；空活动加旧域为 8192 bytes / 2 记录，对应 **1790**；没有旧活动时只归档 4096 bytes / 1 记录的域，对应 **1791**。这是逻辑计费计算，不是实测可达组合或物理空间保证。

预检一次性计算旧域、旧活动和已有责任的净占用；共享旧域只计一次，当前域不能既免费保留又漏计。余额不足拒绝第二步，不扩大 config、借出固定预留或删除旧事实。SQLite 主库、journal、迁移重建页面及宿主硬边界仍须另证，逻辑余量不能当作执行资源。

首批每个新域都与一个新活动共同提交，只有迁移/新库的首域可没有活动，故域记录数不超过活动记录数加 1。失败尝试和隔离态的再次 boot 不生成新域日志；该关系也要作为全库完整性检查，不能仅靠逻辑字节总额掩盖无主域增长。

### 显式迁移与兼容

采用 schema v9 与 `migration_v9.sql`。v8→v9 在同一事务内映射结构、按原坐标校验源事实，只有全部校验成功才提交；不完整或损坏会回滚原格式。实现先将已知原坐标映射到首个域，再按该快照完整核验原 meta/活动/消息关联，冷迁移只有通过后才冻结；不使用新 boot 的采样冒充原坐标。缺字段的 legacy 数据仍隔离，不猜测 session 或安全身份。旧 SQL 与历史实验合同保持。

- v9 程序的普通 open 对 v8 返回 MigrationRequired；同 boot 的源活动须先用兼容 v8 的入口停用，不能借升级自动重配。
- 冷启动时 v8 活动可能尚未停用。必须由单独的“迁移并隔离旧 boot”精确请求明确授权此状态转换，在同一迁移事务中保存原坐标、冻结/停用并退休旧权限；不能伪装原 boot 或调用普通迁移解锁。旧坐标仅作为只读完整性校验的持久事实，不能构造旧 Clock 调用普通 open、重置桶或推进时钟。其成功只得到隔离后的新格式，新活动另走第二步。
- v1..v7 继续遵循既有兼容链及停用前置；已有 migrate_v1..v7 仅在原前置成立时沿原 SQL 链到 v8 中间态，再进入v9 的同 boot 显式迁移。本批不增加从更早冷启动隔离库直接建立新活动的捷径；不满足旧链前置时拒绝并说明需另审兼容维护方案。
- 未知版本、错误来源/revision、损坏关联、容量不足及中途失败整笔拒绝；不得回填 user_version 降级。提交未知隔离并重开查询。真实用户数据迁移与物理空间验收不在本轮范围。

### 长期归档回收评估

“归档只读”保护原身份、安全与交付事实；D5 允许的到期历史删除须单独判断，不能由活动结束推导全部数据可删。

| 对象 | 已有许可与引用闭包 | 首批建议 |
| --- | --- | --- |
| 用户可见历史 | D5 七天；history→message；需要可信 UTC 下界达到原 expires | 新域可信 UTC 满足上述条件后可沿既有分批规则隐藏/删除到期历史；时间未知保留只读，不以新 boot 重新起算七天 |
| 传输 payload / data queue / 中继预留 | 到期清理须证明原消息寿命结束，且关联责任共同终结；policy stopped 本身不授权删除唯一 payload | 当前域沿原规则；跨域首批不新增 payload 回收，不拿新 monotonic 与旧 deadline 比较 |
| 证明队列 / receipt intent | 已有到期或 policy stopped 清理；删除不能抹掉消息去重、已交付事实和原预算 | 仅沿明确适用的既有政策终结规则清理；跨域时间到期不得猜测，不能转换成新活动的证明责任 |
| 消息 marker / core / 去重 / ACK 与重试事实 | actions、history、queue、intent、reservation、message_data 及业务身份互相引用 | 缺少已接受的最终回收窗口，继续保留并计费；retain_until 数值不是跨域删除许可 |
| 控制归档、封禁、活动 ID / 凭据 | 业务消息/邻居/证明与跨域后继仍引用；删除会影响旧活动拒绝和不变量 | 保留原事实和实际计费；不压缩为不能核验关联的单个 hash，不回收 ID 后允许重用 |
| session / UI action / domain | session 属活动；action→message，scope 代数退休；域被活动/消息/后继引用 | 不复制旧会话；保留退休拒绝依据。域或 marker 压缩必须先有完整引用闭包与拒绝证明，另案评审 |

首批结论：**继续有限容量、满额拒绝，不承诺长期自动回收或无限使用。** 后续回收须先定义最小保留证据、可信删除时钟、引用关闭顺序、可中断分批状态及每步原子恢复；不得通过提高预算、自动删历史或取消关联检查掩盖不可持续性。
