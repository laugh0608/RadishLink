# Node 状态拥有者资源与在途工作账本

2026-11-08，接线前评审稿。基线为 `1eeff29` 及此前的离线实现，接续[拥有者输入、交接与关闭](node-outbound-owner.md)。这里登记已有代码边界、仍缺的资源控制和验收证据，不新增协议、配额或运行授权。适用范围是一个 Node 的文字与控制路径；[I5 整批 768 MiB](../testing/sw-g4-synthetic-i5-resource-isolation.md)和[新图 G1/G2](../testing/node-security-graph-review-package.md)各有独立账本，不能引用彼此的余量或通过结果。

## 已有逻辑上限

| 阶段与持有者 | 基线可以核对的边界 | 真正接线时必须补上的计费 |
| --- | --- | --- |
| 已认证输入 → framing，传输拥有者与 `Ingress` | [`framing.rs`](../../node/src/framing.rs)每邻居一条组装槽，共四槽。每帧至多 65,536 bytes，含 4-byte 前缀，四槽合计至多 262,144 bytes 的帧内容。10 秒从首字节起，只处理未完整组装；完整帧靠显式取走或关闭释放。`push` 最多消费到本帧末尾，`take` 把帧体交给下游 | 认证前连接、read credit、读缓冲和未消费后缀单列；后缀不能借 framing 空槽滞留。按分配容量计算 backing，含预分配但尚未写入的空间。四个 framing 槽与 Store 四个登记实例是两套逻辑状态，需绑定到同一真实实例，不能由其推导 FD 或握手并发上限 |
| 严格解码 → kind 2/3 等待、派发、返回，Store 与验证 worker | [`control_ingress.rs`](../../node/src/store/control_ingress.rs)有四个实例登记槽及独立的四个 peer 限速槽；对象 1–512 bytes，等待及租约共用 16 槽，原始 COSE 合计至多 8192 bytes。`Arc` 在条目与租约间共享同一 backing。限速全局 4/s、burst 4，每 peer 1/s、burst 2；已知及重复仍经过限速 | 派发前预留 worker、scratch 与结果位置。结果等待仍占原任务额度。入队复制前可能同时持有完整帧，返回还可能持有 `PreparedControl.cose`、`fields.payload`、加密库和 SQLite 参数副本。当前同步完成先取下原槽再执行事务，函数返回前仍持有对象；此段转由正在执行的拥有者计费。实际 worker、结果通道和分配上限均未实现 |
| 数据、COSE kind 1 回执与逐跳 ACK，解码器 → 拥有者 | kind 2/3 的槽不覆盖这些输入。T-B 中继、T-C 目标接纳与新插入控制对象有明确提交后产生待发 ACK 的内部入口。T-B 和 T-C 合法重传共用原 ACK 队列与持久预算，控制对象的重传确认待评审 | 为数据、回执、ACK 分别定义解码深度、单对象/总分配量、同时验证数和 owner 等候位置；限制解密临时数据及持久化参数的重叠。不能让满额的数据路径占用撤销、关闭或归还租约必需的资源。未定义额度的路径不接入 |
| 候选扫描 → 周期输入、决策与已提交交接，Store | [`outbound_scan.rs`](../../node/src/store/outbound_scan.rs)单页最多返回 128 个元数据候选，另读至多一个探查项；[`outbound_cycle.rs`](../../node/src/store/outbound_cycle.rs)最多 80 个退出 + 16 普通控制/回执 + 16 数据候选，三个逻辑页共至多 112 个候选及 3 个探查项，另合计至多 16 个 ACK 输入，总事件至多 128。探查项不是可执行输入。页只取责任键或引用，不取帧体 | 扫描位置、页、合并事件、通道绑定、事务决定和返回报告可同时存在，复制后的键与容器容量另计。`LIMIT` 约束返回行，不约束 SQLite 检查行数、排序空间或耗时；两种候选合用的普通控制页也不能按返回行数推算查询成本。调用方保留的输入或报告不在 Store 单批上限内 |
| 入站终结与待发 ACK，Store | [`outbound_terminal.rs`](../../node/src/store/outbound_terminal.rs)最多一个待提交终结，接纳时撤回当前交接批次。[`outbound_ack.rs`](../../node/src/store/outbound_ack.rs)合计 16 个待发描述符，冻结后到明确 COMMIT 前仍占原槽。带交接的周期不混用管理队列与显式 ACK 输入；冻结后的引用是附加内存，不是额外的 16 次机会。描述符未编码成 127-byte ACK 帧 | 终结事件与完成/撤回通知需要有界来源和接收位置，不能在一个终结槽之前堆积待验证输入。满 ACK 槽保留已提交接纳并舍弃本次回 ACK 机会；失败路径不能通过另外的队列积压待发副本 |
| 交接 → 外部写入，Store 与传输拥有者 | [`outbound_handoff.rs`](../../node/src/store/outbound_handoff.rs)只保留一个已提交批次，至多 128 条决定所派生的引用，只有队首可在部分写入中；模型存形状和偏移，不编码也不写字节。数据形状至多 65,536 bytes，控制对象与回执至多 522 bytes，两类 ACK 恰为 127 bytes。持久控制桶（含回执和 ACK）4 frames/s、8192 bytes/s，burst 分别为 4 和 8192；这是计费速率 | 分开计编码帧、应用写缓冲、传输层密文、仍在内核的前缀及背压。不能从共享桶、尝试次数或应用帧长推出驻留内存和线路字节。禁止把可自行提交字节的许可交给写 worker；取消后禁止刷新旧应用缓冲或续写 |
| 本机请求和回复，Service 与调用方 | [`service.rs`](../../node/src/service.rs)邮箱容纳 32 条，另有一条正在执行；每次调用创建一个回复通道，只有一个回复；历史查询单页至多 100 项。移除唯一发送端关闭准入，不占邮箱槽；已接纳请求仍排空 | 克隆的客户端、入队前请求、已发出未消费的响应和调用方持有的结果不由邮箱覆盖。实际 UI/RPC 要对等待者、请求/回复字节、连接和关闭设置独立上限。Service 目前只 Join 状态线程 |
| 停止、通道与 worker 收束，Store 与平台监督者 | [`owner_shutdown.rs`](../../node/src/store/owner_shutdown.rs)撤回待发批次、待发 ACK、未提交终结和等待验证；已派发租约继续占槽。最多四个已登记实例需要关闭，另记录一个部分帧的实例，它可能与其中一个相同；离线入口也允许它是未登记的实例。确认关闭、租约归还、Join 结果均到齐才放开 SQLite 关闭与锁释放 | 真实接线必须能枚举所有 FD、任务及尚未返回的资源，覆盖认证前、关闭中的旧实例和仍运行的 worker。断开/关闭请求、取消信号、超时或任务句柄析构本身不能作为资源已释放的证据；失败保留闩锁、根因和未归还资源的归属 |
| 持久数据、维护与日志，Store 与文件系统 | [D16 固定预留](../testing/node-control-persistence.md#容量与-schema-v4)在默认控制总额 8 MiB / 4096 条中预留 1 MiB / 576 条，同时在全局记录账本中占位；业务/回执责任按原预算，跨域归档不增加总额度。[`mod.rs`](../../node/src/store/mod.rs)限制主库 32,768 个 4096-byte 页，即 128 MiB 的主库逻辑文件上限；`DELETE` journal、`synchronous=EXTRA`、`temp_store=MEMORY`，零 SQLite busy 等待。[`maintenance.rs`](../../node/src/store/maintenance.rs)按清理类别各最多选取 256 个对象 | 主库增长、rollback journal、迁移/恢复峰值、文件系统元数据及底层卷要有同时占用的硬预留；缓存、临时排序、回滚与同步也占内存和时间。页缓存设置是目标缓存大小，不是 RSS 限制。诊断、日志、备份、转储、swap 各要有明确归属、保留及限制；应用配额不足以约束这些写入 |

### 计费和归还

实际入口须给每一项登记限制对象、计费单位、每实例及全局上限、执行限制的位置、持有者、转移点、拒绝结果及可观察的归还条件。每次转移先确认接收方的槽位和字节额度，再改变归属。同一 backing 共享引用只计一次，直到最后一个引用释放；需要复制时先为两份预留重叠量。任务排队、运行、返回、撤销等待都要计入并发；旧实例释放前与新实例并存的资源也要计入。未取得下游额度时，沿原背压或明确丢弃路径处理，不在上游、回调或重试列表另留副本。

整机账本应分别计算同时驻留的进程/线程栈、分配器容量、原生库和 SQLite 内存、内核 socket 缓冲及记账归属、FD/进程/任务数、持久文件和文件系统占用。共享量按实际归属去重，能够重叠的阶段按最坏同时占用计；不能直接相加上表中的帧字节、速率和主库页得到整机上限。内存和写入证据应覆盖分配或写入前的拒绝及可容纳回滚和收束的余量。外部监督只用于封住失效边界，不能用进程被杀替代正常拒绝及 SQLite/锁的收束证明。

## 检查到外部效果的时间

| 必须封住的区间 | 需要证明的条件 |
| --- | --- |
| 收到首字节 → framing 判定及归还 | 在持续有输入和其余槽满时仍能及时观察 10 秒组装边界；这个定时不覆盖握手、完整帧等待或 worker。各段另给开始/截止条件、超限动作和最晚释放点 |
| 批次截点 → 事务结束 → 下一次拥有者检查 | 分开限制 SQLite 候选/索引查询、读行/排序、`observe`/`bind` 纯回调、时钟推进和政策协调、事务内配额/不变量检查及 COMMIT/回滚与文件同步。重开还有 `integrity_check(1)` 与 `foreign_key_check`，未完成前不准入。256 项清理、128 个事件和零 busy 等待都不限制一次事务或开库所耗的时间。停止、撤销和已完成结果在下一有界单元被观察；必须证明该单元最长多久，包含已在执行的维护 |
| 最新可信采样 → 一次物理写入的边界 | 以底层不可撤回接纳字节的点为准，覆盖 Store 复核、编码/加密（若在采样后执行）、系统调用前调度及调用到接纳的上界。活动/队列使用同 boot 单调 deadline，适用的数据、回执、数据 ACK 同时使用 D15 原截止与保守 UTC 上界。最早适用截止之前必须容纳上述整段余量；等于截止、时间不可用或余量无法证明时拒绝。数据首字节前按该余量编码剩余寿命，续写前重新采样并复核固定编码值，不能满足即中止原实例。应用成功、内核接纳与对端收到是三个不同观察点 |
| 停止闩锁 → 拒绝新接纳 → 中止 → 关闭与 Join → SQLite/锁 | 记录门禁、最后一次不可撤回接纳、每个实例的关闭及每个 worker 返回，证明停机不依赖远程队列或日志 sink 腾位。Service 还要覆盖当前单元和已接纳本机请求的排空。验证失败或超时只能维持关闭并报告未收束对象；监督超时不能替代 Join。通道关闭前已接纳的字节可能稍后到达对端，禁止新增剩余偏移的提交 |

固定平台前不填写新的毫秒值。未来的证据要绑定 Linux ARM64 镜像/内核、SQLite 与文件系统配置、负载与监督条件，说明界限由何种机制保证。采样峰值或时延分位数用于发现问题，不能充当上界。若无法封住采样到不可撤回接纳的间隔，发送入口保持关闭。

## 拒绝证据和首个接线入口

| 场景 | 未来须取得的可复核结果 |
| --- | --- |
| 数量或字节刚好到限，再多一项或一字节 | 分别压满连接与 read credit、framing、验证及待返回结果、应用邮箱/回复、输出缓冲、FD 和存储额度。记录限制来自哪个入口、拒绝前后各阶段的占用及归还原因。拒绝不得增配新对象、静默积压或绕开计费；关闭和归还仍须能进行。持久接纳之前的丢弃不回 ACK，ACK 槽满不回滚此前接纳 |
| 最大可并存占用、旧实例重连与慢消费者 | 同时保有满组装、等待/运行/返回任务、批次元数据、部分写入及 SQLite journal/内存活动；加上读尾部、未消费响应与日志 sink 背压。查跨阶段重叠与旧新实例的归属，确认没有无法回收的额度或老实例向新实例转移资格 |
| 检查后被抢占、接近截止、短写/结果未知期间撤销或停止 | 在纳入余量的边界前、恰好及之后取证，注入检查与底层接纳之间的延迟、关闭及重连。用实际 I/O 边界观察点核对无首字节或无后续偏移提交，不能只看拥有者返回值。已消费尝试不返还、不重放；接纳晚到终结后仍须保持批次撤回 |
| 文件满、COMMIT/回滚异常、关闭失败、worker 不退出 | 记录真实拒绝点、错误和退出原因、锁仍在或确已释放、实际 FD/worker 归还及重开可见的持久事实。明确回滚与提交未知分开观察，后者隔离；不得用重试成功掩盖未知结果。证据限额、记录丢失与清理失败都须可见，日志只含有界计数、偏移及合成关联号，不含帧体或凭据 |

首个入口是 **认证实例登记 → 有界读入 → framing → 下游接纳或丢弃 → 同一实例关闭**，接口与验收条件见[有界输入评审稿](node-bounded-ingress.md)。它同时检验最早的字节所有权转移和停止可达性。该合同经评审且环境和对应安全前置满足后，再提出精确的实施与运行范围；一次只放开证据可覆盖的入口。后续工作池、可信时钟及真实输出逐项独立验收。

本次只有源码与合同核对。没有实际资源、耗时、设备、密码或网络证据，也没有改变许可证/R2/Phase B、新图 G1/G2、可信平台、I5 与 HW/RF 停止线。长期归档继续满额拒绝。
