# RadishLink 网络与路由

## 设计目标

网络需要同时满足两种差异很大的通信：文字允许短时断链并可以多跳存储转发；实时语音和视频要求连续、低抖动、少跳数的路径。用同一种“尽力而为洪泛”处理全部流量会迅速耗尽 Sub-1 GHz 空口。

## 两层网络模型

### 无线承载层

承载层负责在直接可达的邻居之间传输 IP 包或数据帧。POC 首选 MM8108/OpenWrt 提供的 802.11s；同时保留普通 AP/STA、2.4 GHz 局域网和 Ethernet 测试承载。

802.11s 只解决链路级 Mesh 和下一跳转发，不提供 RadishLink 所需的离线消息语义、端到端确认、附件配额、身份撤销或媒体准入。厂商当前把相关功能标为实验性，因此不能成为唯一产品真相源。

### RadishLink 覆盖层

覆盖层负责：

- 稳定节点 ID 与设备身份的映射；
- 邻居能力、链路质量、负载、电量和中继意愿发布；
- 消息 ID、去重、跳数上限、过期时间和端到端确认；
- 无路径时的有界存储转发；
- 实时会话的路径探测、准入、保持和降级；
- 在不同承载之间切换，不改变上层消息格式。

## 节点角色

协议只定义一种正式节点。每台节点都能：

- 作为本地用户的终端；
- 转发密文消息和媒体包；
- 宣告临时拒绝中继，例如低电、过热、存储不足或用户关闭；
- 在固定供电时提高中继配额和广播频率。

“每台都可以中继”不等于“每台必须无条件中继”。资源策略必须显式，否则随身设备会因他人流量失去续航。

## 寻址与发现

- 设备身份使用密码学公钥派生的稳定 ID，不以 MAC 地址作为用户身份。
- 链路地址、IP 地址和承载可变化；覆盖层通过已认证邻居声明建立映射。
- 首期网络规模目标为 3–10 节点，不提前设计上千节点全局路由。
- 邻居声明包含版本、能力、队列摘要、可接受流量类型和量化链路指标，不包含联系人名称或消息内容。

## 消息转发

消息信封至少需要版本、消息 ID、密文长度、优先级、过期条件、跳数预算、下一跳提示和认证字段。精确交付语义已由 `SW-G1` 接受，见[覆盖层消息交付语义](../protocol/message-delivery-semantics.md)；线格式仍未冻结。`tools/t0/` 的探索性 JSON `version: 0` 不是候选协议，不能从测试实现反推产品设计。当前设计顺序见[D0/P0 软件工作计划](../status/d0-t0-p0-plan.md)。

转发策略：

1. 已有可信路径时单播，不默认全网广播。
2. 路径未知时使用受控查询或有限扇出的机会式转发。
3. 每节点维护有界去重缓存和每来源速率限制。
4. 端到端确认到达后传播可验证的删除提示；中继不得伪造“已读”。
5. 过期、跳数归零、签名无效、超配额或版本不支持的包立即拒绝。

首期不使用无限制 gossip。广播风暴在窄带、半双工、多跳环境中会同时破坏续航和实时媒体。

## 路径度量

路由成本不能只看 RSSI。至少考虑：

- 近期丢包与重传；
- 可用应用吞吐而非 PHY 速率；
- RTT、抖动和队列等待；
- 跳数与路径稳定时间；
- 中继电量、温度和主动负载；
- 承载类型与法规允许的占空/带宽限制。

文字路径偏向可达性与稳定性；语音路径偏向低抖动；视频路径还要求持续吞吐余量。不同业务可以选择不同路径。

## 实时会话边界

- POC 只保证一对一，优先单跳，最多一个中继。
- 建立语音前要求测得的双向可用吞吐至少达到目标媒体总码率的 2.5 倍。
- 建立视频前要求至少 2 倍持续余量，并在通话期间保留文字/控制优先队列。
- 路径切换使用短时双发或状态迁移时要有严格时限，不能永久复制媒体。
- 超过一个中继、频繁切路或指标不足时主动降低码率/分辨率，最终退回语音。

## 存储转发

- 每个来源、会话和优先级都有磁盘与发送配额；
- 密文落盘，内容密钥不交给中继；
- 语音留言和附件分块、逐块校验并支持断点续传；
- 淘汰顺序为过期内容、已确认副本、低优先级大附件，最后才是未确认文字；
- 消息过期使用相对寿命和单调计时辅助，不能完全信任未同步的墙上时钟。

## 必须验证的失败场景

- A—B—C 中 B 断电后重新建立直连或替代路径；
- 同一密文通过两条路径到达时只交付一次；
- 恶意节点高速发送新 ID 时触发来源配额而不挤掉控制消息；
- 中继磁盘满、时钟回拨、网络分区与合并；
- 语音进行时发送图片不造成语音队列饥饿；
- 路由层可替换 802.11s 承载为 Ethernet 模拟而不改消息格式。
