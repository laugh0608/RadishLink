# Node 外发遍历与状态拥有者接线工作包

- 日期：2026-11-02
- 状态：只读候选遍历与同步离线拥有者周期已实施；真实输入路由、工作池及发送交接尚未接入
- 来源：[ADR 0004](../adr/0004-node-service-foundation.md)、[ADR 0007 D16](../adr/0007-node-envelope-and-control-budget.md)、[ADR 0009 D18](../adr/0009-node-clock-domains.md)
- 面向：Node 状态拥有者、调度、输入和恢复协作者。目标是将已有内部批处理接到完整且有界的责任来源；不定义新 wire、密码实现、可信平台或产品 QoS。

## 基线与本批范围

D18 已提交为 `8573e88`，schema v9；旧域冻结，新活动不继承旧权限。本批沿用该格式、原配额与现有依赖。所有者明确要求提交工作区并继续下一步；按 [current](../status/current.md) 的接续顺序，完成本工作包及不改变权限/格式的只读候选遍历，用合成数据验证到既有事务调度的路径。

候选遍历随后按所有者要求提交为 `7ee3120`，同步周期随后提交为 `c4ffb5b`。均在同一 Node 自有边界，没有新增持久格式、授权、依赖或 Service/CLI 命令，不扩展真实运行范围。

已有 `process_outbound_batch` 只处理调用者给出的最多 128 个事件。它可以在这批输入内合并观察、优先退出、共享控制桶和持久轮转，但不能知道调用者漏掉的责任，也不能把一次决定当作真实通道的可重放许可。本批不将“可遍历全部保留责任”写成“全部已就绪”或“已经实现全局发送公平”。

## 原实现核对与消费者

| 位置 | 已有事实 | 接线时必须保留的边界 |
| --- | --- | --- |
| `store/outbound.rs` | 四类控制共享额度；exit_cursor / ordinary_cursor 仅在成功消费额度时推进 | 不把这两个位置改成访问位置；原优先级、失败不返还与每批 128 输入不变 |
| `store/scheduling.rs` / `retry.rs` | 数据/receipt 的同坐标合并、持久重试与期限 | 遍历不是新的定时器，不复制一套 retry 算法；link、signal、Admission 来自可信拥有者输入 |
| `store/control_scheduling.rs` | 原始已验证退出例外、控制时槽、恢复和 ACK 次数 | 只有原权限允许的控制对象可以候选输出；被限流或错过的机会不补发 |
| `store/control_ingress.rs` | 16 个等待/leased 对象共享额度，结果绑定拥有者/域/政策/通道 | 不把 Known、取消或槽清零当作已签验、已持久接纳或 worker 已停止 |
| `framing.rs` | 四邻居、每邻居一个 frame、10 秒组装期限 | take 只交接字节所有权，不能自动接纳到验证/业务队列；超时须真正关闭对应 transport |
| `service.rs` | 单拥有者、32 个命令、停止/Join 与拒绝发送 | 本批不新增公开调度命令，不把既有状态线程 Join 写成验证/传输 worker 已 Join |

## 首批已实施：只读候选遍历

实现集中在 `node/src/store/outbound_scan.rs`，复用 Store 及既有 ControlIngress 的运行者身份，不新增拥有者、线程、数据库、provider 或配置。

| 接口 / 结构 | 合同 |
| --- | --- |
| `start_outbound_scan(lane)` | 由当前可写 Store 创建不透明运行期位置；绑定本次拥有者、当前域和活动。没有当前活动、时间隔离、已停止或到期时拒绝 |
| `OutboundLane::Exit` | 当前活动非 terminal 的 kind 2 邻居责任，以 object/participant 稳定排序 |
| `OutboundLane::OrdinaryControl` | 先列当前域/活动且 policy_stopped=0 的 evidence queue，再列当前活动非 terminal 的 kind 3 邻居责任；这是遍历顺序，不取代实际发送轮转 |
| `OutboundLane::Data` | 当前域/活动且 policy_stopped=0 的 data queue；与控制分开遍历，调用方不能只轮询控制来声称数据公平 |
| `scan_outbound_page` | 使用 keyset 条件和 LIMIT，不使用 OFFSET 或先装入全表；每次返回至多 128 个引用，内部至多读取 129 个作尾页判断。普通控制页可跨 receipt/report 分界，零 ID 是合法键 |
| `OutboundPage` | 只有域、活动、发现时 revision、分组、引用及 complete，不返回正文、事件、签验结论、ACK、预算或发送许可 |
| 失败 / 终结 | 查询中途失败不推进位置；complete 后再次使用显式 Conflict，调用方须明确开启下一轮。游标不支持克隆/序列化，不跨 Store 重开、活动或域复用 |

候选仍可能在未来时槽、Paused、次数耗尽、链路不可达或因后续政策变化而不可输出；就绪判断继续执行原算法与事务内授权。不从持久 source_neighbor、Known 对象或邻居表自动生成 ACK 请求；ACK 必须由已认证、严格解析且已持久接纳的输入驱动，并再次检查已有十次上限。

遍历期间允许合法提交改变 revision；页只说明发现时事实，下一批仍以当前状态复核。游标后方新增的键可在本轮发现，前方新增的键等待下一轮；删除的键不能使后续位置倒退。集合稳定时，一轮有限分页覆盖全部该分组候选，避免永久只取相同前 128 项；持续变化和反复丢弃游标不具有此保证。

位置只存于调用方拥有的内存，重开丢弃；原持久尝试、空桶和成功消费游标均不重置。本批不承诺跨重启的访问公平。未来若要求持久遍历位置，必须显式设计 schema 演进、归档与计费，不能借用现有两个发送游标或写旁路文件。

页面只包含有界键，既有文本引用各至多 64 ASCII bytes，二进制引用为固定 32/16 bytes。最多 129 个临时候选、一个尾部位置与拥有者引用；不是 129 份 payload/frame。返回 Vec 的 capacity、SQLite 查询/索引、allocator、进程 RSS 和实际解析器硬内存仍须平台验证，不能从返回条数推导物理限额已经成立。没有提高 1 MiB / 576、8 MiB 或全局记录总额，也没有新增持久行。

## 第二批已实施：同步离线拥有者周期

`node/src/store/outbound_cycle.rs` 将发现、已捕获观察、显式 ACK 请求与原 `process_outbound_batch` 连成一次同步调用。状态拥有者使用一个不透明 `OutboundCycle`，分别保留 Data 与 OrdinaryControl 的运行期位置；实际线程、事件收集和可信采样仍在未来边界，本模块不制造这些事实。

| 接口 / 阶段 | 实际合同 |
| --- | --- |
| `start_outbound_cycle` | 从当前 Store 创建 Data / OrdinaryControl 位置，绑定原拥有者、域和活动；不支持 Clone/Debug/序列化，不恢复旧输入或决定 |
| `OutboundCycleInput` | 调用方先提交本机控制与完整已验证结果，再提供当前 expected_revision、可信 Clock 和至多 16 个显式 ACK 输入；对象本身不实施认证 |
| 截点与观察 | revision 必须仍匹配；观察提供方只读取已经捕获、认证、合并的输入，对每个候选显式返回同坐标 Batch。没有默认 Allow/link/信号，不在回调中签验、等待 worker、驱动通道或产生外部效果 |
| 退出集合 | 每步重新读取完整当前 kind 2 邻居责任。D16 最多 20 个退出 × 4 邻居，即 80；超过该上界显式 StoreCorrupt，不截断退出集合后先处理普通工作 |
| 数据 / 普通控制 / ACK | 每步分别至多 16 个数据候选、16 个普通控制候选、16 个显式 ACK 输入；ACK 超限整步拒绝，不截断或自动生成。数据和普通控制各自轮到完成时才开启下一轮 |
| 提交 | 合计至多 `80+16+16+16=128` 个原事件，委托既有批处理合并、排序、核验、计费及维护。空步委托既有 maintain，不伪造空批成功 |
| 位置与失败 | 内部暂存两个遍历位置，仅 COMMIT 明确成功后发布位置和本步时刻；读取、观察、权限或写入失败均不跳过候选。原错误及 source 保留，不吞错重放整个周期 |
| 关闭坐标 | 同一句柄成功提交后，该单调毫秒关闭；相同毫秒不得补交晚到输入。后续步须使用更大的真实可信采样，不能自行 +1；无效/回退采样仍沿原路径锁存时间隔离 |
| 提交未知 / 重开 | 原 Store 隔离并拒绝后续写入；重开查询持久责任，旧句柄因拥有者不同而拒绝。新句柄重建遍历，不返还持久尝试、ACK 次数或旧发送额度，也不恢复 ACK 输入 |

80 是既有 D16 的保守退出责任上界，三个 16 是从原 128 输入上限保留退出空间后分配的内部工作片，不是 wire、数据速率、存储上限或产品 QoS 参数。不在退出较少时借出这些工作片，也不扩大 config 或固定预留。周期最多发现 112 个候选及三个尾页判断键，再接纳至多 16 个 ACK 输入；复用的原事务仍执行每类至多 256 条维护。逻辑条数不证明查询、完整性扫描、fsync、回调或整步的物理耗时/RSS 硬上限。

对稳定候选集合，每个分组至多经 `ceil(N/16)` 个成功步遍历到尾项；控制有工作不能使数据工作片永久不被访问。每步重取完整退出集合，已在步间持久接纳的退出进入下一步的原退出优先序列。该结论不是发送机会公平、有限时槽内必达、跨重启公平或真实响应时间保证；错过/受限机会继续按原规则消费，不补发。

本机停止、封禁和已验证结果不依赖周期的“更大毫秒”门；它们先走原控制事务。周期报告只有原已提交决定、截点、候选/ACK 数量及两组尾页事实，不新增发送许可。真正写出前的政策、通道、时间复查及一次消费仍未接入。

周期 expected_revision / cutoff_revision 表示 Store 的提交修订；已有 `validate_business_output` 的 expected_revision 比较的是政策修订。两者含义不同，不能把周期截点直接传作输出授权或把修订相等解释为通道仍被授权。

## 后续完整接线顺序

以下真实消费者仍待接入；同步周期只在调用者已供应合格输入时完成上述内部部分。候选或周期 API 均不允许跳过消费者合同直接接网络。

1. 状态拥有者从可信平台取 Clock，为输入分配本地顺序并冻结批次截点；先处理已接纳的本机停止/封禁及完整验证结果。未验证字节不能自称退出以插队；结果晚于截点进入下一批，不能回填成已经合并的同坐标输入。
2. 每个分组保留自己的遍历位置，轮到其有界工作页时推进；把候选与当前已认证邻接、期限及 Admission 结合。ACK 输入保持单独的有界来源，不能被候选扫描制造。未来需明确数据/控制工作量配额与实际耗时上限；D16 的控制发送优先不授权无限占用状态线程。
3. 对同责任、同可信坐标的观察先完整合并，再通过原 `process_outbound_batch` 提交。超过 128 的责任分成多批，每批之间留出本机控制和已验证退出的处理点；不能在一个长 SQL 事务中扫完全库，也不能在遍历页之间把普通控制抢先送出当作已保证全局退出优先。
4. 发现已失效项必须有明确拒绝/终结结果；不因一条错误循环重放整页，不吞错后报告全部成功。新退出/封禁应使受影响准备结果失效，再次复核当前域、活动、政策、精确邻接和消息期限；不把整个旧页的 revision 当作权限替代。
5. 只有成功 COMMIT 的决定才可进入同一拥有者的受限交接。发送位置以新可信采样复核当前责任、终态、政策、活动/域、通道实例及截止；一次消费、写失败不返还。退出例外只适用于原已验证自身退出，不能为旧业务、receipt 或 ACK 重新授权。
6. 真实通道须提供有界、非阻塞的交接及部分写入语义；不能在状态线程等待无限 socket/worker。部分 frame 与撤销/关闭竞态须定义停止续写和关闭行为，不能把旧剩余字节移到新通道。实际实现前另行核对 transport 与认证接口，不先制造可重放的公共 permit。
7. 停止时先关闭新准入、撤回未交接工作，再停止并 Join 验证及 I/O worker，收束 leased 任务后关闭 Store。不能因 cancel 释放槽或 pending=0 就建立新活动；跨 boot 或拥有者重建后旧结果与通道必须拒绝。失败保留原因，不以强制清零模拟成功。
