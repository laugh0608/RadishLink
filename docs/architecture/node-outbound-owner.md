# Node 外发遍历与状态拥有者接线工作包

- 日期：2026-11-02
- 状态：只读候选遍历、同步离线拥有者周期、单次交接、kind 2/3 入站租约实例绑定及晚到逐跳 ACK 终结的合成路径已实施。真实路由、工作池及传输待接入。
- 来源：[ADR 0004](../adr/0004-node-service-foundation.md)、[ADR 0007 D16](../adr/0007-node-envelope-and-control-budget.md)、[ADR 0009 D18](../adr/0009-node-clock-domains.md)
- 面向：Node 状态拥有者、调度、输入和恢复协作者。目标是将已有内部批处理接到完整且有界的责任来源；不定义新 wire、密码实现、可信平台或产品 QoS。

## 基线与本批范围

D18 已提交为 `8573e88`，schema v9；旧域冻结，新活动不继承旧权限。本批沿用该格式、原配额与现有依赖。所有者明确要求提交工作区并继续下一步；按 [current](../status/current.md) 的接续顺序，完成本工作包及不改变权限/格式的只读候选遍历，用合成数据验证到既有事务调度的路径。

候选遍历随后按所有者要求提交为 `7ee3120`，同步周期随后提交为 `c4ffb5b`。均在同一 Node 自有边界，没有新增持久格式、授权、依赖或 Service/CLI 命令，不扩展真实运行范围。

已有 `process_outbound_batch` 只处理调用者给出的最多 128 个事件。它可以在这批输入内合并观察、优先退出、共享控制桶和持久轮转，但不能知道调用者漏掉的责任，也不能把一次决定当作真实通道的可重放许可。本批不将“可遍历全部保留责任”写成“全部已就绪”或“已经实现全局发送公平”。

## 首批已实施：只读候选遍历

实现集中在 `node/src/store/outbound_scan.rs`，复用 Store 及既有 ControlIngress 的运行者身份，不新增拥有者、线程、数据库、provider 或配置。

| 接口 / 结构 | 合同 |
| --- | --- |
| `start_outbound_scan(lane)` | 由当前可写 Store 创建不透明运行期位置；绑定本次拥有者、当前域和活动。没有当前活动、时间隔离、已停止或到期时拒绝 |
| `OutboundLane::Exit` | 当前活动非 terminal 的 kind 2 邻居责任，以 object/participant 稳定排序 |
| `OutboundLane::OrdinaryControl` | 先列当前域/活动且 policy_stopped=0 的 evidence queue，再列当前活动非 terminal 的 kind 3 邻居责任；这是遍历顺序，不取代实际发送轮转 |
| `OutboundLane::Data` | 当前域/活动且 policy_stopped=0 的 data queue；与控制分开遍历，调用方不能只轮询控制来声称数据公平 |
| `scan_outbound_page` | 使用 keyset 条件和 LIMIT，不使用 OFFSET 或先装入全表；每次返回至多 128 个引用，内部至多读取 129 个作尾页判断。普通控制页可跨 receipt/report 分界，零 ID 是合法键 |
| `OutboundPage` | 只有域、活动、发现时 revision、分组、引用及 complete，不返回正文、事件、签验结论、ACK、预算或发送许可 |
| 失败 / 终结 | 查询中途失败不推进位置；complete 后再次使用显式 Conflict，调用方须明确开启下一轮。游标不支持克隆/序列化，不跨 Store 重开、活动或域复用 |

候选仍可能在未来时槽、Paused、次数耗尽、链路不可达或因后续政策变化而不可输出；就绪判断继续执行原算法与事务内授权。不从持久 source_neighbor、Known 对象或邻居表自动生成 ACK 请求；ACK 必须由已认证、严格解析且已持久接纳的输入驱动，并再次检查已有十次上限。

遍历期间允许合法提交改变 revision；页只说明发现时事实，下一批仍以当前状态复核。游标后方新增的键可在本轮发现，前方新增的键等待下一轮；删除的键不能使后续位置倒退。集合稳定时，一轮有限分页覆盖全部该分组候选，避免永久只取相同前 128 项；持续变化和反复丢弃游标不具有此保证。

位置只存于调用方拥有的内存，重开丢弃；原持久尝试、空桶和成功消费游标均不重置。本批不承诺跨重启的访问公平。未来若要求持久遍历位置，必须显式设计 schema 演进、归档与计费，不能借用现有两个发送游标或写旁路文件。

页面只包含有界键，既有文本引用各至多 64 ASCII bytes，二进制引用为固定 32/16 bytes。最多 129 个临时候选、一个尾部位置与拥有者引用；不是 129 份 payload/frame。返回 Vec 的 capacity、SQLite 查询/索引、allocator、进程 RSS 和实际解析器硬内存仍须平台验证，不能从返回条数推导物理限额已经成立。没有提高 1 MiB / 576、8 MiB 或全局记录总额，也没有新增持久行。

## 第二批已实施：同步离线拥有者周期

`node/src/store/outbound_cycle.rs` 将发现、已捕获观察、显式 ACK 请求与原 `process_outbound_batch` 连成一次同步调用。状态拥有者使用一个不透明 `OutboundCycle`，分别保留 Data 与 OrdinaryControl 的运行期位置；实际线程、事件收集和可信采样仍在未来边界，本模块不制造这些事实。

| 接口 / 阶段 | 实际合同 |
| --- | --- |
| `start_outbound_cycle` | 从当前 Store 创建 Data / OrdinaryControl 位置，绑定原拥有者、域和活动；不支持 Clone/Debug/序列化，不恢复旧输入或决定 |
| `OutboundCycleInput` | 调用方先提交本机控制与完整已验证结果，再提供当前 expected_revision、可信 Clock 和至多 16 个显式 ACK 输入；对象本身不实施认证 |
| 截点与观察 | revision 必须仍匹配；观察提供方只读取已经捕获、认证、合并的输入，对每个候选显式返回同坐标 Batch。没有默认 Allow/link/信号，不在回调中签验、等待 worker、驱动通道或产生外部效果 |
| 退出集合 | 每步重新读取完整当前 kind 2 邻居责任。D16 最多 20 个退出 × 4 邻居，即 80；超过该上界显式 StoreCorrupt，不截断退出集合后先处理普通工作 |
| 数据 / 普通控制 / ACK | 每步分别至多 16 个数据候选、16 个普通控制候选、16 个显式 ACK 输入；ACK 超限整步拒绝，不截断或自动生成。数据和普通控制各自轮到完成时才开启下一轮 |
| 提交 | 合计至多 `80+16+16+16=128` 个原事件，委托既有批处理合并、排序、核验、计费及维护。空步委托既有 maintain，不伪造空批成功 |
| 位置与失败 | 内部暂存两个遍历位置，仅 COMMIT 明确成功后发布位置和本步时刻；读取、观察、权限或写入失败均不跳过候选。原错误及 source 保留，不吞错重放整个周期 |
| 关闭坐标 | 同一句柄成功提交后，该单调毫秒关闭；相同毫秒不得补交晚到输入。后续步须使用更大的真实可信采样，不能自行 +1；无效/回退采样仍沿原路径锁存时间隔离 |
| 提交未知 / 重开 | 原 Store 隔离并拒绝后续写入；重开查询持久责任，旧句柄因拥有者不同而拒绝。新句柄重建遍历，不返还持久尝试、ACK 次数或旧发送额度，也不恢复 ACK 输入 |

80 是既有 D16 的保守退出责任上界，三个 16 是从原 128 输入上限保留退出空间后分配的内部工作片，不是 wire、数据速率、存储上限或产品 QoS 参数。不在退出较少时借出这些工作片，也不扩大 config 或固定预留。周期最多发现 112 个候选及三个尾页判断键，再接纳至多 16 个 ACK 输入；复用的原事务仍执行每类至多 256 条维护。逻辑条数不证明查询、完整性扫描、fsync、回调或整步的物理耗时/RSS 硬上限。

对稳定候选集合，每个分组至多经 `ceil(N/16)` 个成功步遍历到尾项；控制有工作不能使数据工作片永久不被访问。每步重取完整退出集合，已在步间持久接纳的退出进入下一步的原退出优先序列。该结论不是发送机会公平、有限时槽内必达、跨重启公平或真实响应时间保证；错过/受限机会继续按原规则消费，不补发。

本机停止和封禁不依赖周期的“更大毫秒”门，先走原控制事务。已验证结果依各自事务合同处理，迟到的终结输入见[拥有者输入与关闭评审](#拥有者输入与关闭评审2026-11-08)。周期报告只有原已提交决定、截点、候选/ACK 数量及两组尾页事实。交接的合成路径另见[离线接入](#单次交接的离线接入2026-11-08)。

周期 expected_revision / cutoff_revision 表示 Store 的提交修订；已有 `validate_business_output` 的 expected_revision 比较的是政策修订。两者含义不同，不能把周期截点直接传作输出授权或把修订相等解释为通道仍被授权。

## 后续完整接线顺序

以下真实消费者仍待接入；同步周期只在调用者已供应合格输入时完成上述内部部分。候选或周期 API 均不允许跳过消费者合同直接接网络。

1. 状态拥有者从可信平台取 Clock，为输入分配本地顺序并冻结批次截点；先处理已接纳的本机停止/封禁及完整验证结果。未验证字节不能自称退出以插队；结果晚于截点进入下一批，不能回填成已经合并的同坐标输入。
2. 每个分组保留自己的遍历位置，轮到其有界工作页时推进；把候选与当前已认证邻接、期限及 Admission 结合。ACK 输入保持单独的有界来源，不能被候选扫描制造。未来需明确数据/控制工作量配额与实际耗时上限；D16 的控制发送优先不授权无限占用状态线程。
3. 对同责任、同可信坐标的观察先完整合并，再通过原 `process_outbound_batch` 提交。超过 128 的责任分成多批，每批之间留出本机控制和已验证退出的处理点；不能在一个长 SQL 事务中扫完全库，也不能在遍历页之间把普通控制抢先送出当作已保证全局退出优先。
4. 发现已失效项必须有明确拒绝/终结结果；不因一条错误循环重放整页，不吞错后报告全部成功。新退出/封禁应使受影响准备结果失效，再次复核当前域、活动、政策、精确邻接和消息期限；不把整个旧页的 revision 当作权限替代。
5. 只有明确 COMMIT 成功的正向决定才可进入同一拥有者的受限交接。输出前复核与失败处置见[单次交接与撤销设计](#单次交接与撤销设计2026-11-08)。
6. 真实通道须提供有界、非阻塞的写入及中止语义。实际接线前核对 transport 与认证接口能否执行下述合同。
7. 停止时先关闭新准入、撤回未交接工作，再停止并 Join 验证及 I/O worker，收束 leased 任务后关闭 Store。不能因 cancel 释放槽或 pending=0 就建立新活动；跨 boot 或拥有者重建后旧结果与通道必须拒绝。失败保留原因，不以强制清零模拟成功。

## 单次交接与撤销设计（2026-11-08）

本节是 Node 内部的实现前评审稿。第一片只用合成时钟、通道身份和写入结果验证状态转换。沿用 schema v9、现有协议、授权、重试及配额。通道身份的可信来源、实际字节所有权、队列账本与中止能力由后续 transport 评审证明。

### 现有输出路径与复核范围

| 输出 | 现有事务与计费 | 交接前还要核对 |
| --- | --- | --- |
| 数据 `Queue(Data)` | `advance_queue_in_transaction` 检查业务授权和剩余寿命，提交对应队列的重试状态，走独立数据预算 | 同一消息、队列、原始数据及精确邻居凭据。复用业务授权及寿命检查，并拒绝已经暂停、停止、移除或换了内容的责任。剩余寿命按 D15 上界计算，取本次剩余与已准备上限的较小值 |
| 回执 `Queue(Evidence)` | 同一队列入口，提交原重试状态并扣共享控制桶，按 `max(522, body.len()+10)` 计费 | 对应已准备回执和原消息，适用同一业务授权及原消息 deadline。清理、暂停或替换后拒绝旧回执。原内部 proof buffer 的计费上限与严格 COSE wire 上限各自适用 |
| 控制 `Control`（kind 2/3） | `advance_control` 使用当前对象和邻居 participant 责任，扣共享控制桶 522 bytes 后记一次尝试 | 对象、原始已验证字节、邻居责任与认证通道精确匹配。以新时间重查活动与 `control_output_allowed` 的分支权限。kind 3 仍要求 issuer 有效。kind 2 仅可沿 D13 传播原始退出，当前本机非 Active 时只允许原有的本机自身退出例外 |
| 数据 ACK `DataAck` | `consume_data_ack_in_transaction` 要求业务授权、原消息未到期和已持久接收。排除 origin 和已释放 payload 的 relay，按 participant 固定槽，每槽最多十次，扣共享控制桶 127 bytes | 绑定已认证入站请求及已持久接纳的同一消息和邻居。重查接收事实、政策和原消息期限，无需存在外发数据队列。换凭据不会给相同 participant 增加次数 |
| 控制 ACK `ControlAck` | `consume_control_ack_in_transaction` 要求活动有效、本机和邻居均 Active、已有对象/邻居责任，每责任最多十次，扣共享控制桶 127 bytes | 绑定原已认证请求、已持久对象、精确邻居凭据及活动期限。对象传播是否已终结与 ACK 资格分别判断。自身退出例外不适用于 ACK |

依据是 [`scheduling.rs`](../../node/src/store/scheduling.rs)、[`control_scheduling.rs`](../../node/src/store/control_scheduling.rs)、[`outbound.rs`](../../node/src/store/outbound.rs)及 [D15](../protocol/node-data-envelope.md#d15一小时寿命与保守时间判定)和 [D16](../protocol/node-control-propagation.md#转发限速与次数)。两类 ACK 的来源继续由已认证、严格解析并已持久接纳的输入提供。交接阶段只复核已经扣费的这一份决定，不能再次调用扣费入口，也不能以已达到计数上限为由拒掉刚刚扣费的最后一次 ACK。

[`validate_business_output`](../../node/src/store/business_policy.rs) 只读检查 `data` / `evidence` 的 Store 可写状态、原消息剩余寿命、当前业务政策修订及对应队列是否存在。它读取 `self.clock`，未显式接收新采样，也未检查重试相位或认证通道实例。设计复用其业务检查，给输出复核显式传入本次可信采样，并补上责任状态及通道检查。控制对象和两类 ACK 沿各自入口复核，避免套用数据队列存在条件。

控制最后一次尝试可同时返回 `send=true` 与 `progress.terminal=true`，因为本次已用尽未来机会。若本机停止、封禁、对端有效持久 ACK 或其他适用的终结先于交接，仍要撤回这次输出。未来接线须在拥有者中按输入先后撤回相应待交接项，区分本次扣费导致的耗尽与后到的终结事件。单读 `terminal`、重放调度或从持久计数反推旧决定都无法完成这个区分。

### 绑定、消费与中止

1. **创建。** 当前拥有者直接接收原调度事务明确 COMMIT 成功的返回值，只为 `send=true` 的决定建立私有、不可复制、不可序列化的待交接项。绑定本次 owner、时钟域、boot、活动、批次与决定位置、输出种类、原责任与内容引用，以及通道两端的 participant 和 credential ref。调度前从已认证观察固定通道实例，与原责任键关联。同地址、同凭据重连也须用新实例。两类 ACK 还须绑定原请求及其入站实例，不能换通道回发。缺少上下文即拒绝交接，报告或调用者传入的 `send=true` 无法新建待交接项。
2. **区分修订。** 周期 `cutoff_revision` 是提交前的 Store 批次截点，提交后的 Store 修订用于追踪这笔调度的出处。两者都不用于授权相等检查。提交时另取活动的本机政策修订，消费前必须与当前政策修订一致。政策变化使旧准备项失效，不能原地换上新修订。无关 Store 提交允许继续复核，责任、期限和通道仍须逐项检查。D13 路径须在其专用检查下取得同一活动的政策修订，不能借业务修订读取失败跳过复核，也不放宽 `business_policy_revision` 对 Retiring 的业务限制。
3. **复核并消费。** 同一拥有者先处理已接纳的本机停止、封禁、完整验证结果及通道失效。第一次写入前用新采样检查当前 Store 未隔离且 owner、域、活动仍匹配。所有输出都要求有效的同 boot 单调时间及活动 deadline。数据、回执和数据 ACK 另要求可信 UTC 上界与 D15 原消息 deadline，数据和回执还要检查各自队列的 deadline。任何适用截止取更早值，等于截止即拒绝，缺失或回退的可信输入沿原隔离边界失败。绑定、期限、责任或通道不匹配时撤回。检查成功后，在同一有序步骤先终结待交接项的可消费状态，再把它移入唯一写入路径。任何返回、重复通知或失败都不得重新激活。
4. **限制滞留。** 候选设计只保留当前已提交批次的引用，数量受原 128 个决定上限约束，无跨批发送积压、持久新行或额外 payload 副本。按原决定顺序分派。没有有界写入位置就丢弃当前机会，先撤回本批剩余项再推进下次调度。后续独立合法机会仍走原重试或 ACK 输入、扣费与 COMMIT。每个通道实例至多有一个正在写的帧，后续步骤不得与其交错。此边界只约束逻辑状态数量，真实缓存、查询耗时和阻塞上限待测。
5. **处理部分写入。** 合成模型区分零字节、部分、完整和结果未知。确认已写前缀后，只能在同一通道实例推进同一帧的剩余偏移，每次推进前重新复核步骤 3 的条件。后续不就绪、写入失败、已接纳撤销、截止、通道变化、停机或本批结束使剩余偏移失效，立即中止并关闭该实例，禁止排空未写字节、续写、重头写或转移到新通道。结果未知按可能已写前缀处置。确认零字节且通道仍有效时可以仅丢弃该机会。完整写入只记本地输出结果，交付历史仍由原确认路径产生。
6. **序列化关闭。** 未来真实写入的最后授权检查与发起一次有界、非阻塞写入，必须与拥有者观察到的撤销、到期和关闭事件有明确的先后顺序。不能预先把可自行写出的授权排给 worker。已交给内核的字节无法撤回，须验证中止后不会再提交剩余字节。停止时先关准入、撤回待交接项、中止在途写入，再停止并 Join I/O 和验证 worker，最后关闭 Store。Join 不确定则保持关闭并保留故障，旧通道和旧结果不能进入下一活动。

带 `remaining_lifetime_ms` 的数据帧在首字节前确定保守编码值。首字节交付后帧字节固定，续写时若编码值已超过当下保守剩余值，按部分写入中止。真实接线需给出从采样到字节提交的时间上界，并在编码值和截止检查中预留该段时间。合成矩阵只检验离散检查点的顺序与判定。

## 单次交接的离线接入（2026-11-08）

首批在同一 Store 复用 `process_outbound_batch` 和原事务计费。`process_outbound_cycle_with_handoff` 在调度前从调用方已捕获的输入取得每个事件的通道绑定，同责任的矛盾输入整步拒绝。明确提交后才按原报告顺序保留正向且已有通道绑定的决定。缺少绑定的决定不进入交接，持久计费沿原事务结果处理。旧周期入口继续只返回调度报告。

Store 只持有一批有界引用，首版按队首串行推进一个合成帧。`next_outbound_handoff` 返回定位当前项的请求，实际校验使用 Store 内原记录。请求绑定 owner、已提交批次、决定位置和偏移，只有当前有效请求能调用合成写入回调。`advance_outbound_handoff` 在调用前复核当前作用域、政策、精确凭据/实例、适用截止和责任状态。后续短写须保持同一帧描述及偏移。帧描述只有长度和适用的寿命/跳数，真实编码和字节所有权留待 transport。

下一批在前批处理完或显式取消前返回 `Busy`。`withdraw_outbound_handoff` 让拥有者先撤回已接纳终结输入对应的决定，区分这一事件与本次扣费已耗尽未来机会。`cancel_outbound_handoff` 撤回整批。中止、续写失败或结果未知按合成合同返回需关闭的原通道实例，并撤掉批内绑定该实例的其他项。拥有者须先处置关闭结果，才可继续使用该通道映射。重开不会恢复待交接项。

真实接线前还须证明认证通道实例来源、实际字节边界、可中止非阻塞写入、可信时钟采样到写入的上界、物理资源与 worker Join。合成验证只覆盖上述内部顺序和状态。若需改变授权语义、持久格式、配额或依赖，按 AGENTS.md 单独说明影响并确认。

## 拥有者输入与关闭评审（2026-11-08）

本节是接线前评审稿，沿用 D13–D18 的授权、格式和预算。目标是让现有周期只消费有来源、顺序和资源归属的输入。可信时钟、严格解码与验签、真实认证与传输仍由各自前置评审提供。已核对的入口是 [`framing.rs`](../../node/src/framing.rs)、[`control_ingress.rs`](../../node/src/store/control_ingress.rs)、[`outbound_cycle.rs`](../../node/src/store/outbound_cycle.rs)、[`transactions.rs`](../../node/src/store/transactions.rs)、[`control_scheduling.rs`](../../node/src/store/control_scheduling.rs) 和 [`service.rs`](../../node/src/service.rs)。

### 来源、接纳和字节所有权

| 来源 | 现有入口给出的事实 | 拟议接线要求 |
| --- | --- | --- |
| 可信时钟及本机控制 | `ClockSource` 是平台接口。Service 的 32 槽是命令邮箱，`Stop` 排在已接纳命令后 | 使用同一拥有者有序处理平台采样和可信控制。关闭闩锁与远程队列分离，普通命令不能延迟所有者停止或封禁到远程队列清空 |
| 认证邻接和 framing | `Ingress` 按 participant 维护至多四个组装槽，`push` 只消费到第一个完整帧，`take` 转移 body。`expire` 只处理尚未组装完的帧 | 认证层先将活动、双方 participant 与精确凭据交给拥有者。拥有者在本次 owner 下分配唯一、不可回绕的实例标识，同一 participant 同时至多一个活动实例。每次 push/take/close 都先比较实例。关闭旧实例并标记其结果失效后才登记替代实例。尚未返回的旧验签继续占原槽，旧回调不能关闭或填充新的同 participant 槽 |
| 外层解码与 kind 2/3 验签 | framing 完成仅代表长度有效。`queue_control_candidate` 接收不透明 COSE，核对邻居凭据、政策和原始字节，产出 Queued、AlreadyPending、Known 或拒绝 | 严格解码先区分数据帧、COSE 帧及 `LinkAckV1`。COSE frame kind 与对象内部 kind 分开处理。kind 2/3 候选仍按 FIFO、原速率及 16 槽接纳，未验证字节无退出优先级。排队时在同一内部条目绑定精确实例，租约派发和完成都复核此实例及 owner、域、活动、凭据、政策修订。当前接口缺实例且 Queued 不返回任务号，后续需在原排队边界接线，不能按凭据或 FIFO 位置事后猜测 |
| 数据与回执 | `receive` 可返回既有 `MessageView`，relay 的 `schedule_forward` 是另一个入口。T-D 由 `finish_delivery` 复核并提交 | 依严格验证结果进入 T-B/T-C/T-D 原入口。交付事实只来自 T-D。回执 COSE kind 1 保持独立验证与资源账本，不借用 kind 2/3 的 16 槽。T-B 的消息、去重、恢复所需转发责任及预留须完整可核对，具体责任映射评审后才启用 custody |
| 收到逐跳 ACK | `LinkAckV1` 依靠已认证逐跳通道。`observe_custody` 只暂停数据责任。控制 ACK 通过 `ControlEvent` 的 `Signal::Pause` 终结对应邻居的传播 | 用严格解码的 `ack_kind`、活动、对象引用、custodian 及凭据定位已有责任。活动/凭据须在接纳时有效，通道实例须匹配。接收 ACK 进入终结路径，数据不释放唯一 payload，控制不扩大到其他邻居，也不回 ACK |
| 待发逐跳 ACK | `OutboundAck` 是显式内部输入，`OutboundCycleInput` 每批至多 16 项。既有计费仍复核责任和次数 | 只从有明确持久接纳依据的本次入站帧生成描述符，绑定原请求、对象和原入站实例。`receive` 的 `Ok` 或控制的 `Known` / `AlreadyPending` / `Merged` 本身不足以生成。丢 ACK 后的合法重复回复仍按原协议评审，须有本次已认证请求、持久事实及明确复核依据。候选遍历、source_neighbor 和收到的 ACK 都不能代造 |

背压按所有权转移计费。framing 的上界是四个完整帧，每帧 64 KiB 含前缀。`push` 未消费的后缀由调用方持有，接线必须限制单次 read credit 并把读缓冲、未消费后缀计入承载账本。完整帧在下一阶段有额度时才转移。没有额度时停止为该实例继续读取，在本次有界处理内明确丢弃完整帧并记录原因，不靠 `Ingress::expire` 回收完整帧。畸形或组装超时按原合同移除槽并关闭该实例。丢弃发生在持久接纳之前时不回 ACK。

kind 2/3 的等待、leased 及结果待拥有者处理共用原 16 槽，原对象最多 `16 × 512 = 8192 bytes`。完成结果占用原任务额度直至交回，不另开结果积压队列。`take` 与 `Arc` 分配间的瞬时重叠、验证结果中的 `cose` 与 `fields.payload`、解析 scratch、传输队列和 OS 缓冲须另计。原限速继续作用于 Known 与重复。QueueFull/RateLimited 明确丢弃，不退已消费额度，不在其它队列保留待重试副本。数据、回执、握手、实际写入和各 worker 的对象数/字节/时限须在真实运行评审中逐项封账，未封账的入口保留停止。

待发 ACK 首片拟采用一个合计 16 个的描述符槽，冻结给本批的项仍占同一额度。满额只舍弃本次回 ACK 机会，已经成功持久接纳的对象和责任按原事实保留。相同责任及实例的可合并输入只留一项，旧实例条目失效后不迁移到新实例。明确提交成功后释放已被本批消费的描述符。明确失败时保留原错误，只有仍有效且尚未消费的项可在下一合法批复核，禁止自动重放整批。提交未知时隔离并丢弃相关运行期输入，重开只查询持久事实。

### 批次截点与后到终结

1. **有序接纳。** 拥有者对已接纳输入分配本地递增序号，以 owner、域和活动为作用域。网络字节和排队任务可记接收顺序，但只有验证完整且由拥有者复核的结果才进入可执行事件序列。终结类输入只有已有位置可保证处理时才接受，已接纳的终结不因普通队列满而丢失。工作方或对端时间不决定拥有者顺序。计数耗尽时停止准入，不回绕。
2. **冻结截点。** 开始一个调度步时冻结已接纳输入的序号上界。先应用该截点内的停止、封禁、已验证自身退出及适用终结，再处理可安全排序的普通结果。限制性事务不依赖普通观察能否合并。第一笔撤销若改变政策修订，其余旧修订验签结果仍须走原接纳复核，显式记录拒绝，禁止替换修订后提交。只要有已接纳的限制性输入尚未处置，就不推进受影响输出。之后取新可信 Clock 和这些提交之后的 Store 修订。输入序号上界、Store 提交修订与本机政策修订各有用途。时钟尚未超过上次关闭坐标时等待新采样，不伪造 `+1`，也不等待未完成验签来凑齐批次。
3. **提供明确观察。** 用冻结的通道注册与终结事实为每个候选生成原 `Batch`。`Up`/`Down` 来自有序认证连接事件，`Unchanged` 需要已有连续观察，`Admission` 由原授权、资源与 hop 检查给出。未知状态不补 `Allow`。同坐标冲突仍由原 `Batch::merge` 拒绝，不能挑一个结果伪造恢复机会。回调只读冻结事实，签验、I/O 和等候均在其外。一次原调度步之后回到拥有者控制点处理后到事件。
4. **先撤回再处理终结。** 截点后的输入不改旧批次或计费。已接纳的停止、封禁、退出、有效 ACK 及通道失效必须在下一次受影响写入前由拥有者处理。撤回受影响交接项，有已写前缀则关闭原实例，并维持已扣次数。本机封禁和已验证退出按原事务提交，失败或未知保留原原因并阻止受影响输出。受影响写入的最后复核与一次非阻塞发起仍须在同一拥有者顺序内。
5. **兼容既有终结入口。** 数据 `observe_custody` 复用 `RetryState::advance`，在已提交发送的同一毫秒补不同事件可能返回 `Conflict`。控制 `process_control_batch` 经共享批处理，旧交接批未清空时返回 `Busy`。首片候选先撤回对应项并保留已核验的终结输入，若旧批阻塞控制终结则显式取消旧批，再用合法的新时间坐标提交只包含终结的工作。等待期间不发送受影响责任，也不让下一轮重开该责任。重新核对活动、凭据、政策和期限，终结或拒绝原因记录清楚。因处置已接纳终结而本机关闭原通道时，可继续处理该限制性事实，不能借此建立新通道权限。若无法在有界窗口内落地，保持停止并报告失败。首片不改原 retry 的同坐标规则。

### 停止、验收与下一片

关闭准入和设置停止闩锁须在同一同步边界完成，并独立于远程背压。拥有者在每次有界事务或写入段之间检查闩锁，撤回待发项，中止部分写入并处理关闭结果，随后发出 worker 停止请求。等待项显式丢弃，leased 项保持占位直到 worker 交回结果或证实已结束。结果返回不得依赖已经关闭的普通邮箱腾出位置。所有验证及 I/O worker 都须有退出与 Join 证据，释放租约并确认旧通道无续写后，最后关闭 Store。Join 失败或截止未能证明停止，保留故障和旧上下文隔离，不开放新活动或新域。现有 Service 只 Join 状态线程，其阻塞式 Stop 投递和 `cancel_control_verification` 释放槽都不能证明这段生命周期。

评审稿提出以实例绑定原验签租约、给待发 ACK 单设 16 个描述符槽、迟到终结先撤回再持久化，以及独立于远程积压的停止信号。先用合成事件核对这些边界，复用现有队列、事务和交接入口。真实解码、签验、传输、可信平台及实际资源测量按原门逐项进入。

### 通道实例与验签租约离线接入

首片已将通道实例接到 kind 2/3 的原 16 槽和原接纳事务。Store 为调用者已提供的认证端点登记实例，逐次分配 owner 内的实例号。排队、派发、验证后提交均核对同一实例，凭据相同的重连也不转用旧租约。旧实例的关闭调用不能移除新实例。关闭后等待项在原轮询中显式丢弃，已派发项继续计费至归还。当前实例的有效结果仍用原事务原子保存控制对象、封禁效果和传播责任。详见[实现与验收](../testing/node-control-ingress.md#通道实例绑定离线接续2026-11-08)。

同 boot 活动切换须先明确关闭已登记的控制入站实例并清空原有任务。此检查只覆盖 Store 的内存登记。真正的 framing 回调、物理通道关闭、worker 生命周期与实例在外发侧的来源仍需接线。

### 晚到逐跳 ACK 终结离线接入

`accept_outbound_terminal` 接受一条由拥有者已严格核验的入站逐跳 ACK。它核对已登记的精确通道实例、两端凭据、域、活动和既有责任。数据同时核对消息绑定及原截止。未知或不匹配输入不撤回外发，已经终结且没有末次待交接项的重复输入返回 `AlreadyTerminal`。

首片使用一个运行期终结槽。每条明确接纳的终结取消当前交接整批，已有短写时返回须关闭的原通道实例，所有已扣额度保留。整批取消避免在等待持久化期间悬挂无关的部分帧，代价是放弃该批的其他已计费机会。终结待提交时调度返回 `Busy`。`commit_outbound_terminal` 等严格更新的可信坐标，再按当前凭据、政策、责任与截止复核并只提交暂停或控制终结。接纳后的通道关闭不抹除限制性事实，也不为替代实例恢复权限。

明确回滚保留原错误与调度阻断，拥有者可用新采样显式重试。提交未知沿原 Store 隔离，重开只恢复持久事实。若当前权限或期限已使终结无法落地，首片保留阻断并返回原因，由拥有者收束旧活动。真实通道关闭和上游解码/验权来源仍待验证。下一片处理待发 ACK 描述符，独立停止信号随后接续。见[离线验收](../testing/node-outbound-scheduling.md#晚到逐跳-ack-终结离线接续2026-11-08)。
