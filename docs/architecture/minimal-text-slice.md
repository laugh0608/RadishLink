# 最小文字闭环实现前设计

- 状态：Draft，待系统、安全与验证评审
- 日期：2026-09-26
- 目标读者：产品、消息实现、安全与测试协作者
- 范围：一对一文字，A—B—C 唯一中继，手机可缺席
- 非目标：冻结密码库、数据库、生产语言、线格式或实际运行授权

## 用户路径与端点边界

本设计承接[首期场景](../product-definition.md#首期范围决定2026-09-26)：熟人小队入场前配对，现场无互联网，先验证短文字、状态与按键通话所需的文字基础。语音在 P1 验收，本切片只处理文字及作为文字发送的状态短语，不新增遥测协议。

候选沿用[手机身份收敛方案](../mobile/companion-app.md#身份与阶段收敛候选待-sw-g2-评审)：A/C Node 各自持有身份、会话与历史；本机按键/显示和获授权的本地 Web 调用同一个发送/查询入口。手机离开不终止 Node 会话，也不转移私钥。该端点选择仍待 SW-G2 接受，用户确认场景不等于接受具体身份架构。

用户在 A 选择已验证的 C，提交短文字，看到“已排队”；B custody 只显示“中继已接收，等待送达”；A 验证 C 的送达证据后显示“已送达”，不能自动显示已读。断链显示等待及到期结果，存储/身份错误给出明确原因。重启或网页刷新恢复已持久化状态，不重新发起同一用户动作。

配对与会话建立是前置用户路径，不能用预设 verified 标记宣称跑通。合成轨只注入带模式标识的测试身份与不透明载荷；真实轨必须先证明带外验证、首次信任、KeyPackage 生命周期及离线并发策略。本地 Web 的 HTTPS 身份绑定、授权/撤销与同网客户端拒绝仍是独立待关闭项。

## 从动作到恢复的事务表

下列 T-A/T-B/T-C/T-D 是文档中的提交边界名称，不是新的公共 API 或数据库表。实际密码库函数和存储实现尚未选定。

| 步骤 / 所有者 | 输入与必要接口能力 | 提交边界与结果 | UI / 失败行为 |
| --- | --- | --- | --- |
| 1. A 接收用户动作 | 已验证联系人端点、编码后正文、受限的本地动作引用；查询授权与身份状态 | 尚未入队前检查正文长度、资源、身份；动作引用与最终 message key 的绑定须随 T-A 持久化，重试同一动作不生成第二条消息 | 未提交不能显示已排队；身份变化要求重新验证 |
| 2. A 创建待发对象 | 安全层生成密文与待提交安全状态；应用准备 key、不可变核心、deadline 和 outbox | T-A 原子提交发送安全状态、动作绑定、密文、队列与恢复信息，成功后才允许发包 | `QUEUED`；失败不发送，保留真实错误，不重复使用安全材料 |
| 3. B 接受 custody | 有界 frame；relay admission、可见摘要、deadline/hop、配额校验 | T-B 同时提交 payload、key/摘要、deadline、去重、责任、预算及恢复信息；提交后才发 custody | A 只增加 custody 事实，继续保留 payload；B 写失败则拒绝 |
| 4. B 转发 | 同一消息的下一邻接副本；有界发送与可达性事件接口 | hop 减值后的副本及尝试预算可恢复；同邻接重传不再减 hop；断链按修订策略排队 | 发送成功不等于 destination delivery，不释放 payload |
| 5. C 接受与提交 | 版本/长度检查；安全层认证、解密、去重、正文边界与身份检查 | T-C 原子或已证明等价地提交接收安全状态、受保护消息、去重 marker、可重建 receipt/proof 状态 | `COMMITTED` 后才展示一条消息；提交前失败无展示、无 evidence |
| 6. C 返回证据 | 从已提交状态重建 E2EE receipt 与 relay-clear proof | 不为重试重新消费接收安全状态；重复输入只恢复同等语义证据，受寿命与控制配额约束 | C 展示与 A 得知送达可暂时不同，不冒充已读 |
| 7. A/B 分别验证与清理 | A 验证目标端 E2EE receipt；B 验证无正文的清理 proof | 各自 T-D 提交验证后的终态、tombstone、清理记录，再回收传输副本；提交失败保留可恢复责任 | A 才显示 `DESTINATION_DELIVERED`；B 不持有读状态 |
| 8. 各节点重启 | 版本化状态、事务恢复信息、保守时钟锚点、已消费预算 | 恢复唯一消息和责任；证据可幂等重发；损坏/未知版本隔离，时钟不确定不续期 | 恢复原状态或明确失败，不能默认为成功 |

清理对象是待传输副本；A/C 的用户历史按独立保留策略处理，不因网络队列清理而删除用户可见历史。C 的用户交付采用 SW-G1 窗口内 effectively-once：持久化消息身份驱动 UI，不通过内存回调次数声称永久 exactly-once。

动作引用属于本地入口候选，必须限定授权会话/Node scope、长度、数量和保留窗口，并与 T-A 提交及查询恢复一起评审；不得直接复用浏览器随机值充当安全 message ID。若客户端丢失动作引用，应先查询已提交结果，不能默默创建新消息。

## 安全接口与必须证明的缺口

| 接口能力 | 所需证明 | 当前状态 / 关闭责任 |
| --- | --- | --- |
| 身份、会话和配对查询 | Node 与界面权限分离；身份变化、撤销未知和重置可见；端点绑定明确 | 待 SW-G2 系统/安全评审；未指定具体库 API |
| 准备并提交发送/接收安全状态 | 与 T-A/T-C 同一事务或可证明等价的 crash-safe 协调；失败不重用 key/nonce | 候选适配阻塞；不能由 SQLite provider 名称推导成立 |
| relay admission | B 能做准入且不获得内容密钥或假冒真实用户身份 | 待成熟机制与库接口映射 |
| E2EE receipt 和 relay-clear proof | 绑定版本、消息引用、密文认证引用、目标身份/验证凭据和类型；B 只见清理必要字段 | 关键阻塞；不设计新的签名/MAC/握手构造 |
| 恢复与迁移 | 未知主版本拒绝、缺关键字段/损坏隔离、旧状态回滚拒绝；安全状态不单独恢复 | 等待具体持久化设计及故障点映射 |

若 proof 或事务能力无法由被接受的成熟方案实现，报告候选不适配并重开 SW-G1/SW-G2 评审，不能退化成未认证 ACK、摘要相等即送达或跨库补偿掩盖失败。mls-rs Phase A PASS 不填补上述任何一项。

## 路由、时间与观测边界

测试 A→B→C 消耗两个覆盖层 hop；承载连接不自行增加或伪造 custody。物理 hop 与覆盖层 hop 分开记录，Ethernet/Docker 结果不推导无线性能。B 消失且无替代路径时排队或到期；仅 B 恢复后重建原路径，不宣称自动切路。

时间、重试、长度、单故障和版本方案见[SW-G3 修订评审包](../testing/sw-g3-revision-2-review.md)。日志仅使用合成别名、长度、摘要、提交点和结果；真实内容、长期身份、凭据和密钥不入 evidence。schema/profile 不匹配、故障未命中、时钟失效或证据不完整为 INVALID；有效条件下不变量违规或超时为 FAIL。

## 最小验收矩阵

每项均须保存模式、profile/version、输入、注入点、提交前后状态和 expected/forbidden assertions。尚未运行，表格不是验证结果。

| 场景 | 必须成立的结果 | 对应设计 |
| --- | --- | --- |
| 正常文字、手机缺席 | A 单次入队、B custody、C 交付一次；独立操作与网页查询读同一持久状态 | BASE；本机/界面实际入口仍须另行验收 |
| 确认丢失 | C 已提交但 A 未知；duplicate 返回既有证据，不重复展示 | LOSS-EVIDENCE |
| B 只读 / C 满盘 | B 不回 custody；C 安全/消息/去重不部分推进，不回 delivery | READONLY / FULL，分别单故障 |
| A/B/C 提交前后崩溃 | 每个 T-A/T-B/T-C/T-D 的提交前、提交中、成功后而通知前分别注入；恢复为完整旧态或新态 | RESTART 系列扩展子用例，不能只测提交后 |
| 断链 5 s | 同 key/deadline/副本恢复发送，不偷偷增加次数、hop 或观察窗 | DOWN-AB / DOWN-BC version 2 |
| duplicate / conflict | 相同 key/摘要最多一条用户消息；同 key 不同摘要拒绝且原记录不变 | DUP / CONFLICT |
| 身份变化 / 伪造清理证明 | 不发送到未经接受的新身份；无效证据不改变送达、不删除未送达副本 | 合成轨只测分支；真实认证归 SW-V3 |
| 未知版本、超长、截断、损坏 | 高成本操作前有界拒绝；未知持久状态不自动重建空库 | VERSION / LENGTH / CORRUPT |
| 到期、回拨与旧库回滚 | 不续期、不复活已清理副本；无法证明安全状态时隔离 | EXPIRE / CLOCK；安全回滚归 SW-V3 |

## 实施拆分与进入条件

1. **设计接受**：评审本切片、SW-G3 修订及端点/事务/proof 的适用范围；记录接受者与未关闭项。产品场景已确认不替代这些专题评审。
2. **合成 SW-V1/V2 实施包**：明确仅模拟不透明载荷与认证结果；复用 harness 的时间、故障和证据职责，建立正式消息语义的测试实现，禁止把探索性 `t0node` JSON、摘要 ACK 和 snapshot 当作产品协议。先列精确文件和版本，再授权实现。
3. **受限运行包**：实现与离线正负例通过后，固定容器、网络、次数、资源、时长和清理；获得相应授权后才能产生正式三节点 evidence。
4. **真实 E2EE 适配**：遵循 SW-G2 候选精确合同，先关闭许可证/R2 等前置并获准候选运行，证明本表的库 API 和事务/proof 映射；最终 SW-G2 接受后再进入正式 SW-V3。合成通过不跳过此步骤。
5. **P0 用户入口与实体闭环**：补齐首次配对、设备独立操作、本地 Web 信任和三台独立 Linux 有线台架；按 HW 与 D0 条件评审，不把容器当实体。

当前只完成可审阅设计；实现、运行、R2、Phase B、SW-V3 和 P0 均未因此启动。下一轮可先评审合成范围及 SW-G3 修订，真实安全缺口保留为显式阻塞，不新增占位“安全已完成”状态。
