# RadishLink 产品定义

## 定位

RadishLink 是一套可随身携带、无需互联网即可工作的加密自组网通信终端与协议。每台设备既能为本机用户收发内容，也能在不读取内容明文的前提下为其他设备转发数据。

项目不复制 AirTag 的云端众包定位模式。它借鉴的是“附近设备共同扩展网络”的思想，但首要问题是离线通信；定位只作为以后独立评估的可选能力。

## 产品承诺

> 手机在时更方便，手机不在时仍然可用；网络没有中心，消息仍然只有通信双方或群组成员能读。

## 核心使用场景

- 户外活动、营地、园区、展会、地下或灾后局部区域的离线联络；
- 小队在不建设基站、不购买蜂窝流量的情况下共享文字、位置说明和小型媒体；
- 节点之间存在遮挡或距离过远时，通过其他随身节点自动转发；
- 手机靠近设备时使用手机屏幕、键盘、相机和耳机，离开手机时使用设备自身的基本交互。

## 必须能力

这些能力描述产品目标，不表示 D0 或 P0 必须同时实现全部媒体。阶段交付遵循[路线图](roadmap.md)；2026-09-26 已确认首台文字/语音样机不以视频通过为前置，视频仍是后续能力目标。

1. **无网自组网**：没有互联网、路由器或云服务时仍能发现邻居、形成路径和恢复断链。
2. **终端与中继统一**：所有正式设备在硬件和协议上都具备两种能力，不制造只能中继的必需中心节点。
3. **分级通信**：文字和控制消息优先于附件，附件优先于实时视频；链路恶化时自动降级而不是全部失效。
4. **端到端加密**：中继节点和被动监听者无法读取内容；身份、密钥变更和设备撤销对用户可见。
5. **独立操作**：设备至少提供联系人/群组选择、预设或短文字、按键通话、通知和网络/电量状态。
6. **附近手机接入**：手机可作为完整界面和媒体终端，但不被假设具有 HaLow 无线能力。

## 首个场景的收敛方法

2026-09-05 的优先验证假设是：少量熟人组成的小队，在进入无网区域前完成配对，通过随身 Node 交换文字、状态和按键通话。它用于集中需求研究，不代表已经选定首个市场、测试地区或证明用户需求；展会、地下和灾后场景不自动共享同一验收结论。

范围评审需要以下输入；2026-09-26 的范围决定及 2026-10-09 的细化记录在下一节，余项保持待定，不用厂商参数补成用户需求：

| 输入 | 必须回答的问题 | 对设计的影响 |
| --- | --- | --- |
| 用户与替代方式 | 谁携带、谁维护；额外携带设备解决了什么现有问题 | 是否值得形成独立硬件产品 |
| 三项核心操作 | 最常用操作、操作频率、失败后果和可接受等待 | UI、交付语义和验证顺序 |
| 网络条件 | 首个地区、人数、移动/固定、遮挡和典型断连时长 | 无线候选、缓存、发现与路由 |
| 手机缺席 | 手机离开/没电后需继续联系谁、读取哪些消息 | Node 身份与多设备会话边界 |
| 携带与成本 | 重量、体积、充电频率、单机及整套成本上限 | 电池、显示、音频和媒体裁剪 |
| 视频必要性 | 视频是否为主要使用理由；无视频时产品是否仍有价值 | P2 与可携带样机的先后关系 |

在使用者研究或交互验证获授权后，记录任务完成情况、误操作、失败状态理解和携带意愿；保留样本数量与条件，不把个人偏好或纸面推演当成需求验证。具体地区与预算只记录所有者的实际选择。

## 首期范围决定（2026-09-26）

所有者在本轮明确采用“小队熟人在进入无网区域前完成配对，以随身 Node 交换短文字、状态和按键通话”的场景，并确认视频不阻挡首台文字/语音样机。该决定选定开发范围，不代表使用者研究或需求实测已完成。

### 当前范围细化（2026-10-09）

所有者接受熟人小队、Node 身份、有线台架优先及分渠道许可证评审的推荐方向，并将原整套 2000 元上限调整为目标 2000–3000 元、硬上限 3000 元。以下是当前设计输入，不是实测能力或正式实验参数；原视频顺序不变。

| 输入 | 已确认范围 / 待补输入 |
| --- | --- |
| 用户与操作 | 面向 3–5 人熟人小队；最低验证三台节点。短文字、预设状态优先，P1 增加一对一按键通话；不据此扩展现有 profile 或群组协议 |
| 活动与携带 | 一次白天 6–8 小时活动，当天可充电；首台允许背包携带，重量、温升和续航实测后再收敛衣袋形态；6–8 小时是使用目标，尚非续航结论 |
| 断连 | 允许断连、重连与中继暂时离开；文字在寿命和配额内排队，明确等待、送达、过期和失败；语音断开明确提示，不承诺无链路送达 |
| 手机缺席 | Node 持有通信身份、会话与受保护历史，手机为可断开的已授权界面；Node 独立完成联系人选择、文字和状态操作，P1 增加按键通话；安全机制仍须 SW-G2 评审 |
| 地区 | 测试/首期使用地区仍为中国上海；场地可按验证需要选择，先室内有线、后续再选择合规无线场地；不限制场地不等于改变地区或免除 RF 前置，销售范围未指定 |
| 成本 | 整套目标人民币 2000–3000 元，累计硬上限 3000 元；不是最低消费或单机额度。首轮有线台架新增支出评审上限仍为 1000 元，未授权采购 |
| 设备基础 | 所有者确认没有可复用设备；三节点及必要配件按全新增方案核算，不假定能借到设备 |
| 视频 | 不阻挡首台文字/语音可携带样机；P2/Share/View 继续独立验收，不宣称已经支持 |
| 尚缺条件 | 具体参与者、操作频率、典型断连时长、可接受等待、重量/体积数值上限及全新增 BOM 报价；不得用现有测试参数代填 |

预算核算先覆盖三节点方案的新增设备、存储、电源、接口/线材、必要交互外设、运费及预留；已有设备单列复用和重置价值，不用复用价证明量产成本。是否能在该预算内覆盖无线和可携带样机尚未证明，超预算须提交取舍，不能自动加预算、减少三节点或降低安全条件。此预算不是采购授权。

首个完整用户路径为 A 经 B 向 C 发送加密文字，在允许寿命内断连恢复，重启后不丢失已承担的持久化责任、不错误显示送达。Node 身份选择见[手机接入方案](mobile/companion-app.md#首期身份与阶段选择2026-10-09)，硬件顺序见[硬件验证计划](hardware/hardware-validation-plan.md)，许可证渠道与候选顺位见[SW-G2 决策包](security/e2ee-sw-g2-decision-package.md#2026-10-09-所有者选择与近期评审输入)。

## 验收层级

以下数字是需要实测的产品目标，不是现有硬件承诺。距离默认指室外视距、合法功率、合规天线、天线离地高度和天气均被记录的单跳条件。

| 层级 | 目标能力 | 首期验收目标 |
| --- | --- | --- |
| `Reach` | 文字、状态、低频位置与小型控制数据 | 1 km 单跳，16 KiB 正文经端到端加密后，99% 在 10 秒内取得目的端送达确认 |
| `Share` | 压缩图片、语音留言、小视频片段 | 500 m 单跳，支持断点、校验和后台低优先级传输 |
| `Talk` | 一对一实时语音 | 500 m 单跳，Opus 目标 16–32 kbit/s，连续 10 分钟可理解且无持续卡顿 |
| `View` | 一对一中低码率视频 | 500 m 单跳，240p/360p、10–15 fps、目标 250–700 kbit/s，连续 5 分钟可用 |

多跳目标单独验收。POC 首先限制为最多一个中继；不能用每跳 500 m 的目标推导任意跳数下仍有相同视频质量。

## 首期内容边界

- 文字单条正文最大 16 KiB，以编码后的正文 bytes 计，不含加密、认证和覆盖层信封开销；
- 图片原始上传最大 1 MiB，并生成不超过 64 KiB 的预览；
- 语音留言默认最长 120 秒，Opus 编码；
- 小视频默认最长 15 秒、最大 8 MiB；
- 实时语音和视频首期仅一对一；
- 超限内容在发送端拒绝或转码，不把限制造成中继节点的内存风险。

限额属于初始安全阀，可在真实链路、存储和功耗数据出现后调整。

正式实现须分别限制正文、认证密文、信封与附件分块长度，在分配前检查对应上限；不得把 16 KiB 正文直接当成密文上限。精确额外开销和分块策略由 `SW-G2` 与版本化协议设计确定，合成测试限额不自动成为产品格式。

## 明确非目标

- 不在首期承诺替代蜂窝网络、卫星通信或专业应急无线电；
- 不承诺在密集城区、地下深处或复杂山地仍达到标称视距距离；
- 不以 RSSI 冒充精确定位，也不在首期建设 AirTag 式全球众包定位；
- 不允许用户随意解锁超法规功率、频段或外接功放；
- 不自研密码算法、音视频编解码器或未经审计的安全握手；
- 不在 POC 阶段承诺防水、防摔、全天续航或量产成本。

## 成功标准

项目进入手持工程样机前，至少需要形成：

- 三节点路径建立、断开和恢复的可重复证据；
- 消息跨不可信中继的端到端加密证据；
- 明确地区下 1 km 文字与 500 m 语音的外场数据，条件按对应验收层级记录；
- 首台样机所含文字/语音的吞吐、时延、丢包、温升和能耗预算；
- 手机在场与不在场两条用户路径；
- 选定模块、天线和整机方案的法规与认证路线。

以上按 2026-09-26 所有者决定收敛为首台文字/语音样机基线，具体依赖见[阶段顺序修订记录](roadmap.md#阶段顺序修订记录2026-09-26)。后续视频样机仍须完成 500 m 视频外场目标、Share/View 与对应媒体资源验收；安全、升级恢复、硬件、法规和文字/语音条件均未放宽。未达到这些条件的局部 Demo 不能称为 E0。
