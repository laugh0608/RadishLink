# RadishLink 原型采购清单

## 先回答“现在是否要买设备”

**现在不采购。** 当前先评审[项目执行计划](../status/project-execution-plan.md)与[低成本硬件验证计划](hardware-validation-plan.md)，并只读盘点可以复用或借用的 Linux 设备、USB Ethernet、电源和外设。`HW-G2` 未通过前不下单；HaLow 采购继续暂停，并受独立射频合规门约束。

若软件可行性证据成立，最低成本实体化顺序是：复用三台 Linux 设备完成 `HW1` 纯有线台架；确有缺口时再购买三台一致的低成本 Linux SBC；之后只买一块 ESP32-S3 与最少外设完成 `HW2`。不要先买三块 MCU 或一块地区不明的 HaLow 模块。

## 第一阶段 BOM：无射频硬件验证

以下是 `HW-G1` 盘点模板，不是采购授权：

| 优先级 | 数量 | 物品 | 用途 | 采购条件 |
| --- | ---: | --- | --- | --- |
| 1 | 3 | 已有/借用 Linux 主机或 SBC | A/B/C 独立供电、存储与重启 | 首选零采购；记录型号、RAM、存储、BSP 和用户数据边界 |
| 1 | 2–3 | 已有 USB Ethernet 与短网线 | 强制 A—B—C 两段有线拓扑 | 只补实际接口缺口；B 必须有两个独立接口 |
| 1 | 3 | 合规电源与存储介质 | 供电、掉电和恢复 | 优先复用；禁止覆盖用户已有数据 |
| 2 | 最多 3 | 同型号低成本 Linux SBC | 无可复用设备时替代 | `HW-G2` 比较 BSP、退换和总成本后授权 |
| 3 | 1 | ESP32-S3 开发板 | 单节点按键、显示、电源与看门狗 Demo | `HW1` 与 IPC 设计通过后单独授权 |
| 3 | 各 1 | 小屏/按键/电量或温度外设 | A 节点最小交互闭环 | 只买已列入 `HW2` manifest 的外设 |

低成本 SBC 候选与限制见[低成本硬件验证计划](hardware-validation-plan.md)。价格、卖家和本地供货变化快，只有提交采购授权时才记录实时单价；本文不把挂牌价写成项目预算事实。

## HaLow 采购前置门（后续）

向供应商、当地无线电管理专业人员或认证实验室书面确认：

- 实际测试国家/地区；
- 精确料号和硬件 revision；
- 固件监管域与允许信道；
- 1/2/4/8 MHz 中哪些带宽可用；
- 最大发射功率、天线增益、占空限制和室内/室外条件；
- 评估设备进口、持有和外场发射所需手续；
- 802.11s 在该监管域和当前固件是否可选。

未关闭这些问题前，只允许依法合规的无辐射/屏蔽/传导测试方案，并应由专业方确认实验安排。

## 后续清单：路线 A（HaLow 应用优先）

| 数量 | 物品 | 用途 | 采购备注 |
| ---: | --- | --- | --- |
| 3 | `MM8108-EKH01-01` | Linux + MM8108 的完整三节点 | 三套保持同地区、同 revision；确认是否包含电源、天线和当前 OpenWrt 镜像 |
| 3 | 独立 2.4 GHz USB Wi-Fi 适配器 | 手机/Mac 近距接入 | 先确认芯片组在套件 Linux/OpenWrt 上支持 AP 模式与 HaLow 并发 |
| 3 | 32–64 GiB 高耐久 microSD | 系统、日志和媒体缓存 | 统一型号，保留一张金镜像 |
| 3 | 合规 USB-C 电源或带 PD 的移动电源 | 台架与外场供电 | 记录实际输出能力，避免电压跌落被误判为无线故障 |
| 3 | USB 耳麦或统一 USB 音频适配器 | 双向语音测试 | 统一型号降低音频驱动变量 |
| 1 | 官方相机版本或兼容摄像头 | 视频发送端 | 先买一个；视频链路通过后再补齐其余节点 |
| 3 | 便携支架/固定夹 | 统一天线高度与方向 | 测试时记录高度、极化和朝向 |
| 1 | USB 功率计 | 记录节点功耗 | 分待机、文字、语音、视频状态采样 |
| 1 | 软卷尺/激光测距辅助 + GNSS 轨迹记录 | 距离证据 | GNSS 可先使用手机，但要保存轨迹和误差说明 |

建议第 4 台节点作为第二批采购，用于路径冗余和同时故障；三台是最低闭环，不是最终网络规模。

## 后续清单：路线 B（射频与应用解耦）

| 数量 | 物品 | 用途 |
| ---: | --- | --- |
| 3 | `HaLowLink 2` 或 `MM8108-EKH19` | HaLow Mesh、2.4 GHz 接入和 Ethernet 桥接 |
| 3 | 2–4 GiB RAM 的 Linux SBC | 运行加密消息和媒体应用 |
| 3 | 短 Ethernet 线 | 每个路由节点连接本地应用主机 |
| 3 | 统一电源/移动电源 | 同时为路由器与 SBC 供电 |

这条路线调试最清楚，但体积与功耗完全不能作为手持产品指标。HaLowLink 2 的 32 MB NAND 也不适合直接塞入完整媒体应用。

## ESP32-S3 的采购边界

在 `HW1` 与 IPC 边界评审后，最多购买 1 块带 PSRAM、USB 和目标显示/音频接口的 ESP32-S3 开发板，用于验证：

- 按键、显示、电池计量和低功耗唤醒；
- 首次 USB 刷写后的局域网签名 OTA；
- 主处理器关机/唤醒与看门狗协议。

在 Linux 三节点 POC 完成前，不买三套 ESP32-S3，也不投入它与 MM8108 的自定义 PCB。MCU 无线默认关闭，不能用其 2.4 GHz 结果替代 HaLow 或产品近距接入结论。

## 这一阶段不要买

- 只支持 LoRa/FSK 的模块作为实时语音视频主链路；
- 地区版本不明、不能锁定监管域的 HaLow 模块；
- 外接功率放大器、高增益改装天线或“解锁全频段”设备；
- 只凭峰值 PHY 速率宣传、没有 Linux/OpenWrt 驱动与参考设计的模块；
- 最终屏幕、摄像头、电池和外壳的大批量物料；
- 两台节点后就宣称完成 Mesh 的采购方案。

## 到货验收

1. 拍照记录料号、revision、天线、序列号和包装地区标记；
2. 保存供应商页面、数据表、固件与校验值，不依赖未来可能变化的下载链接；
3. 在不发射或合法的台架条件下验证启动、恢复、Ethernet/USB 和日志；
4. 三台升级到同一已记录固件，禁用自动漂移；
5. 备份原始配置和恢复镜像；
6. 完成近距离单跳、三节点中继和断电恢复后，才进入距离阶梯测试。

## 未来 HaLow 首单建议

只有目标测试地区确认支持对应 MM8108 套件、`RF-R*` 与采购授权均通过时，才比较路线 A 的三套 `MM8108-EKH01-01` 与路线 B。届时仍只给一台配摄像头，其他媒体和外设按验证结果分批补齐。地区或 SKU 未确认时保持零 HaLow 采购。
