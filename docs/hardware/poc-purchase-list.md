### 接口与首次操作路径

候选板卡收敛为三台同型号 **ZERO 3E 2GB、带排针、无 eMMC 的 `RS109-D2E0H1`**，实际 PCB revision 须随报价确认；官方资源页列出 3E V1.2，不代表卖家交付一定是该 revision。3E 与 3W 的存储/无线配置不同，不从系列名称继承 eMMC 或 Wi-Fi。

### 两级预算判断

令 `P` 为每台板卡人民币含税价格，`X` 为表中所有非板卡项目、运费/税费/支付费用和预留合计，则首轮必须满足 `3P + X ≤ 1000`。若 `P` 尚未含税，税差必须计入 X；套装已包含的部件只计一次。

目前只有三类美元标价可组成**不完整参考小计**：`3 × (39.99 + 7.90 + 2.50) = USD 151.17`。它不包含存储、线材、网卡、救援/测量工具和税运，且板卡、散热片缺货，不能称完整报价。设实际综合换算系数为 `r` 元/USD，该小计为 `151.17r` 元；仅当 `r ≤ 1000 / 151.17 ≈ 6.615` 才可能让这三类标价本身不超首轮上限，其他新增费用还会压低这个阈值。本次没有把任何假设汇率写成实时汇率。

用于筛选国内报价的反向算术：如果将来 X 的完整报价分别为 250 / 350 / 450 元，则 P 上限分别为 250 / 216.66 / 183.33 元（向下取到分）。这些是敏感性条件，**不是附件估价、预留批准或市场可行价**。在 X 未闭合前不填“预计总计 1000 元”。

| 累计账目 | 当前值 / 计算规则 |
| --- | --- |
| 已支出 | 本轮采购为 0；历史累计金额 `S` 待对账 |
| 首轮待购 | `C1 = 3P + X`，当前未知；需同时满足首轮 ≤ 1000 和累计上限 |
| HW2 增量 | A 一套 MCU/显示/按键/采集及连接件，待精确 SKU 和报价 |
| P1 增量 | A/C 两端音频、接口扩展及供电余量，待报价；不能只算一套 |
| 携带增量 | 三台电池/供电转换/保护、结构与必要线材，待报价；能量仅按[规划假设](hardware-strategy.md#能量体积与成本联合预算)核算 |
| 无线与合规 | 经上海核对的长距/近距配置、天线及所需评审测试成本均未知，不按零元 |
| 剩余额度 | `3000 - S - C1`，仅是余额；须再覆盖上述增量和预留。即便 S=0、C1=1000，也只是尚余 2000，不证明足够 |

结论：本次完成了物料范围与成本缺口定位，**尚不能证明首轮 1000 元或整套 3000 元可行，也不能证明全部市场方案均超预算**。优先补同型号三台的国内含税报价和配件报价；若不能满足，提交“同板型 4GB 实际可购方案 / 已有其他板型候选 / 明确调整首轮额度”的并列影响，再由所有者选择，不自动变成两节点或挪用后续预算。

### 关闭本轮缺口的顺序

1. 依据[设备/BSP 预检表](hardware-validation-plan.md#本轮候选与-bsp-预检2026-10-24)完成板型、镜像来源、网卡驱动、初始配置和恢复的纸面闭合；后续实测单列，采购前不伪装成已验证。
2. 获得可供三台同 revision 的国内报价，逐行补齐金额、税运、退换范围、报价日期与来源，核算 C1 与累计账目；没有合法来源/库存就保持待定，不自动联系卖家或下单。
3. 上海无线路径另按[地区预检表](../regulatory/radio-compliance.md#地区记录内容)补具体 SKU/revision、固件监管域、频率/带宽/功率、天线与书面结论来源。本轮未重判法规，仍为 RF-R0；有线 BOM 不替代这项。
4. HW-G0/G1 详细评审与软件前置满足后，才提交精确 HW-G2 采购包；首次写卡、启动、配置和掉电测试另走 HW-G3。本次未改变“暂不新增 I5 宿主采购”的决定。

## HaLow 采购前置门（后续）

向供应商、当地无线电管理专业人员或认证实验室书面确认：

- 实际测试国家/地区；
- 精确料号和硬件 revision；
- 固件监管域与允许信道；
- 1/2/4/8 MHz 中哪些带宽可用；
- 最大发射功率、天线增益、占空限制和室内/室外条件；
- 评估设备进口、持有和外场发射所需手续；
- 802.11s 在该监管域和当前固件是否可选。

未关闭这些问题前，只允许依法合规的无辐射/屏蔽/传导测试方案，并应由专业方确认实验安排。

## ESP32-S3 的采购边界

在 `HW1` 与 IPC 边界评审后，最多购买 1 块带 PSRAM、USB 和目标显示/音频接口的 ESP32-S3 开发板，用于验证：

- 按键、显示、电池计量和低功耗唤醒；
- 首次 USB 刷写后的局域网签名 OTA；
- 主处理器关机/唤醒与看门狗协议。

在 Linux 三节点 POC 完成前，不买三套 ESP32-S3，也不投入它与 MM8108 的自定义 PCB。MCU 无线默认关闭，不能用其 2.4 GHz 结果替代 HaLow 或产品近距接入结论。

## 这一阶段不要买

- 只支持 LoRa/FSK 的模块作为实时语音视频主链路；
- 地区版本不明、不能锁定监管域的 HaLow 模块；
- 外接功率放大器、高增益改装天线或“解锁全频段”设备；
- 只凭峰值 PHY 速率宣传、没有 Linux/OpenWrt 驱动与参考设计的模块；
- 最终屏幕、摄像头、电池和外壳的大批量物料；
- 两台节点后就宣称完成 Mesh 的采购方案。

## 到货验收

1. 拍照记录料号、revision、天线、序列号和包装地区标记；
2. 保存供应商页面、数据表、固件与校验值，不依赖未来可能变化的下载链接；
3. 在不发射或合法的台架条件下验证启动、恢复、Ethernet/USB 和日志；
4. 三台升级到同一已记录固件，禁用自动漂移；
5. 备份原始配置和恢复镜像；
6. 完成近距离单跳、三节点中继和断电恢复后，才进入距离阶梯测试。

## 未来 HaLow 首单建议

只有目标测试地区确认支持对应 MM8108 套件、`RF-R*` 与采购授权均通过时，才比较路线 A 的三套 `MM8108-EKH01-01` 与路线 B。届时仍只给一台配摄像头，其他媒体和外设按验证结果分批补齐。地区或 SKU 未确认时保持零 HaLow 采购。
