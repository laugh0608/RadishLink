# Node 安全接入设计

日期：2026-10-24。面向 Node 实现与安全评审，细化已接受的 [ADR 0005 D6—D10](../adr/0005-node-security-integration.md)。本文区分设计合同、已有持久基础和仍须真实候选验证的事项；不定义最终 wire 字节格式，不充当密码安全审计或许可证意见。

## 依据与实现状态

[固定源码核对](e2ee-sw-g2-decision-package.md#node-联合事务接入源码核对2026-10-24)覆盖 mls-rs 0.56.0、mls-rs-core 0.27.0、SQLite provider 0.23.0。补充读取同一留存归档的 `src/identity/provider.rs`、`src/psk.rs`、`src/client_builder.rs` 与 manifest，均与归档对应文件逐字一致；没有构建或运行候选。

- builder 允许分别配置 group storage、KeyPackage repository、PSK storage 和 IdentityProvider。
- GroupStateStorage 涵盖 snapshot/epoch，KeyPackage 删除也必须纳入同一事务；仅包住 group write 不够。
- PreSharedKeyStorage 此版本提供 get/contains；不能臆造写方法。若未来启用外部 PSK，其配置写入属于应用持久职责，并须另行核对实际 feature 闭包。
- IdentityProvider 的 validate_member 不能代替每条业务的授权检查；valid_successor 专用于 external commit 的替换关系，不是通用撤销入口。

D6—D10 接受后的 Node 自有持久实现与 63 项离线测试见[证明生命周期记录](../testing/node-receipt-lifecycle.md)；该结果不包含实际候选或密码能力。

现有 Node 的 SecurityUpdate 仍是不透明的合成状态接口，不是完整 MLS 持久适配。产品图去除旧 SQLite provider 可避免已发现的两组 libsqlite3-sys links 冲突输入，但必须重新解析并审查完整图，不能据此预先宣告整合成功。

## 唯一事务拥有者

状态线程打开 SQLite 事务，建立只在本次操作有效的访问上下文；正式 trait 的回调共享同一连接。上下文至少约束拥有线程、操作代数和活动状态。不得另开连接、嵌套事务、自行 COMMIT，事务结束后的句柄必须拒绝访问。

候选结构是共享连接加短时互斥访问：每次 SQL 回调只短暂持锁，调用 MLS 前释放该锁，避免递归等待自己。Send/Sync、同步或异步 feature、回调线程与重入行为须通过实际候选编译和负例验证；本方案没有通过不安全类型转换强行满足 trait 的豁免。

| 操作 | 必须共同持久的内容 | 提交后才可发生 |
| --- | --- | --- |
| 发送 T-A | 安全状态/epoch、动作幂等键、消息、历史、待发责任、对应授权检查 | 密文离开 Node、界面确认动作成功 |
| 目标接收 T-C | 安全状态/KeyPackage 等变化、受保护历史、消息去重、证明意图与控制容量 | 展示明文、读取已提交意图进行签署 |
| 中继 T-B | 已准入密文、来源邻居、原 deadline、去重与返回容量预留 | custody 确认 |
| 中继清理 T-D | 已验证证明的返回责任、终态与 payload/data queue 清理 | 宣告清理成功、上游发送证明 |
| 配对/成员/撤销 | 库要求的状态与应用信任映射、授权修订及受影响责任 | 使用新权限、关闭旧授权后的完成通知 |

任何错误均丢弃已推进的 group 和关联缓存，重新建立对象必须依据完整持久结果。提交结果未知时禁止继续签署、加密、展示或发送；恢复按动作/消息键核对，不自动重发。旁路 KeyPackage 生成与消费、旧 epoch、外部 PSK（如启用）和身份映射都要列入实际写集合。库的序列化状态与清零类型按库合同使用，不自制 nonce 或密码状态格式。

## 证明与信任映射

A 与 C 的私聊只让 A/C 持内容密钥；B 不因参与活动而成为这段私聊的 MLS 成员。参与者可分别建立通信会话，活动前面对面验证的映射让 B 能检查 C 的独立证明键。绑定过程必须覆盖实际 MLS SigningIdentity 和证明公钥，不能只比较昵称、IP、MAC 或一个未认证标识。

COSE_Sign1 是标准封装方向，采用成熟实现；应用仍须验证签名键与主体授权，kid 只是查找提示。[RFC 9052 §3.1](https://www.rfc-editor.org/rfc/rfc9052.html#section-3.1)、[§4.4](https://www.rfc-editor.org/rfc/rfc9052.html#section-4.4)。具体算法与编码 profile 未冻结。

拟议签名负载绑定协议版本、receipt 类型、活动/重放范围、message key、不可变认证核心与密文摘要、目标凭据引用及其代数。使用活动内标识减少跨活动关联，不公开低熵正文摘要。签名类型必须区分 custody、destination delivery 与可选 read receipt；custody 不能代替终点交付。

验证使用存储消息的预期目标及本地可信键映射，检查所有绑定、长度、算法 allowlist、关键字段与授权状态。拒绝未知必需字段、歧义编码、跨活动/跨消息重放和自带替换键；不把单纯签名有效当作有权清理。

### 提交、签署与返回

1. T-C 原子提交可语义幂等重建的证明意图与返回容量，不把事务内准备的数据送到签名器或网络。
2. 提交后读取意图，检查当前授权和可信 deadline；签署后在入队时再次检查，并以一笔事务把意图/预留转换成待发证明。
3. 签署后、入队前崩溃可重新处理同一意图；不得再次创建历史。重复入队不能重置起算点、重试次数或恢复额度。
4. B 验证后以 T-D 接管返回责任再清理；重复 proof 复用已有责任，错误来源邻居不能替换原返回路径。
5. 生成、入队和实际输出前都检查原消息 deadline。调度决定不是可以无限期持有的发送许可；未来 I/O 接入还须在输出点检查授权代数、有效时间及当前状态。

到期清理可以释放证明/意图占用，但保留目标端已交付事实、历史和去重记录。消息保留窗口不延长证据寿命。时间不确定时不继续这些写入或输出；过期签名、自报签名时间不能复活责任。实际事务跨过 deadline 的竞态还须由平台采样与提交/输出边界共同验证，当前手动 Clock 测试不是实时保证。

## 撤销状态与并发规则

手机授权代数、通信凭据代数、MLS epoch 和本机策略修订是四种不同坐标。内部验证结果必须绑定读取时的策略修订，业务提交及输出再次核对，避免“验证后撤销、仍按旧权限输出”。MLS 的凭据规则需要应用身份服务，撤销后的处理策略不能省略。[RFC 9420 §5.3](https://www.rfc-editor.org/rfc/rfc9420.html#section-5.3)。

| 情况 | 已接受行为 | 仍待机制验证 |
| --- | --- | --- |
| 手机界面撤销 | 本机持久撤销后拒绝请求，取消未交付旧响应并关闭连接；Node 继续通信 | 输出竞争、会话失效、已在途字节的边界和通知顺序 |
| 联系人/证明键被撤销 | 本机阻止相应新业务、旧会话使用与新证明接受；既有历史事实保留 | 全部操作路径的统一检查、旧 epoch 与待发项处置 |
| 网络分区 | 尚未获知撤销的节点可在既有合法寿命内离线工作；不承诺即时全队撤销 | 有权主体的凭据、消息传播、重复/乱序合并 |
| 队友报告设备丢失 | 作为待确认信息，本机所有者确认封禁；报告者不自动取得全队撤销权 | 报告认证、界面确认与抵抗恶意封禁 |
| 身份替换 | 重新可信配对，不因同名/地址自动解除封禁 | 新旧活动/凭据关联、避免回滚到旧授权 |

同一被封禁凭据不得被迟到“允许”消息自动恢复；不同节点的本机计数不能直接比较形成全局胜者。更广的队伍管理权限和无人确认全队撤销不在首期接受范围。签名证明不能证明恶意目标端确实存储内容，已显示明文无法撤回。

## boot、时间与状态新鲜性

同 boot 优先接入 CLOCK_BOOTTIME，以计入休眠；普通 CLOCK_MONOTONIC 不计休眠。二者均不提供跨 boot 停机时长证明。[Linux clock_gettime](https://man7.org/linux/man-pages/man2/clock_gettime.2.html)。可信平台输入还需约束时钟误差、启动标识来源、权限和输出前采样，不能信任 UI 或邻居自报时间。

跨 boot 必须分开证明：当前时间/停机上界可信，以及持久安全状态没有被替换成旧副本。LUKS、库内 revision 和 clean-shutdown 标志不满足第二项；手动解锁也不是授权继续旧会话。

首期只恢复可检查的只读事实，旧安全状态与传输责任保持隔离。新活动需新的会话与可信配对，并让相关对端拒绝旧活动；没有该过程前不能调用新建数据库来假装恢复完成。历史副本不得恢复 UI 授权或联系人信任。即使重新配对，也不能宣称已经具备硬件防克隆或完整防回滚能力。

未来如评审透明恢复：剩余寿命需扣除可证明的已过时间上界，并与可信 not-after 及本地上限取更早值；没有正的可信剩余值就不续传。到期历史删除反而需要时间下界已到达保留期限，不能用时间上界提前删除。外部计数器/见证与 SQLite 之间的崩溃窗口也必须有可证明处理；不确定时继续隔离，不假定两者天然原子。
