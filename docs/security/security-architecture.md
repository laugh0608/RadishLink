# RadishLink 安全架构

## 安全目标

RadishLink 假设无线信道可被完整监听、记录、重放和注入，也假设某些中继节点不可信。系统需要保护消息和媒体的机密性、完整性、发送者真实性，并在设备丢失、成员移除或密钥更新后限制历史与未来泄露范围。

## 不承诺解决的问题

- 不能阻止射频干扰、阻塞、设备物理摧毁或大范围断电；
- 不能完全隐藏通信时间、包大小、邻接关系和大致流量模式；
- 设备已解锁且端点被恶意软件控制时，端到端加密不能保护正在显示的明文；
- POC 不宣称达到军用、国家秘密、执法或生命安全系统等级。

## 信任分层

| 层 | 保护 | 不足 |
| --- | --- | --- |
| HaLow / 2.4 GHz 的 WPA3 或等效机制 | 当前无线邻接上的帧与入网控制 | 中继或网络成员仍可能看到上层明文，不能替代 E2EE |
| TLS / QUIC / DTLS 等传输安全 | 当前端点或逐跳传输、抗篡改与拥塞语义 | 如果连接在中继终止，中继仍可能获得明文 |
| RadishLink E2EE | 只有会话端点或群组成员能够解密内容 | 仍暴露必要路由元数据和流量特征 |
| 本地加密存储 | 锁定或丢失设备上的静态数据 | 已解锁端点与内存中的明文仍需系统隔离 |

所有层都应启用，但产品“加密聊天”的核心声明以 E2EE 为准。

## 设备身份与配对

- 首次启动在设备内生成身份密钥，不从序列号、MAC 地址或弱随机数推导。
- 身份私钥应为不可导出或至少受硬件密钥包装保护；POC 可先使用 Linux 受限密钥文件，但不得误称硬件保护。
- 用户通过二维码、短认证串或面对面扫描验证联系人，界面明确显示“未验证”“已验证”“密钥变化”。
- 添加新设备必须由现有已验证设备或离线恢复凭据授权，不能仅凭知道群组名加入。
- 设备撤销和密钥变化通过签名控制消息传播，并允许网络分区后的确定性合并。

精确签名算法和安全元件等待实现库与硬件评审后冻结。协议线格式必须版本化并支持算法协商的受控迁移，不能允许静默降级。

## 消息与群组

推荐评估路线：

- 一对一会话评估成熟的预密钥握手与双棘轮实现，满足异步建立、前向保密和失陷后恢复；
- 群组评估 IETF MLS（RFC 9420），它面向异步群组密钥建立，并把不可信投递服务纳入模型；
- 附件使用独立随机内容密钥分块加密，内容密钥只通过 E2EE 消息发送；
- 中继缓存的是完整认证密文，不能重加密为中继可读格式。

在正式选择前必须完成：实现库维护状态、许可证、持久状态崩溃安全、随机数质量、跨平台兼容和已知审计结果。不得根据本文自行拼装“类似 Signal/MLS”的新协议。

## 实时媒体

- 信令和媒体密钥通过已认证的 E2EE 会话建立；
- 首期评估 SFrame（RFC 9605）或成熟媒体栈提供的等价端到端帧加密；
- 中继可以读取转发所需的最小序号、时序和拥塞元数据，但不能解码音视频；
- 每个发送者使用独立密钥/计数空间，严格防止 nonce 重用；
- 重新入会、换路、设备新增和移除时触发清晰的密钥 epoch 变化。

## 重放、滥用与资源耗尽

- 消息 ID、发送者序列、会话 epoch、时间/寿命和认证标签联合防重放；
- 在解密大载荷前先检查长度、版本、来源配额和认证可行性；
- 每来源限制邻居声明、路由查询、握手、未确认消息和附件占用；
- 控制消息使用独立小队列，不能被视频或恶意附件挤占；
- 错误响应采用限速和固定上限，避免成为反射放大器；
- 日志默认不记录联系人名称、消息正文、密钥、完整节点 ID 或精确位置。

## 本地设备安全

- 主系统启用验证启动；发布镜像签名并绑定明确的版本与硬件兼容范围；
- 根文件系统或应用采用 A/B 更新，首次启动健康检查失败自动回滚；
- 防回滚计数、防止旧漏洞镜像重新安装；
- 用户数据卷加密，锁屏后销毁会话明文缓存和可销毁的派生密钥；
- 恢复模式只接受签名镜像，恢复会清楚说明用户数据是否保留；
- 调试接口在开发机开放、工程样机受控、量产默认关闭或要求物理授权。

ESP32-S3 若被采用，应启用 Secure Boot v2、Flash Encryption、签名 OTA、双 OTA 槽和回滚确认。首次可信引导仍由有线或生产预烧录完成；OTA 不是无信任根的“无线烧录”。

## 更新分发

无互联网环境下，签名更新包可以通过手机、本地 Mac、USB 或其他 RadishLink 节点传播。传播节点不需要更新签名私钥，也不能修改包。设备在安装前验证：

1. 产品与硬件型号；
2. 签名链与撤销状态；
3. 版本和防回滚策略；
4. 完整性、大小和可用空间；
5. 电量与可回滚分区。

## 上线前安全门

- 形成版本化威胁模型和数据流图；
- 选定经过维护与审计的密码实现，不直接调用自制原语组合；
- 对解析器、消息状态机和附件分块执行模糊测试；
- 覆盖断电、存储损坏、nonce 状态回滚、重复包和分区合并；
- 独立复核配对、撤销、群组成员变更、升级与恢复流程；
- 明确公开的安全报告与响应渠道。
