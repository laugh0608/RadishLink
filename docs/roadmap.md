# RadishLink 路线图

本文给出阶段顺序和退出条件。时间仅为单人或小团队的工作量估算，不是发布日期承诺。

现有周数是早期工作量假设，不包含已确认的上游回复、专业评审或供货等待时长，不能直接相加得到交付日期。下一轮计划应按已关闭前置、可投入工时、等待项和返工风险重估；没有负责人和输入时不填写虚假截止日期。

项目成熟度使用 `D0/P0/P1/P2/E0`，软件、硬件和射频证据分别使用 `SW-*`、`HW-*` 和 `RF-*`；依赖图、当前 gate 与授权边界以[项目执行计划](status/project-execution-plan.md)为准。证据可以并行积累，但不能用局部探针跳过产品阶段退出条件。

## D0：定义与法规预检（1–2 周）

交付物：

- 产品、网络、安全、媒体、硬件和测试边界；
- 首个测试地区的书面法规核对结果；
- 三节点硬件验证路线、复用清单与采购上限；
- 计划优先的无射频软件方案、消息语义、安全候选和验证设计；
- 可重复软件环境的探索性证据，不把探针实现冻结为生产技术栈。

工作顺序：先完成 `PLAN-G0`，再按[D0/P0 软件工作计划](status/d0-t0-p0-plan.md)完成 `SW-G0..G3`，并按[低成本硬件验证计划](hardware/hardware-validation-plan.md)完成 `HW-G0/HW-G1`。已有 Docker 探针只提供环境可行性证据，不能跳过设计门。

退出条件：可以明确回答“在哪里、用哪个 SKU、哪根天线、什么功率和带宽进行测试”，并且软件计划、覆盖层消息语义、E2EE/身份路线、验证设计和硬件复用/采购门已有可审阅结论。未关闭时产品仍处于 D0，但经授权的软件或无射频硬件证据可以继续积累。

## P0：加密文字三节点闭环（2–4 周）

进入条件：D0 决策门与相应授权完成；不得以探索性探针代替正式消息、安全和测试设计。

范围：

- 节点身份、二维码配对和会话建立；
- 邻居发现、单中继路由、消息去重、TTL、确认和存储转发；
- 本地 Web 管理界面，Mac 和手机通过近距 Wi-Fi 使用；
- 链路中断、节点重启和重复包测试；
- `SW-V*` 确定性故障矩阵与 `HW1` 三台实体 Linux 纯有线台架；
- `HW2` 只为一台节点增加按键、显示和电源状态，另外两台可以 headless。

退出条件：A 与 C 无法直连时，消息稳定经 B 送达；B 只能观察必要路由元数据，不能读取内容；掉电、持久化、部署和 UI 失败状态具有可复核证据。P0 不要求先获得 HaLow 距离结果，但不能把有线台架外推为无线结论。

## P1：实时语音与链路自适应（3–6 周）

范围：

- Opus、抖动缓冲、丢包隐藏、拥塞反馈和优先队列；
- 一对一、单跳优先、最多一个中继；
- 10 分钟通话、切路和链路降级测试；
- 音频硬件与端到端时延分解；
- 在 `SW/HW` 台架先形成资源预算；真实无线数据只在对应 `RF-R*` gate 后进入结论。

退出条件：达到 `Talk` 层级目标，且文字在通话负载下仍可用。

## P2：受限视频与附件（4–8 周）

范围：

- 240p/360p、10–15 fps 的硬件编码；
- 码率自适应、关键帧请求、附件断点续传和配额；
- 五分钟视频通话及 15 秒视频片段；
- 明确视频不可用时退化为语音的状态机；
- 比较 2GB 以上 Linux SBC/SoM 的编码、存储、热和接口余量，不冻结量产 SoC。

退出条件：达到 `View` 层级目标，温升和功耗没有超过工程样机预算。

## E0：可携带工程样机（6–12 周）

范围：

- 冻结应用处理器、HaLow 模块、2.4 GHz/BLE、显示、音频、摄像头和电池；
- 设计载板、天线隔离、电源路径、散热和外壳；
- 签名 A/B 升级、恢复模式、设备锁和工厂初始化；
- 在法规与射频 gate 通过后开展三至十节点小规模外场。

退出条件：设备可放入日常背包或衣袋，能够独立完成文字与按键通话，并具备可测量的续航数据。

## 暂不进入的阶段

群组实时视频、大规模群组、精确定位、量产认证、公开销售和云端增值服务，均等待 E0 证据后单独立项，不提前制造空架构。

## 阶段顺序修订候选（待评审）

提出日期：2026-09-05。建议在 P0/P1 已形成文字、安全、语音和资源证据后，允许先评审文字/按键通话的可携带样机；P2 视频作为增强工作包单独通过，不让摄像头、编码器和视频吞吐成为首台文字/语音样机的隐含必要条件。

| 方案 | 收益 | 代价与必须保留的条件 |
| --- | --- | --- |
| 现行 `P0 → P1 → P2 → E0` | 一次覆盖全部首期媒体后再收敛硬件 | 首台可携带样机受视频、编码与热预算阻塞 |
| 候选：P0/P1 后先评审可携带文字/语音样机 | 更早验证独立操作、携带、充电和中继策略 | 必须明确样机能力标签、无视频硬件的扩展代价；安全、升级恢复、HW 与相应 RF 条件不能省略 |

接受候选前，需要所有者确认首个场景和视频必要性，重新评审 `PLAN-G0` 的依赖图、P1/P2/E0 进入退出条件、产品成功标准、硬件配置与媒体验收范围，并明确新旧里程碑的对应关系。本文不新建已生效的阶段编号，不把局部 Demo 重命名为 E0；现行顺序继续有效。

无论是否调整阶段顺序，软件、有线硬件和射频证据都可以按各自前置与授权积累。达到 P1/P2 的台架资源目标不等于已经达到 `Talk/View` 的外场距离目标。
