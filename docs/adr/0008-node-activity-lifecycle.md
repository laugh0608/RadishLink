# ADR 0008：Node 活动作用域与有界归档

- 状态：Accepted
- 日期：2026-10-28
- 接受者：项目所有者在本次会话明确回复“接受，实施”

## D17：旧事实保留与同 boot 新活动

接受[活动生命周期方案](../architecture/node-activity-lifecycle.md)的单库活动作用域、当前活动指针与旧控制归档。结束活动的身份、绑定、控制对象、邻居次数及关联历史保留，不恢复旧 Active 权限；业务消息保持原身份、core、密文、历史和去重。新活动使用新活动/参与者标识及新凭据，安全状态按 `(activity_id, session)` 隔离，旧版无法确定活动的 session 不猜测归属。旧界面动作代数退休，保留动作事实，新代数须显式绑定当前活动。

当前活动继续享有原 1 MiB / 576 记录预留。旧控制事实按实际记录计入原控制总额扣除此预留后的余额：上下文 4096 bytes、绑定 1024 bytes、对象 4096 bytes、邻居责任 512 bytes，每条占一个记录并计入全局记录额度。单旧活动的保守组合为 644096 bytes / 526 记录；在没有其他占用时，相应 4096-byte 业务证明容量上限从 1792 降至 1634。此组合不宣称可同时达到，也不代表物理磁盘预算。

容量不足拒绝新活动；本机停用不等待归档余额或远端任务，切换失败不恢复旧权限。首次不自动删除旧活动 marker、身份、去重或其他被引用数据腾空间，因此可切换次数有限。长期归档回收须另行核对引用闭包、可信保留时间与旧活动拒绝依据。

首次实施仅覆盖同 boot、旧活动已明确持久停用后的切换。旧等待项须显式丢弃，在途验证任务须返回或取消；真实 worker/channel/UI 的停止与 Join 仍由未来接入层完成。新活动从空绑定与空速率桶开始；新指针、旧归档、旧动作退休及新上下文在同一事务提交，提交结果未知时隔离拥有者，重开查询持久后继关系，不重复发放额度。

## 迁移与实施边界

采用显式 schema v8 迁移，普通 open 不自动迁移。已有活动须先由兼容旧版本的可信维护入口明确停用；迁移不自动停用活动或恢复旧会话/动作权限。兼容源版本、失败回滚、COMMIT 两侧退出及容量检查均须离线验证；未知版本和不完整关联拒绝。

本次授权 Node 自有边界与合成离线验证，不授权新密码依赖、真实用户数据迁移、跨 boot 解锁、自动回收或远程写入。ADR 0005 D9 的跨 boot 新活动方向保留，但须另行完成新写域、旧坐标与可信输入设计。许可证/R2、Phase B、真实配对/签验/平台、G1/G2、I5、HW/RF 停止线不变。
