# ADR 0006：Node 活动身份与控制证明 profile

- 状态：Accepted
- 日期：2026-10-24
- 接受者：项目所有者（本次会话明确接受 D11—D14）

## 背景

[ADR 0005](0005-node-security-integration.md) 接受两端 MLS、独立交付证明、分层撤销与冷启动隔离，尚需确定首次信任、用途分键及控制消息精确约束。所有者已审阅[身份与控制 profile](../security/node-identity-control-profile.md)和[依赖评审准备](../security/node-control-dependency-review.md)，接受以下方案及其代价。

## 决策

### D11：活动内逐对核验与用途分键

3–5 人活动入场前逐对双向核验完整公开绑定，共 3–10 对关系。每活动使用新的活动/参与者标识，独立生成 MLS 签名、交付证明及撤销控制三组键；以完整绑定的 SHA-256 引用关联身份。Node 或可信本地界面核对完整指纹；已授权手机可辅助扫码，但手机和相机不是独立运行前提。不授予队长代其他成员背书的权限。

MLS Basic credential identity 绑定 credential_ref，SigningIdentity 公钥必须匹配已核验的 MLS 键。首期以 ciphersuite 0x0001 为候选，不协商降级。新绑定 Pending，核验后 Active；换键重新配对并封禁旧引用，不凭昵称、地址或代数自动信任。冷启动后新活动重配，旧会话/责任保持隔离；接受该操作负担，不宣称透明续传、防克隆或完整防回滚。

### D12：严格 COSE_Control_V1 评审基线

接受专题中的 BindingV1、ReceiptV1、ControlV1 字段、用途与严格编码作为后续设计/实现评审基线：带 tag 18 的 COSE_Sign1、Ed25519 -19、固定 protected 头、空 unprotected、内嵌 payload、固定 external_aad 和 512-byte 对象上限；拒绝旧算法、歧义编码、额外字段和未知版本。现有 Node 4096-byte 控制预留不缩减。

签验使用本地已核验的用途公钥，kid 仅为提示；交付证明绑定原消息不可变核心和密文，不公开正文摘要。中继可见活动内标识、消息关联与交付事实，这一隐私代价已接受。

数据 envelope、MLS AAD 映射、控制传播预算及真实互操作向量仍须补齐；接受基线不等于完整运行协议已冻结、密码实现已通过或所有后续数值已接受。

### D13：本机封禁与已认证自身退出

本机所有者可封禁目标凭据。已认证且 issuer/target 完全相同的自身退出自动封禁这一凭据；他人遗失报告仅提示，由接收方本机所有者决定。没有远程允许、自动换键或队长代他人退出类型。封禁不能由迟到消息撤回。

接受控制键泄露可能导致该身份退出的可用性代价；不因此授予撤销其他成员的权力。分区中无法即时全队生效，重新连通先处理已收到的有效撤销。已验证的原始自身退出对象可在其 issuer 被封禁后继续受限转发，仅此例外，不恢复普通业务或 receipt 权限。

### D14：候选依赖评审方向

优先评审 coset 0.4.2、ciborium 0.2.2 与既有 aws-lc-rs 1.16.3 候选；沿用 mls-rs 0.56.0 / mls-rs-crypto-awslc 0.25.0 方向。产品图依 D6 不引入旧 SQLite provider。新图必须独立固定来源、版本、feature、native links、许可证/NOTICE 与 advisory；旧 94-package PASS 不继承。

严格解码、分配前资源限制、用途授权、错误传播与联合事务由实际候选验证；无法满足时重新评审，不自行重写密码算法或用宽松 fallback 放行。

## 授权与后续

本次明确授权固化文档和 ADR 并提交，再补齐数据 envelope、控制传播预算和新依赖图精确评审包；后续未接受的新取舍集中列出。设计准备可读取公开标准和既有源码、计算静态预算，不执行依赖下载/解析/安装、候选构建/签验、设备/VM/网络实验或远程写入。

许可证/R2、Phase B、SW-G2、I5、HW/RF 停止线保持不变。独立安全/许可证意见、实际图与平台证据不能由本 ADR 替代。后续协议设计或执行包仅在其明确范围内另行接受，不能通过修改历史 spike/合同追认通过。
