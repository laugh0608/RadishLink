# ADR 0004：Node 服务、事务与本地数据基线

- 状态：Accepted
- 日期：2026-10-24
- 接受者：项目所有者（本次会话明确接受 D1—D5）

## 背景

项目已接受 Node 持有身份、会话与历史、手机作为可断开界面的职责。已有 Go 合成验证实现，但尚无产品服务。正式消息路径需要保证安全状态、消息、去重与传输责任共同提交，不能把测试身份、文件快照或跨库补偿作为产品安全能力。

完整比较与工程细化见 [Node 服务设计](../architecture/node-service-design.md)。本 ADR 只记录所有者已接受的五项决定及其影响，不把其他候选机制一并接受。

## 决策

### D1：Rust 产品服务

产品 Node 使用 Rust；已有 Go 工具保留验证职责。调度算法按规范与测试向量移植并独立核对，不通过产品中的 Go 子进程复用。首期一个 Cargo package，模块按应用、消息、安全会话、存储和 I/O 职责划分，避免提前拆分空框架。

这减少了与当前 Rust 安全候选的跨语言集成，但不等于选择或批准 mls-rs；候选变化时重新评估集成。

### D2：单进程与单库事务

采用模块化单进程、明确的状态提交者和 SQLite 单库事务。网络 I/O 可并发，消息和安全状态的持久变更串行化。首期采用 DELETE journal 与 EXTRA synchronous，并验证设置生效。

发送、接收、去重、证据责任及相应安全状态必须处于同一事务，或在重新评审后采用有证明的等价方案。当前不接受双库补偿。密码库若不能参与所需提交边界，停止接入并报告差距；SQLite provider 名称不构成原子性证明。

### D3：加密数据卷与显式解锁

Linux 数据使用 LUKS2 加密卷方向，冷启动需要在设备本机解锁。Node 进程不承担块设备管理权限；手机离开不锁定已解锁设备。完全锁定设备时暂停端点和中继服务，关闭敏感状态与数据卷；关闭失败不能宣告锁定成功。

首期不承诺无人值守冷启动恢复，不把自动解锁密钥与数据一起保存在卡上。加密卷不代替可信启动、防回滚、swap/core dump 防护及物理掉电验证。

### D4：P0 Web 的受控开发 CA

P0 本地 Web 使用受控开发 CA，在明确指定的测试手机/Mac 上安装信任。CA 私钥留在受控签发端，Node 使用各自证书；浏览器仍须正常验证证书与名称。设备身份、界面授权与撤销另行验证，不以 Wi-Fi 或 HTTPS 连接成功代替授权。

安装会扩大测试终端的信任范围，测试结束后撤销。当前接受设计方向，实际证书签发、安装和系统配置仍需精确操作授权。

### D5：历史保留

用户可见历史默认保留 7 天，到期自动删除；容量不足时明确提示，不提前静默删除未到期历史。历史清理与传输副本、去重 marker、证据返回责任分别管理；不能为清理历史而删除仍必要的安全/协议状态，也不承诺闪存物理擦除。

到期依赖可证明的时间条件；时间不确定时不能猜测到期或延长消息传输寿命。具体容量和保留时钟的实现仍须覆盖失败与恢复。

## 结果与取舍

- 增加 Rust 移植、构建和依赖维护工作；Go 既有证据保留，不重新解释为产品结果。
- 单进程故障会影响整个 Node，需要完整恢复和有界监督；短文字阶段不以增加进程来回避事务问题。
- 冷启动需人工解锁，完全锁定期间不能中继；固定无人值守中继的硬件密钥路线另行评审。
- P0 测试网页需证书准备，不承诺普通用户免设置使用；长期产品接入体验仍需改进。
- 7 天后历史不可继续查询；网络去重和确认责任按自己的安全窗口保留。

## 接受边界与后续

所有者同时要求提交方案/ADR 后推进第一批服务与事务基础开发。该批包括工程配置、错误和生命周期、纯消息模型与调度、SQLite 事务/恢复、应用命令/查询及离线故障测试。依赖精确差量、文件范围和验证方法记录在实施文档中，使用已有工具链时优先离线验证。

这不授权依赖安装、密码候选 Phase B、采购、CA/加密卷实际操作、设备/虚拟机启动、网络实验或远程写入；既有 R2、SW-G2、I5 和 HW/RF 条件继续适用。正式密码机制、wire 字节格式、依赖完整图、生产容量及物理安全能力尚未因此接受。

若实现发现联合事务、可信时间或安全恢复无法满足既有消息语义，应重新打开相应设计，而不是默认成功或绕过停止线。本 ADR 的接受不代表服务已经实现或产品阶段已经通过。
