# ADR 0007：Node 数据 envelope 与控制传播预算

- 状态：Accepted
- 日期：2026-10-24
- 接受者：项目所有者（本次会话明确接受 D15、D16）

## 背景

[ADR 0006](0006-node-identity-and-control-profile.md) 已接受活动身份、COSE 控制 profile 和撤销权限。所有者随后审阅[数据 envelope](../protocol/node-data-envelope.md)、[控制传播预算](../protocol/node-control-propagation.md)及[新图精确评审包](../testing/node-security-graph-review-package.md)，接受以下公共格式、时间准入与容量代价。

## D15：数据 envelope 与保守寿命

接受专题定义的 CoreV1/DataFrameV1 固定字段和严格类型、长度、版本规则；MLS authenticated_data 精确等于原始 core bytes，随后对完整 MLSMessage 与 core 的有界封装计算 message_binding，避免循环摘要。目标端须核对实际 sender/group/epoch/AAD；中继的可见摘要校验不等于 origin 认证。

短文字默认/最长寿命为 60 分钟；平台必须提供宽度不超过 2000 ms 的可信 UTC 区间及同 boot 单调时间。起点用可信时间下界，接收/提交/输出用上界保守判断；deadline 和剩余预算不得延长。没有可信时间输入则拒绝，不假设普通墙钟/NTP 或邻居时间可信，不改写冷启动隔离。

正文当前上限仍为 4096 UTF-8 bytes；完整应用 frame 上限 65536 bytes，MLSMessage 上限 61440 bytes。每个已核验邻居最多一个接收 frame、总计最多四个，完整组装最多 10 秒，超限拒绝。接受公开活动内 group/epoch/时间元数据和慢帧丢弃的代价；60 分钟不构成送达或持续重试保证。

## D16：活动与控制传播有界

每 Node 同时一个可通信活动，最长 12 小时；最多 5 人，每人最多 4 个已核验凭据代数。活动、代数、封禁记录与尝试次数不得由重连/重试/进程重开重置；超限须停止新准入或明确结束活动并重新配对。

最多 20 个自身退出与 80 个他人报告对象；按固定目标/报告者槽合并，不因新 operation_id、reason 或报告者换键增殖。每对象最多向四个邻居分别尝试十次，使用专题的八个常规时槽及两次有间隔的恢复机会；消费尝试后才输出，失败不返还。逐跳确认只终结相应邻居责任，不冒充全队撤销或目的端交付。

从现有 8 MiB / 4096 控制记录中固定保留 1 MiB / 576 记录用于身份与撤销，不提高总额，不挤掉已承诺责任。接受业务证明容量按字节计算的理论上限降至 1792 条；新活动或迁移空间不足必须拒绝，不能提前删除现有责任。逻辑计费不等于物理磁盘隔离。

接受专题的入站限速、16 对象验签等待上限及外发控制总上限 4 frames/s、8192 bytes/s（各同值 burst）；限速重建不补额度。本机所有者封禁不被远端排队阻塞。本机退出先持久 Retiring/唯一意图，再完成固定控制签署与封禁/传播提交，失败不恢复 Active；真实签署仍等待安全前置。

## 实施与执行边界

本次明确授权先固化文档/ADR 并提交，再推进不受现有停止线阻塞的开发与验证、补齐新依赖图执行前置。可以使用现有工具链/依赖实施 Node 自有的非密码边界与离线准备工具，并以合成数据验证；不自制 CBOR/COSE 密码实现，不用假验签放行真实入口。

新图 G1/G2 的命令合同已准备，但真实硬写入域、网络/进程监督环境与单次执行授权仍未满足。不得解析/下载新依赖、安装、构建或运行密码候选，不启动 VM/设备/网络实验，不修改系统或远程状态。许可证/R2、Phase B、SW-G2、I5、HW/RF 等停止线保持不变。

本 ADR 不接受未来新增的安全或资源降级方案。真实平台能力、合格复核意见、完整依赖图和实际故障/互操作证据仍需分别取得；无法在当前环境关闭的前置必须明确报告。
