# ADR 0009：Node 跨 boot 时钟域与新活动

- 状态：Accepted
- 日期：2026-11-02
- 接受者：项目所有者明确选择“接受四项选择并实施（推荐）”

## D18：显式时钟域、隔离与全新活动

接受[活动生命周期方案](../architecture/node-activity-lifecycle.md)中四项选择及 Node 自有边界的合成离线实施范围：

1. 单 SQLite 库增加时钟域，当前写域与活动共同限定权限；旧域冻结，旧单调时间、消息寿命及安全状态不转换到新 boot，不透明续传。UTC、boot 与状态新鲜性仍须真实可信平台单独证明。
2. 先持久隔离旧域，再在一个事务中建立新域和新活动。隔离不以新身份、可信新 UTC 或归档余额为前置；后一步失败保留隔离，不伪造退出证明或旧活动结束时刻。重复请求绑定完整参数，仅返回已提交事实，不返还权限、寿命或额度。
3. 每域按 4096 bytes / 1 记录计费；当前域占原 1 MiB / 576 记录预留，旧域进入原 8 MiB 控制总额的业务余额和全局记录额度。没有旧活动也计域费用，旧域只计一次。首批不新增自动归档回收，容量不足拒绝新活动；D5 的可信到期历史清理不变。
4. 采用显式 schema v9 迁移，普通 open 不自动迁移。v8 冷启动使用明确的迁移并隔离请求；v1..v7 的原兼容链、同 boot 与停用前置不放宽。旧格式的缺失身份/安全映射不猜测，未知版本、损坏、配额不足与失败均拒绝或隔离。

新活动使用新活动/参与者标识和重新核验的凭据，不继承旧绑定、session、UI 动作或 job。新域建立要求可信新 UTC 满足原 D15 约束及保留端点不回退；无可信时间可保持隔离，不能建立业务写域。跨 boot 的历史后继关系不用单调时间数值比较。

## 实施与结论边界

实施须将 schema、全部相关查询、显式迁移、两步事务、计费与合成故障矩阵作为完整切片；部分字段/helper 不作为能力完成。普通 Service/CLI 不增加用户恢复入口，生产 run 继续拒绝。使用已有工具链和依赖，不修改 manifest/lock，不生成真实密码材料。

本次接受不授权 Git 提交/push、新依赖、真实密码/Phase B、网络、设备/VM、真实数据迁移或平台操作。许可证/R2、SW-G2、G1/G2、I5、HW/RF 停止线保持；离线结果不证明端到端安全、物理掉电、完整防回滚或真实平台成立。

2026-11-02 实施与验证交接后，所有者另行明确要求“提交工作区更改，继续推进下一步”，本地 Git 提交由该要求单独授权；不包含 push 或其他远程写入。
