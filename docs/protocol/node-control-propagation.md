# Node 控制传播与预算

更新日期：2026-10-28。状态：**D16 已由 [ADR 0007](../adr/0007-node-envelope-and-control-budget.md) 接受；内部持久与预算已有限离线验证，完整接线与运行仍待验证**。面向 Node 队列、身份与安全评审者，细化 [ADR 0006 D13](../adr/0006-node-identity-and-control-profile.md) 已接受的权限，不新增队长授权或远程解除封禁。预算为 Node 应用逻辑上限，不是 SQLite/文件系统/整机物理资源证明，也不是 I5 的预算。

## 三类责任分开

| 对象 | 寿命与终结 | 权限 |
| --- | --- | --- |
| 交付 receipt（COSE kind 1） | 原消息 deadline，沿已持久返回邻接；重复不重置预算 | 预期目标 receipt key；仅此类可触发交付事实与 T-D |
| 自身退出（kind 2） | 当前活动内保留封禁事实；有界向活动内可信邻居传播，活动结束停止输出 | issuer 等于 target，使用 control key；自动封禁自身凭据 |
| 他人遗失报告（kind 3） | 当前活动内提示/去重；本机确认决定是否封禁 | 当前可信 issuer 的 control key；签名不赋予替人封禁权 |

手机授权撤销是本机权限操作，不能包装成 kind 2/3。控制接收/转发成功不代表全队已撤销。分区、恶意阻断或次数耗尽都可能使其他成员未收到。

## D16：活动、代数与保留上限

推荐每个 Node 同时仅一个可通信活动，活动自本机明确启动起最多 **12 小时**（同 boot 保守计时），覆盖既定 6–8 小时场景并留准备余量。活动截止只可提前；网络重连、报告或对端自报开始时间不重置。成员最多 5 个，每个 participant 最多 **4 个已核验凭据代数**（首个加 3 次替换）；超过则停止新绑定，需所有者结束旧活动并重新配对。

对同一 participant 的历史代数不复用、不删除后再占位；非连续的 credential_generation 可以拒绝并要求核验，不能只凭整数更大激活。最多 20 条已核验绑定，另有每 participant 1 条 Pending 临时绑定（共 5），不自动为陌生 ID 建库。当前 Active 总数仍最多 5；新活动不自动继承旧信任。

封禁、退出、报告与重试耗尽 marker 保留到本机活动停用；此后任何该 activity_id 输入都不进入业务。业务历史继续按既有保留规则，只作只读事实；停止活动不自动删除受保护历史，也不解除 D9 的冷启动隔离。

## 有界去重与存储槽

1. 每条已核验 credential_ref 最多一个自身退出对象，共 20 个专用槽。收到不同 operation_id 的再次退出只合并为同一封禁，不分配第二个对象。
2. 他人报告按 `(活动, reporter participant_id, target_credential_ref)` 最多一个槽；每个目标最多来自其他 4 人，共 `20 × 4 = 80` 个槽。报告者换键、换 reason 或 operation_id 都不能新增该槽或重新提醒；保留首个有效报告及其已核验 issuer 凭据。需要再次表达意见通过本机人工操作，不制造新网络责任。
3. `(活动, issuer_credential_ref, operation_id)` 仍执行 D12 的相同载荷幂等、不同载荷 conflict；有效保留对象上限 100 个。已占目标槽的新 operation_id 不创建记录、不重开计时，按重复/已合并处理；不为了记住所有恶意 ID 建无限 tombstone。
4. 每对象最多 4 个按邻居 participant_id 固定的转发状态，总计 400；邻居换凭据、重连或换地址不返还尝试次数。回发给入站邻居通常不必要，预算仍按最多 4 份保守预留。

本机封禁落在预留的绑定/政策状态中，不要求队列还有业务空间。报告槽耗尽不占自身退出槽，后者耗尽也不能阻止本机所有者停用整个活动。若底层存储不能持久提交封禁，停止相关业务并报告持久化失败，不能向用户谎称已持久撤销。

## 一 MiB 安全控制保留区

建议从现有 **8 MiB / 4096 控制记录**总额度中固定保留 **1 MiB / 576 记录**用于身份及撤销传播，不提高默认总额、不借用已有业务责任的预留。

| 子项 | 记录上限 | 每记录逻辑计费 | 合计 |
| --- | ---: | ---: | ---: |
| 已核验与 Pending 绑定 | 25 | 1024 bytes | 25600 bytes |
| 退出/报告原始对象及状态 | 100 | 4096 bytes | 409600 bytes |
| 四邻居转发状态 | 400 | 512 bytes | 204800 bytes |
| 活动/政策/计数等固定辅助记录 | 51 | 4096 bytes | 208896 bytes |
| 合计 | 576 | — | **848896 bytes** |

剩余 199680 bytes 是同一保留区内的逻辑余量，不外借。原始 COSE 对象上限仍为 512 bytes；较大计费用于元数据与责任，不代表可以接收更长 wire。配对时为最多 20 个历史绑定及其退出槽预留，报告不能挤掉它们。

业务证明意图/返回责任继续每条计费 4096 bytes；预留 1 MiB 后，其字节维度的理论上限从 2048 降为 **1792 条**，实际还受其他已占控制额度、记录和 payload 限制。payload_count 的 2048 上限不自动降低配置值，但可能先撞控制准入门。这是 D16 已接受的容量代价，不能暗中缩减已 custody 的责任。

新活动准入前必须确保完整保留区可用；旧 v3 库若已承诺过多责任，拒绝迁移/新活动或等其正常终结，不强制淘汰来凑空间。2026-10-28 已实施 schema v4 显式迁移，覆盖崩溃、配额不足和错误来源拒绝；config 仍为 v1，低于完整预留的容量不能创建或迁移 v4，详见[实施记录](../testing/node-control-persistence.md)。

上述字节不覆盖 SQLite 索引页、journal、文件系统、传输栈或密码库内存。未来平台包必须统一核算物理上限与拒绝行为；不能把逻辑计费结果写成已具备 1 MiB 磁盘硬隔离。

## 转发、限速与次数

对象的首次本机接纳时刻、原始 bytes、授权上下文和全部已消费额度一起持久化。同一活动内每对象向每个邻居最多 **10 次发送尝试**：

- 8 个常规时槽：从首次可调度时刻起 `0、1、3、10、30、120、600、1800` 秒；错过/断链的槽按已消费跳过，不积攒一串补发。
- 最多 2 次链路从 Down 变 Up 的恢复机会；两次至少间隔 60 秒；若与常规槽同批发生，只产生一个尝试并按一次恢复机会已使用处理。
- 重复输入、重启同 boot 进程、邻居换地址/凭据、链路抖动和队列重建均不能重置起算点或次数。新 boot 不恢复活动输出。
- 每次尝试在持久消费额度后才写传输；写失败或提交后崩溃不返还次数。活动到期、策略封禁通道、对方有效持久确认或次数耗尽后停止该转发状态。marker 保留，不能删除队列后用重复输入重建额度。

最多 `100 × 4 × 10 = 4000` 次控制对象发送，每次最大完整应用 frame 522 bytes，共不超过 **2088000 bytes/活动/Node**，只计算 kind 2/3 对象本体及应用 framing，不含链路头、握手、对方 ACK、外部重传或数据 receipt。不能将这个数当作整机总流量。

候选接纳限速：每个已核验邻居每秒 1 个新 kind 2/3 对象、burst 2；全局每秒 4 个、burst 4。验签等待队列最多 16 个 512-byte 对象；超出丢弃，不落盘/回显。陌生邻居在此之前拒绝。已保存原始对象的 byte-identical 重复可复用已验证结论，但仍受入站速率限制。

候选外发控制总预算（含 kind 2/3、receipt 和下节 ACK）：每秒最多 4 frames，burst 4，同时每秒最多 8192 bytes，burst 8192。按不同责任轮转，优先处理已验证退出，再考虑报告与 ACK；全局上限不因消息自报 priority 提升。数据发送使用独立数据预算，控制不能无限占满发送循环。此速率是本稿评审值，不宣称链路吞吐或 QoS 已验证。

全局/邻居限速状态不能在重连或进程重开时恢复满桶；可持久恢复保守余额，或以空桶和当前同 boot 时间重新开始，不能补发停机期间的历史额度。持久尝试次数与活动截止独立于 token bucket，限速器重建也不重置它们。

限速只影响网络传播；本机所有者封禁直接进入状态线程，不被远程队列耗尽阻止。已完整收到且验权有效的退出先于受影响业务提交/输出。调度器不能为了公平继续使用已经撤销的权限。

## 逐跳确认与消息类型

复用[数据 envelope](node-data-envelope.md#线格式与界限)的长度前缀与版本。COSE 控制体为固定 array `[1, 2, cose_bytes]`，cose_bytes 为 1..512-byte bstr；完整 frame 最多 **522 bytes**。它承载 D12 kind 1/2/3，帧 kind 2 不等于 COSE 自身 kind 2。

逐跳确认使用固定七项 array：

```text
LinkAckV1 = [1, 3, activity_id, ack_kind, object_ref,
             custodian_id, custodian_credential_ref]
```

活动/对象引用/凭据引用分别为 32-byte bstr，custodian_id 为 16-byte bstr。ack_kind 只允许 1（数据 custody）或 2（控制对象持久接纳）。完整 frame 为 **127 bytes**。不带独立 COSE 签名，真实性只来自已认证逐跳通道；custodian 必须等于该通道绑定的邻居，未知/过期/已撤销绑定拒绝。

- 数据 object_ref 等于 message_binding；只使对应邻居的数据重试暂停，不释放唯一 payload、不创建交付事实。
- 控制 object_ref 为 `SHA-256(原始、严格编码的 COSE payload bytes)`，按语义对象绑定，不用可变传输头或签名字节作为新对象键。只终结向该邻居的传播责任，不代表其他邻居已收到，也不是全队撤销证明。
- 只有对象、去重状态、权限效果/待确认报告与继续转发责任原子持久成功后才发 ACK。单纯验签、入内存、写 socket 不够。
- 未知 object_ref 或没有对应本机责任的 ACK 不新建状态。每个已持久对象/数据责任向每个邻居最多发 10 次 ACK，受总速率和活动/消息 deadline 限制；重复请求不能形成无限 ACK 响应。预算需持久，不能重连重置。

关闭或撤销后的通道不得为 ACK 恢复普通授权；ACK 发不出可以由上游用完有界尝试，不以“必须回 ACK”为由绕过撤销。唯一特殊转发权限仍是 D13 已验证的原始自身退出对象。

## 本机退出与并发一致性

本机所有者发起退出时先提交唯一的退出意图并进入只允许该意图的 Retiring 状态，立即阻止普通业务。随后使用已选 control key 对固定载荷签署，原子提交 SignedExit/封禁事实及预留转发责任；失败保持 Retiring 和意图，不能恢复 Active。只有这一意图可使用退休键签署，不能提供任意载荷签名接口；跨 boot 仍隔离。2026-10-28 已离线实现固定意图、Retiring 与退出对象/封禁/责任原子提交；真实签署及业务统一授权门仍是后续验收要求。

收到他人的自身退出，验签与事务内权限复核通过后，一次提交封禁及原始对象的传播责任，再取消受影响业务/证明输出。后续只能转发已经验证的相同原始对象，不能重新签署或加工。已有交付历史不改为未交付。

所有对象只向本活动最多 4 个可信邻居有界转发；五成员范围内的控制扩散不赋予业务数据超过一个中继的路由权限。封禁其他人只改变本机政策；向外报告仍遵守 kind 3 无越权语义。
