## 已实现行为

在既有 Store 单拥有者和原子事务中增加 `business_policy.rs`，未新建身份库、服务、网络入口或依赖。T-A/B/C 的调用方必须提供验证准备时的 `expected_policy_revision`；事务内检查当前活动、两端 participant/credential 精确映射、Active 状态、本机角色及已核验邻居，再推进安全状态和业务记录。`business_policy_revision` 只是本机政策坐标，不是 MLS epoch、手机授权代数、全队时间戳或单独的授权许可。

| 责任 / 事件 | 当前内部行为 |
| --- | --- |
| 身份与邻居 | origin 必须为本机起点、destination 必须为本机终点、relay 不得冒充任一端点；新业务 neighbor/source_neighbor 采用精确 credential_ref 的 64 位小写十六进制，禁止昵称、地址或其他别名。真正逐跳通道认证仍由未来接入层提供 |
| 本机凭据 | 每条新消息持久记录本机当时的 Active credential；本机换代后不能借新凭据继续旧责任 |
| 政策修订 | 激活/替换绑定、封禁、Retiring、已验证自身退出、活动缩短或停用在同事务更新专用有界修订；准备时版本不符，拒绝新业务/证明提交，不推进合成安全状态 |
| 关联停止 | 活动、端点、本机凭据、来源邻居或已建队邻居失效，原子置 `policy_stopped`；标记不反转，重连、换代、重复接收或重开均不恢复责任或返还 retry 次数。来源/已选下一邻居失效会停止整条消息责任，不自动换路继续 |
| 证明 | 已提交意图返回当前政策修订；签署完成后入队和 T-D 再核对修订与当前权限。签署前后发生撤销/换代或其他政策变化时拒绝旧结果；不能用自报签署时间绕过 |
| 调度与输出 | 数据/证明队列决定、custody、转发建队均查当前权限；`validate_business_output` 可在未来串行交接处复查精确队列、凭据、修订与时间。它不发送 bytes，也不是一次性或可重放的发送令牌 |
| 控制例外 | 报告只提示，不封禁业务；持久封禁后仅允许转发原始已验证的自身退出对象。本机 Retiring 不允许普通业务、receipt 或 ACK 借道恢复权限 |
| 事实与清理 | `MessageView.policy_stopped` 区分业务事实与当前权限；保留 payload 至原到期规则、历史、去重及重试记录，已交付事实不改写。停止后的 proof/intent 各批最多清理 256 条，剩余项也不能输出；relay 唯一 payload 的既有预留仍至原生命周期终结 |
| 写失败 | 政策事务出现存储失败/提交未知或修订耗尽，当前拥有者隔离并拒绝继续输出；不把回滚后的旧 Active 状态当作继续运行许可。重开只恢复实际持久结果；失败的封禁须由可信调用方重新处理，不能报告已持久成功 |

事务中的权限检查使用现有可信 Clock 输入；原 UTC 区间、同 boot deadline、未知提交隔离保持。平台新鲜采样、签验结果与通道的可信绑定、已收到退出先于业务的真实输入调度、实际 I/O 交接及在途 bytes 边界仍待接入。当前只证明内部调用按上述检查拒绝；生产 run 仍停止。

## schema v6 与迁移

新增 `migration_v6.sql`：control_activity 保存 policy_revision，messages 保存准入修订、本机凭据和不可反转的停止标记。计入已有活动/消息逻辑记录，D16 的 1 MiB/576 记录预留、业务原总额度及 config/retry 版本不变；没有新增可无限分配的映射表。

新库为 v6；普通 open 对 v1..v5 返回 `MigrationRequired`，按来源显式调用 `migrate_v1/v2/v3/v4/v5`。旧 SQL 不改，升级在单事务中完成，错误源版本、跨 boot、损坏、容量不足及存储失败不获放行。

v5 及更早消息没有本批的可信政策/本机凭据快照；迁移保留原 core、业务事实、队列及预算，标记停止，不从既有别名或收到的新帧推导授权。其输出/证明继续返回 `UnsupportedVersion`，不提供原地补齐并复活的接口。原有控制绑定可用于显式准备新消息；新政策计数从 0 起，不能把它解释成旧验证结果仍有效。旧责任不因本批政策清理提前删除，仍由其原到期维护处理。
