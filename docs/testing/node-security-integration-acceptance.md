| 场景 | 输入与故障位置 | 重开时核对 |

## 实际安全用例

下表是后续实现的验收输入。用三套独立状态运行 A、B、C，只有 A/C 是被测 MLS 会话成员。两端无直达路径，经 B 走 A–B–C；B 仍具有本活动的已确认公开绑定及有效的逐跳凭据。每个拒绝分支从同一合成基线独立开始，只改变表中指出的输入或事件顺序。候选门满足后，用获评审库生成一次基线向量并记录公开输入摘要、产物 revision 和库图，按固定配方生成变体。私钥只在获准试验隔离环境内生成和使用；输出保留阶段、原因、计数和可复核的公开对象标识。

| 用例 | 输入与执行顺序 | 判定点与预期结果 |
| --- | --- | --- |
| SEC-01 首次信任与换键 | 在两端录入当前活动的完整 `BindingV1`，先尝试用 Pending 绑定建立会话，再由双方可信本地入口核对完整指纹并确认。分别提交同名/同地址的替代包、更高代数但未核验的绑定、MLS Basic identity 匹配但签名公钥不匹配的 KeyPackage | 只有双向核验后的精确映射可进入 Active，MLS identity 和签名公钥都匹配。替换经新核验后在同一事务封禁旧引用并启用新引用。无未授权会话、队列或历史；重开不恢复旧引用。对应 Store 的 `stage_control_binding`、`activate_control_binding` 和候选 IdentityProvider |
| SEC-02 界面授权与通信撤销 | 手机未授权时尝试辅助确认；授权后将旧响应停在交付前，先提交本机界面撤销再放行。另将收到的遗失报告、代他人退出、有效自身退出分别置于重连后的业务前 | 无授权手机不能确认；撤销后旧响应未开始写入，连接关闭，Node 会话可继续。报告只提示、代退出拒绝、有效自身退出封禁精确凭据。暂停旧凭据的已验证业务，撤销后恢复执行须在提交或输出复核处拒绝，既有历史保留 |
| SEC-03 严格解码与用途签验 | 用 C 的 receipt key 和原始 core/密文生成符合 profile 的 `ReceiptV1`。逐次变更 tag 18、`alg=-19`、protected 编码、空 unprotected、内嵌 payload、固定 external AAD、版本或尾随字节。用库对可签的格式负例分别重新签署；另检查 512 / 513 bytes 的分配前长度门和 4 / 5 层深度门 | 记录最先拒绝的解码、签验或授权阶段。超限在分配前拒绝，达到上限仍须通过其余检查。原始 protected/payload bytes 进入实际签验；用正确 kid 配错误键、自带公钥、C 的 control key 或 B 的 key 签署均不得通过。任何负例都不得进入 T-D |
| SEC-04 送达证明与重放 | B 在无 A/C 私聊状态时接收正常密文，另尝试用 B 自己的独立会话状态处理同一密文。C 完成 T-C 后签署；另用 C 的 receipt key 分别签署错活动、错消息身份、错目标凭据和由单字节变动的 core 或密文计算出错误摘要的变体。B 先接收各变体，再接收合法证明，提交后重交同一证明 | C 有一条持久交付记录；B 的私聊解密失败且只持必要公开元数据与密文，仍可按 C 的可信 receipt key 验证合法证明。各变体不得清理密文或改变返回责任；合法 T-D 与原上游返回责任同提交，重复不恢复队列预算。截止点恰好到达、过后或验证后撤销均禁止清理和新输出 |
| SEC-05 联合事务与不确定提交 | 在 T-A 和涉及真实变化的 T-C 中分别注入 group snapshot、epoch 记录、KeyPackage 消费（建组/加入场景）及各应用写点失败。对 COMMIT 两侧退出及提交结果未知分别保留故障记录。另尝试跨线程、跨操作代数、重入及事务结束后回调 | 只有 Node 拥有连接和提交权。失败前后一并核对 group、epoch、KeyPackage 及应用记录、队列和意图；失效回调拒绝且无独立提交。失败或不确定后丢弃推进过的内存对象；隔离输出，重开按动作/消息键核对完整结果。T-C 提交前无展示、签署或 ACK，T-D 提交前无清理成功和上游证明发送 |
| SEC-06 恢复与时间边界 | 同 boot 重开后重交已提交消息或证明；分别制造未知 UTC、时钟回退与新 boot，尝试旧会话、旧活动绑定或历史副本恢复 | 同 boot 只以当前可信坐标、原截止时间及授权核对恢复，去重与预算不重置。时钟失信或新 boot 隔离旧工作，历史事实保留。新活动须重新可信配对；冷启动测试不提供防回滚结论 |

实际实现前需 [SW-G2 许可证补证与 R2、Phase B 精确合同](../security/e2ee-sw-g2-decision-package.md)、[Node 新图 G1/G2](node-security-graph-review-package.md)及目标环境的独立前置和授权。记录哪个用例依赖具体候选，签验、解析、traits 或可信界面能力不满足时回到相应边界评审。当前以上六项未执行。

## Linux ARM64 接线准入

本清单是[有界入站设计](../architecture/node-bounded-ingress.md#验收输入和平台前置)的验收记录要求。现有目标定位为 Radxa ZERO 3E 2GB 三节点有线 HW1 候选、`rsdk-b1` 的 `radxa-zero3_bookworm_kde_b1.output_512.img.xz`（asset 272946966）、内核 `6.1.84-10-rk2410-nocsf`。[BSP 记录](../hardware/hardware-validation-plan.md#镜像与接口版本证据2026-10-24)里的发布者摘要是后续核对输入。HW1 与 [I5 宿主资源门](sw-g4-synthetic-i5-linux-host-assessment.md)是两套独立环境。

| 检查项 | 进入实际验证前绑定的输入 | 实际证据与通过条件 | 当前判定 |
| --- | --- | --- | --- |
| 台架、镜像与进程 | HW-G0/G1 审阅记录、可用 A/B/C 节点与两条独立有线边、精确资产来源、镜像校验/维护范围、内核配置、非 root 身份及磁盘范围 | 镜像本体核验、各节点实际镜像/内核与接口清单、服务权限、A/C 无直达及有效串口救援记录；预算未批准或来源不清即停在采购/执行之前 | 只有版本与 BSP 纸面证据；无台架，镜像本体未核验 |
| 握手与 I/O 上限 | 逐跳库和版本、双向认证映射、精确连接实例、每阶段 FD/任务/连接和字节配额的执行点，含 TLS 与内核缓冲 | 分别压满握手、待登记、四个 framing 槽和下游；记录各域峰值、满额处拒绝、读 credit 与实际消费量。连续可读、半帧或超读时单步工作有界，不提前读下一帧、不旁路排队，未持久接纳则不回 ACK | 有应用 framing 合成证据；未固定适配层，传输资源无实测 |
| 可信时间、停止与维护时限 | 可核验 boot 来源、同 boot 时钟与可信 UTC 区间来源和误差；明确每个单步/轮转及停止时限和观测点 | 休眠、回退、半帧沉默和持续可读下，用可信坐标记录从读前、读后到期检查到撤销/停止受理的时间。验证 9999 / 10000 / 10001 ms 组装边界；达到 deadline 或失信时无迟到提交/输出 | 只有手动 Clock 和逻辑期限；平台输入和最坏单步证据均缺 |
| 原连接关闭与回收 | 适配层明确关闭确认条件、原实例标识、可取消步骤、关闭及真实 worker Join 的硬时限 | 同凭据重连、迟到回调、EOF、阻塞及关闭失败分开记录；未确认前旧实例计费且不开放替代实例。确认必须证明本地句柄及回调已收束，随后才能归还登记额度。正常关停须核对全部通道、短写、租约、Join 与 SQLite/锁释放 | 有逻辑关闭与停机测试；实际 I/O 和 Join 证据均缺 |

实际记录须附 revision、环境和配额、触发点、单调时间线、状态/计数、退出码、未回收资源及归还方式。由所有者分别确认台架和运行授权，维护者核对适配与资源合同，评审者逐项复核证据；当前无可提交实际接线评审的完整证据。失败停在对应入口，保留原因与未归还资源，隔离该运行根，清理仅限后续执行包批准的精确对象。预算、镜像、可信时间和关闭缺口仍阻止真实接线，本清单不授权采购、刷写、启动、安装或候选执行。
