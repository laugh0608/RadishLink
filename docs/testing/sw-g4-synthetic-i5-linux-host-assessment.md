# I5 路线 A：已有 Linux 资源、最低条件与准备预算

更新日期：2026-10-18。

本文供所有者和环境评审者筛选已有资源、审阅完整准备账目，承接[宿主可行性与真实 FD loader 合同](sw-g4-synthetic-i5-host-loader-decision.md)。它是设计候选，不是设备选型、安装清单、操作授权或可行性 PASS。

## 已确认范围与结论

所有者已选择 **A：保留完整写入边界，优先评估已有 Linux 资源，暂不新增采购**，并补充确认“目前只有已记录的 Mac/UTM”。本次仅做设计；不实现、不启动 VM、不安装依赖、不提交或 push，全部真实入口继续 STOP。没有连接设备、查询 VM 实时状态或探测网络；证据来自仓库历史记录、当前代码和官方机制资料。

**现有资源没有满足 A 路线前置条件的宿主。** 已有 Debian guest 可以复用为历史配置和软件基线参考，但其 Mac/UTM 底层仍为 `blocked-host-system-writes`。不把 guest 的 Linux 内核、root 权限、空闲磁盘或无网卡状态推导成完整宿主可控。此结论是资源匹配失败，不是实测内存/磁盘超额，也不是证明所有 Linux 承载均不可行。

不新增采购的约束下，真实推进暂停在宿主资源门。未来只有资源事实变化，或所有者另行改变费用/证据边界，才重新评估；当前不重问已选定的 A/B/C，不启动采购、租用、借用联系或云资源开通。

## 最低条件：能力要求与容量筛选分开

优先评估已有、可独占的原生 Linux 主机，尽量在同一主机完成制作、控制、执行和证据保留，减少额外宿主。以下是候选准入要求；没有对应事实即记 unknown，不凭发行版名称判断通过。

| 项目 | 最低条件 / 候选筛选值 | 必须补的证据 |
| --- | --- | --- |
| 资源控制权 | 有精确目标和所有者授权，允许独占维护窗口、启动前配置、只读基线和失败恢复；无必须保留运行的用户工作负载 | 设备/磁盘归属、可改范围、已有数据保护与恢复路径；有 root 不等于得到使用授权 |
| 整条宿主链 | 原生 Linux 优先；若是 VM，hypervisor、物理宿主及管理/证据客户端也必须纳入同一完整边界 | 控制、下载、制作、复制、运行、回收、留存各生产者与全部可写对象；普通 VPS/容器不能凭租户 root 证明供应方底层 |
| 架构与系统 | `aarch64` 优先复用既有 ARM64 输入；`x86_64` 可进入设计评估，但必须重取对应架构来源/闭包和基线 | 固定 kernel/解释器/stdlib/共享库/工具来源及摘要；Debian 13、Linux 6.12 系列仅为已有参考，不是唯一可用版本或自动达标条件 |
| 内核能力 | Landlock ABI ≥ 5、`openat2` 所选解析约束、mount/PID/network namespace、seccomp、subreaper、cgroup v2 的 cpu/memory/pids、受限 ext4、只读 ISO/squashfs、`noswap` tmpfs | 特性及启用状态、委派/私有传播、独立回读和真实拒绝；ABI/版本查询只证明接口存在 |
| 系统新增写入 | 从本包首次写入至回收结束，root/var、启动日志、临时目录、固件状态、控制进程全部有明确归属；swap、hibernate、core/kdump/pstore 等禁止或纳入可证硬界 | 首次启动前生效；失败、掉线、强杀和关机路径也覆盖。不能先写入再启用限额 |
| 存储承载 | 每个完整设备与额外开销满足 `D + H ≤ C`，独立副本计峰值；优先固定块边界，文件系统/宿主元数据须包含在承载内或另有硬预留 | 精确对象、全设备大小、只读性、metadata/journal、inode、开放删除文件和并发写满拒绝；目录大小/稀疏文件逻辑长度/清理策略不足 |
| 身份、隔离与工具 | 可信 P/loader 在加载前受约束；N 持有唯一 FD owner；worker 为获审非特权身份；只读工具和输入可追溯 | 不继承当前 root guest-agent 为 worker，不复制真实身份/密钥；安装、来源验签、许可证与工具固定分别关门 |
| 生命周期 | 所选 Linux 控制面等价支持一次执行、ready 绑定、取消、总截止、真实 reap、部分清理与有界证据 | 不依赖 Mac/UTM 旧调用，不增加未经评审的远程服务或重试 execute；断连不能留下无人监督任务 |
| CPU / RAM 筛选 | 暂以 **2 个可用 CPU 执行单元、4 GiB 级 RAM** 筛选已有设备；是容量规划假设，不是实测性能最低值 | 按实际 MemTotal、OS/缓存/受监督进程峰值复算；6 秒加载与原 540/900 秒时限仍必须通过，不能用核数保证时延 |
| 存储余量筛选 | 既有只读基线之外，保守预留准备 3608 MiB、后续 I5 768 MiB、域外安全余量 1024 MiB，共 **5400 MiB** | 这是两阶段可能并存时的保守规划；不是总盘容量，也不是 quota 证明。既有基线实际占用另加，尚未取得 |

上表的 CPU/RAM/余量是本设计的筛选提案，未修改任何消费者参数。2 CPU 对应现有准备 parent 的 `cpu.max=200000 100000`，并为父监督留下调度需求；CPU 配额并不保证得到这些时间。4 GiB 级来自下文保守 RAM 规划，不能据此宣布历史 4 GiB guest 满足要求。正式 I5 的构建和 daemon 峰值仍须独立评估，准备期尺寸不构成全流程最低配置认证。

机制依据与限制：

- [Linux tmpfs](https://docs.kernel.org/filesystems/tmpfs.html)分别提供 bytes/inode 限制，默认可换出；不能用 ramfs 或默认 tmpfs 代替有界、noswap 承载。
- [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)的 memory/pids/cpu 控制需有完整祖先约束；`memory.max` 某些情况下可短暂超出，不能作为整机绝不超用 RAM 或存储计费的证明。
- [Landlock](https://docs.kernel.org/userspace-api/landlock.html)的可用 ABI 和启用状态须实际查询；现有[构建 helper](../../scripts/sw_i5_build.py)要求 ABI ≥ 5。[openat2](https://man7.org/linux/man-pages/man2/openat2.2.html)的精确解析约束仍按 loader 合同验收。
- [OverlayFS](https://docs.kernel.org/filesystems/overlayfs.html)存在 copy-up；只读 lower 加 upper 不能只计算修改字节，复制整个文件及元数据都占 upper。不得让 overlay 覆盖独立 library/APT 挂载并破坏其身份合同。
- [journald](https://www.freedesktop.org/software/systemd/man/latest/journald.conf.html)轮转/保留设置不是整机容量硬界；仍需底层受限承载。[systemd-coredump](https://www.freedesktop.org/software/systemd/man/latest/coredump.conf.html)仅设置 `Storage=none` 仍可能临时写 core；禁止 core 时须覆盖实际处理链及残余日志，不能把“没有留下文件”当作没有写入。

## 完整准备预算候选：3608 MiB

### 适用范围和可信度

本节给出**完整列项的容量上限提案**，不是实测消耗、已批准预算或“必能装下”的估算。现有四项上限沿用代码；新增 environment 子预留是工程设计值，必须逐项以文件/闭包大小和物理机制验证，不以大额度掩盖 unknown。

适用假设是：有一台**已经安装 Linux、可在不重装或整盘复制的情况下形成受控只读基线**的专用主机；原始基线已存在且可核验。本提案覆盖在它上面准备可信加载组件、输入介质、单次验签/APT 求解、未来另行批准的工具差量安装及失败恢复的新增容量，包含并存副本，不逐阶段重发额度。安装只是预算占位，不属于现有 preparation-apt 的任务权限，也不授权实施。

若必须新装 OS、生成/转换完整系统镜像、复制现有 VM、创建额外宿主或保留整盘备份，本提案**不适用，完整总额尚不能冻结**；必须把这些完整设备、原件/目标件和建立边界的环境纳入新版预算后再评审。不能把这些必需步骤称作“免费预装”放在计费起点之前。当前 Mac/UTM 迁移尚无符合此假设的目标，3608 MiB 因而不是其迁移报价或容量承诺。

### 域与子预留

单位均为 MiB（`2^20` bytes）。表中子预留不新增平行 cap 配置，最终仍归入现有 preparation 的五域账本；本轮没有生成可执行 JSON。

| 所属域 / 子项 | 提案上限 | 覆盖内容、依据与必须验证的条件 |
| --- | ---: | --- |
| input | 256 | 继承已有上限；APT 与六文件 library 的独立只读介质完整大小合计，含文件系统开销。不能各拿 256 |
| work | 128 | 继承已有独立 noswap tmpfs；解压索引、APT 求解和有界工作文件，不拿来安装系统 |
| result | 8 | 继承已有独立 noswap tmpfs；原始结果与写入峰值按原上限接受 |
| host-retention | 32 | 继承已有上限；导出源、临时替换、最终证据并存共用。多个阶段的留存累计计入，不每阶段再给 32 |
| environment：介质制作 | 512 | 两份各至多 256 的原始下载/输入树与制作输出；包括 APT 与 library。压缩展开、by-hash 副本和制作工具临时对象必须一起装入，不能只算下载包 |
| environment：独立暂存/传递副本 | 256 | 最多一份完整额外介质；若与 input 同一物理对象，后续可核减，当前保守预留，不把同一对象登记两次 |
| environment：系统/工具差量写层 | 1024 | Go 解包、选定 deb 新增闭包、dpkg 状态、copy-up 和维护脚本写入；完整承载含元数据。现有四 deb Installed-Size 约 290.897 MiB 仅是部分下界，1 GiB 只是待证上限 |
| environment：恢复副本 | 1024 | 对上述获准修改集合的一份受限恢复副本/新旧版本共存；不是任意整盘快照。若固定只读 lower 可恢复，可评审核减；原备份对象大于此值即拒绝 |
| environment：系统 tmpfs | 128 | 包括初始化 root 的 1 MiB / 1024 inode，以及其余 `/run`、临时/共享内存文件；work/result 已单列，不在此重复。必须按挂载细分 bytes/inode |
| environment：系统/启动/失败日志 | 64 | boot、journal、audit、安装诊断、控制失联及关机日志；不得掉到默认域外位置；日志服务与存储都须约束 |
| environment：控制与源码组装 | 64 | 固定源码快照、组装中间件、控制程序、IPC/有界临时文件，覆盖失败时并存；最终证据仍只记 host-retention |
| environment：额外承载元数据 | 64 | 只覆盖尚未包含在各完整设备中的外层元数据、目录/分配记录；不能用这个猜测值将未知 backing 标为 bounded。若实际方案没有可单独限制的外层，仍 STOP |
| environment：固件/启动状态 | 16 | 可写 EFI/启动状态及其恢复副本的共同预留；实际固件变量/外部日志有无法绑定的写入时失败，不因数值小而忽略 |
| environment：可信基座增量交付 | 32 | 固定 P/loader/授权描述符及部署临时副本；解释器/stdlib 已有部分归只读基线，新增工具归 1024 写层，不能重复扣账或遗漏新依赖 |
| environment：swap/hibernate/core/kdump | 0（条件值） | 仅在全链禁用和独立核验通过后成立，残余日志计上方 64；当前状态为 unknown，不是已证明零写入。若要保留这些机制，必须重新预算 |
| **environment 小计** | **3184** | `512 + 256 + 1024 + 1024 + 128 + 64 + 64 + 64 + 16 + 32` |
| **完整准备包络** | **3608** | `256 + 128 + 8 + 32 + 3184 = 3,783,262,208 bytes`，约 3.523 GiB |

额度不是允许填满 payload 的容量：每域仍须 `D + Σ H ≤ C`，各组件峰值不超过其物理预留；嵌套对象计入其承载，独立副本另计。表中制作、暂存和 input 在最保守情况下容纳四份不同表示，不能声称“只读介质不计制作成本”。默认所有预留可并存，不以清理必定成功换取峰值缩减；回收确认前不重用失败对象的额度。

所有正数也须证明机制。固定块域的文件系统元数据已在完整 D 内，不再扣一次额外 metadata；若通过宿主文件承载，底层文件系统的额外增长仍归 H。预算给 64 MiB 不能使全局 metadata 自动有界，给 16 MiB 也不能替代固件路径盘点。禁用项未核验、任意新写入面未归属、组件实际需求超过预留、旧证据占用未纳入时均拒绝，不能借用相邻行或静默扩容。

**冻结前待补**：目标主机全部基线；固定来源验签；原生 APT 结果和归档完整闭包；Go 展开长度；维护脚本实际写入清单；受影响旧文件的恢复大小；copy-up、文件系统布局与完整 inode 规划；各 producer 的峰值；全部硬边界及失败收尾。现有归档部分下界为 Go 加四 deb 共 134,863,381 bytes，来源见[安装体积与缺失输入](sw-g4-synthetic-i5-environment-feasibility.md#安装体积与缺失输入)。它不能证明 256 MiB input 或 1 GiB 安装层已经够用。

### RAM、进程、时间与后续 I5

磁盘/tmpfs 容量、进程 RAM 和可用物理 RAM 是三本不同账。为筛选已有主机，暂按下面的保守 RAM 预留合计 4096 MiB；其中页缓存或 tmpfs 可能已被 cgroup 计入，这里允许保守重叠预留，但不得在实际计费中把重叠当作额外可用额度。

| RAM 用途 | MiB | 状态 |
| --- | ---: | --- |
| 既有任务 parent（含 S/W） | 512 | 现有上限；S=64、W=384，不能另把 512-64-384 交给 loader |
| 加载前 P/N | 256 | 新提案：P 64、N 192；必须在 import/解析前建立，不改变现有代码 |
| Linux 控制/回收进程 | 128 | 新提案，独立于 N 和任务组，必须在任务耗尽时仍可收尾 |
| OS/kernel/必要服务 | 1024 | 待测规划预留；不是内核硬限制，也不是普通进程 cgroup 能完整约束的对象 |
| 其余系统 tmpfs | 128 | 对应存储表；不能允许换出 |
| IO/page cache 等规划余量 | 1024 | 待实测；不能据此允许域外临时文件 |
| 监督存活与未精确归属开销的安全余量 | 1024 | 规划余量，不能转为更多 worker 配额 |
| **合计** | **4096** | 名义 4 GiB 不保证 MemTotal/可用值足够；未覆盖正式 I5 构建/daemon 的实测峰值 |

加载前新提案另以 P/N 合计 16 个 PID、每进程 128 个 FD、core=0 评审；控制组另预留 16 个 PID、每进程 128 FD。既有任务 parent 的 48 PID、S 的 8、W 的 32 保持原值。它们是待审上限，不是已配置事实，需以实际 fork/FD 拓扑和耗尽故障验证；全机 PID、内核开销和 OS 服务仍需盘点，不能只相加三组就称为整机闭合。

准备任务执行时沿用保守 897 秒/绝对 900 秒，guest-equivalent 540 秒及加载与 init 共用 6 秒；迁出 UTM 不自动把空出的启动预算重新发放。介质制作、基座部署和差量安装是不同操作，不能塞入现有一次 preparation-apt 调用；具体命令/次数/持续时间要等目标确定后分别设计，现在没有可批准的运行操作单。

正式 I5 仍为 768 MiB，3608 不能给 I5 补额度。准备期保留下来的工具必须固定为只读基线，不能提前构建本批 bootstrap/node/image。准备期的系统 tmpfs/日志预留也不能直接沿用到 I5 域外；必须重新在其 768 MiB 中归属并验收。若保留全部准备占用且再进行 I5，保守资源规划为 `3608 + 768 = 4376 MiB`，再加原有域外余量门 1024 为 5400 MiB；这不是把正式实验总额改为 4376 或 5400。
